## 创作能力的共同骨架

绘画、音乐、演绎、自由创作看起来是四种能力，内部都遵循同一条骨架：

1. **需求进入**：一句话、一个故事、一组参考图，或一个已批准的计划。
2. **规划**：确定产物类型、风格、步骤和需要的资料；复杂任务先出计划，简单任务直接执行。
3. **取材**：从资源库、记忆、参考图或现场检索里取素材；取不到时明确降级，而不是编造。
4. **执行**：交给对应技法智能体或执行者；长任务按阶段推进，过程可观察。
5. **验收**：检查产物是否完整、是否满足约束；演绎和自由创作还会有人工确认点。
6. **归档**：产物登记为句柄，写入对应资源目录，需要时进入记忆或对话。

差别主要在「谁执行」和「有没有人工确认点」，而不是四套互不相干的流程。

## 绘画

### 触发

- 对话中调用创作任务的绘画分支（`creative_work`，`type=painter`）。
- 生活里的创作事件发起绘画任务。
- 演绎链在分镜阶段批量生图。

### 参与者

- **人格对话**：判断要不要画、抽取主题与风格，把需求整理成绘画入参。
- **图像绘制**：真正调用图像生成引擎的智能体，负责组装提示词、参考图与参数。
- **资源体系**：把参考图与成图登记为句柄。

### 数据怎么流动

1. 需求先变成一段可执行的画面描述，而不是原样丢给模型。
2. 参考图最多三张，按顺序传给生成引擎；可选是否把参考图也作为画面内容。
3. 选择比例：16:9、4:3、1:1、9:16、3:4。
4. 选择风格开关：开启后追加固定的风格提示词；关闭则只用你的描述。
5. 生成引擎出图，结果登记为 `@I` 句柄。
6. 需要时追加 4 倍超分，超分结果作为新的图片句柄，不覆盖原图。

### 失败与降级

- 生成引擎不可用：明确告知失败原因，不返回空白图或旧图。
- 参考图无法读取：跳过该参考图并说明，而不是让整次绘制失败。
- 超分失败：保留原图，提示超分未完成。
- 内容被安全策略拦截：返回拦截原因，不重试绕过。

## 音乐

音乐不是「生成一段音频」，而是让模型按乐理逐 token 写出一段可演奏的 MIDI：

1. **定结构**：先确定曲式、调性、拍速、段落与情绪。
2. **写事件**：按时间顺序生成音符、时值、力度与乐器事件。
3. **合成**：把事件交给本地音源渲染成音频。
4. **归档**：音频登记为 `@A`，同时保留可再次演奏的结构信息。

这样做的结果是：同一首曲子可以改段落、换音色、重新演奏，而不是只能得到一段不可编辑的波形。音乐能力由「音乐演奏」智能体承担，对话中通过创作任务的音乐分支（`creative_work`，`type=musician`）触发；生活里的创作事件也可能产出音乐。

失败时优先保留已生成的结构，音频渲染失败只影响试听，不会让整首曲子丢失。

## 演绎：从故事到分镜

「演绎」面向的是「把一段故事变成一组可看的画面与分镜文档」，不是直接生成视频。对话里提出「把这段故事演绎成分镜」时，人格对话调用 `creative_work` 的 `storyboard` 分支登记生活事件，由生活链直接提交演绎任务（故事正文写在指令里，或把故事文件句柄放进 `handle`）；任务进入分镜队列，完成后在资源库等待确认。它是一条有六个阶段的链：

| 阶段 | 在做什么 | 谁参与 | 是否停顿 |
|------|----------|--------|----------|
| 资料研究 | 查角色、场景、时代背景与视觉参考 | 分镜规划-资料 | 否 |
| 分镜拆解 | 把故事拆成镜头，写画面描述与台词 | 分镜规划-拆解 | 否 |
| 人工审阅 | 你修改镜头、增删场次、调整描述 | 你 + 前端 | **仅手动提交时** |
| 批量绘制 | 按最终分镜逐镜生图 | 图像绘制 | 否 |
| 文档撰写 | 把分镜、画面、说明整理成文档 | 分镜规划-修订已移除 | 否 |
| 完成 | 文档与图片归档，可继续编辑 | 资源体系 | 否 |

### 什么时候会停

只有**用户在资源库手动提交**的演绎会在分镜拆解后暂停，等待你确认。生活系统自动触发的演绎，以及月华通过 `creative_work` 的 `storyboard` 分支下达的演绎，都跳过人工审查，规划完成即开始分镜合成。

审阅阶段支持：

- 修改单个镜头的画面描述、台词、时长与备注。
- 增删镜头或调整顺序。
- 暂停与取消；取消会保留已完成的过程记录，但不再继续后续阶段。
- 确认后直接进入逐镜绘制，不再有「分镜规划-修订」环节。

### 产物

- 图片在绘制阶段直接写入 `multimedia/generated/<项目标题>/`，配音写入 `audios/generated/<项目标题>/`，两者同标题名配套。
- 最终产物是模板拼接的幻灯片 `documents/lens/<项目标题>.html`，用相对路径指向图片与配音；每张画面的展示时长等于该镜配音的播放时长。
- 全部分镜合成完成后，演绎链把标题与句柄写入月华「刚刚在做什么」运行时消息。

## 自由创作：创作 / 编辑 / 演绎三域

自由创作处理的是「没有现成表单」的任务：写一篇东西、做一个小工具、整理一份资料、完成一个多步骤的整活计划。文件族按产物拆成三个**并行、互不调用**的领域：

| 领域 | 承担智能体 / 链 | 负责 |
|------|----------------|------|
| 创作 | 故事创作（`story_writer`） | 故事目录、大纲、章节、进度与设定升级 |
| 编辑 | 文件编辑（`file_operations`） | 文件读写、整理、压缩包、脚本执行、内容回滚 |
| 演绎 | `chain/storyboard` + 图像绘制 | 把故事文本变成分镜与画面 |

跨领域编排只发生在人格对话与生活链这一层：它们按需求直接调用对应领域，域与域之间不互相调用。

### 任务入口

- **人格对话**：统一调用 `creative_work`，用 `type` 分支选择领域——`story` 写 / 续写故事，`files` 做普通文件任务，`storyboard` 提交演绎；前两者同步返回结果，演绎登记生活事件后异步执行。三个分支共用同一套输入输出协议，减少对话侧的心智负担。
- **生活链**：创作事件按主题分流——故事 / 小说主题直接调用故事创作，其余调用文件编辑；心情正向且已有作品时延续同一项目目录与句柄，否则只下发一个主题；调用后把结果写入「刚刚在做什么」运行时消息。
- **资源库创作页**：提交时选择领域（`story` / `edit`），分别进入故事创作或文件编辑；不传领域时按描述关键词推断。演绎仍使用独立的 `storyboard.submit` 入口。

### 项目命名

新作品不预设路径：生活链只给一个主题，智能体先为作品起具体标题，再在 `documents/<标题>/` 下创建文件。返回值会带回实际项目目录，供下次延续与演绎使用。故事创作额外维护 `大纲.md` 与 `进度.md`，章节按 `001-标题.md` 顺序编号。

### 执行

文件编辑智能体先读取必要片段，再把任务拆成有序操作，派发给四个原子智能体：

| 子智能体 | 负责 |
|----------|------|
| 文件操纵（`manipulate_files`） | 按行替换、追加、删除、创建空白文件、删除文件 |
| 归档操纵（`manipulate_archive`） | 创建、删除、列出、提取、追加归档条目 |
| 代码执行（`code_execution`） | 运行 HTML/JavaScript、解析函数与依赖 |
| 内容回滚（`content_rollback`） | 列出历史版本、回滚到指定版本 |

故事创作则通过 `create_story` 与 `write_chapter` 两个专用工具落盘：路径由 Go 侧拼接，章节写完自动追加进度，不允许用普通文件工具手写章节或进度。

### 版本与回滚

每次写文件前，版本库会把原内容存进 `local_data/database/versions.db`：一条记录包含路径、触发操作（替换 / 追加 / 删除行 / 创建 / 删除 / 归档操作）、时间、大小、SHA256 与完整内容。记录和内容在同一个事务里写入，不会出现「有副本没记录」的半截状态。

- 保留策略：单文件最近 50 版、全库 2 万条、最长 90 天，超出自动裁剪。
- 回滚：列出历史版本后按版本 ID 恢复整份内容；若该版本记录的是「文件原本不存在」，回滚会删除文件。
- 旧版按目录保存的 `local_data/file_versions` 会在首次打开版本库时自动导入，原目录改名为 `file_versions.migrated`，确认无误后可手动删除。

文件编辑单次最多 6 个步骤，工具循环上限 32 轮；任一步失败不会立刻销毁文件，而是带上失败原因与已改文件先让智能体自行修复，最多重试 3 次，仍未成功才回滚本次已修改的文件。需要新建项目目录时直接创建文件即可，父目录会自动生成。文件修改按物理行处理，工具会把「第 15 行」当行号，不会把「第 15 镜」误当行号。

### 验收

两个同步领域都按实际执行结果返回，不再经过额外的审查智能体拦截：所有步骤都成功即视为完成；失败时先修复重试，重试次数用尽后才会回滚并返回错误。故事创作还会校验本章是否真的落盘，只有进度没有章节会被判为失败。

作品完成后会回报给心愿系统：与待处理愿望匹配上的自动完成，并轻推心情。规则见 [心愿清单](./03-生活与情绪.md#心愿清单)。需要插画的故事只负责写出故事与目录，图像交给演绎系统处理。

## 作品去哪里

| 产物 | 归档位置 | 句柄类型 |
|------|----------|----------|
| 绘画、截图、超分图 | `multimedia/generated/`（演绎按项目标题分目录） | `@I` |
| 音乐、语音 | `audios/`（演绎配音在 `audios/generated/<项目标题>/`） | `@A` |
| 演绎幻灯片 | `documents/lens/<项目标题>.html` | `@D` |
| 自由创作文档、代码、资料 | `documents/<项目标题>/` | `@D` |

归档后的作品和普通资料没有区别：可以被对话引用、被资源中枢检索、被下一次创作当素材，也可以被删除或回收。作品不会因为「是 AI 做的」而被特殊对待。

## 中断、失败与重试

| 情况 | 表现 | 处理 |
|------|------|------|
| 用户取消 | 任务停在当前阶段 | 保留已完成产物与过程记录，后续可重新发起 |
| 服务重启 | 任务停在当前阶段 | 从保存的现场继续：资料/规划重新发起当前阶段，绘制从未完成镜头接上；取消或现场缺失的任务标记中断 |
| 单个镜头绘制失败 | 分镜文档缺一张图 | 标记该镜头失败，可单独重试，不阻塞其他镜头 |
| 资料研究失败 | 分镜缺少背景依据 | 降级为基于现有描述的拆解，并标注资料不足 |
| 计划步骤失败 | 自由创作卡住 | 重试、换执行者或报告未完成部分，不伪造产物 |
| 验收不通过 | 产物存在但不合格 | 补做或明确报告缺口，不把半成品归档为完成 |

创作系统的原则是：**过程可观察、产物可追溯、失败可续跑**。长任务允许停，但不允许悄悄丢。
