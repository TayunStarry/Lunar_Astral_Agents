## 三块界面

系统没有把所有功能塞进一个页面，而是按「交互场景」拆成三块主界面，再加一个移动端：

| 界面 | 场景 | 核心职责 |
|------|------|----------|
| 月华消息终端 | 日常聊天 | 实时对话、语音、截图、画板、文件、引用 |
| 琉璃桌面 | 找工具、管资料 | 扩展包网格、记忆库、文件与资源入口、设置 |
| 资源库 | 干活与查阅 | 文件树、预览、创作、演绎、数据库、归档 |
| 移动端 | 手机上使用 | 轻量对话、语音、文件与历史查看 |

拆分的依据是**注意力**：聊天时你不希望被文件树打断；整理资料时你也不希望每条命令都变成一轮对话。界面负责把对应能力放到手边，底层仍是同一套服务与同一条资源体系。

## 月华消息终端

### 它解决什么

这是最主要的对话入口，目标是把「说话」这件事做得尽量自然：能打字、能发图、能按住说话、能截屏、能画一张草图再问，也能把文件拖进来。

### 主要区域

- **消息流**：正文、图片、文件、语音、引用块、工具进度与推理实况。
- **输入区**：文字输入、附件、语音录制、截图、画板、发送。
- **会话区**：历史会话切换、未读提示、正在输入状态。
- **设置**：模型、语音、外观、人格追加设定、连接方式。

### 一次发送发生了什么

1. 输入区收集文字与附件；图片、语音、文件先在前端做轻量检查。
2. 消息通过实时连接提交；附件先上传并换取资源句柄。
3. 服务端把消息放进队列，前端进入「正在处理」状态。
4. 正文按段流式返回，工具进度与推理实况走另一条展示线。
5. 需要语音时，前端收到音频后排队播放，不打断正在播放的上一条。
6. 消息落定后，前端更新历史、滚动位置与未读状态。

### 输入能力

| 能力 | 行为 |
|------|------|
| 截图 | 选择窗口、全屏、显示器或区域，截完直接作为图片消息 |
| 画板 | 手绘草图，可带说明一起发送 |
| 语音 | 录音后上传，服务端转写；也支持边录边转的短语音 |
| 文件 | 拖入或选择，支持多文件；大文件先提示再上传 |
| 引用 | 引用某条消息回复，引用块随消息进入上下文 |
| 粘贴 | 图片直接粘贴为待发送图片，文本按普通文本处理 |

## 琉璃桌面

### 它解决什么

琉璃桌面是「工具与承载」的可见形态：把扩展包、记忆库、文件、资源入口和设置集中到一个网格里，让你不必记命令，也不必在聊天里反复描述路径。

### 页面结构

- **卡片网格**：每个扩展包或内建工具是一张卡片，按标签分组，位置与空行可持久化。
- **搜索**：按名称、说明与标签过滤卡片。
- **覆盖层**：点击卡片后在当前页面上方打开 iframe，不整页跳转，关闭后回到网格。
- **卡片菜单**：导出、归档、删除、启用/停用页面助理、打开设置。
- **对话浮层**：不离开桌面也能发起一轮对话，支持文字、图片、文件与语音。

### 它和月华的关系

琉璃桌面不是第二个人格，也不单独调用模型。它做三件事：

1. 承载扩展包页面，让包里的工具能被月华调用。
2. 提供记忆库、文件与资源的管理入口。
3. 在页面里注入共享输入与页面助理，让扩展包具备基本的自然语言操作能力。

## 资源库

### 它解决什么

资源库是「干活」的地方：浏览文件、看预览、发起创作、做演绎、查数据库、处理归档。它比琉璃桌面更偏内容生产，比消息终端更偏结构化操作。

### 主要页面

| 页面 | 用途 |
|------|------|
| 文件 | 目录树、文件详情、预览、上传、下载、移动、重命名、按哈希整理 |
| 创作 | 发起自由创作任务，查看计划、步骤、过程记录与产物 |
| 演绎 | 提交故事、查看分镜、逐镜修改、确认后批量生图、查看最终文档 |
| 数据库 | 查看表结构与行数据，用自然语言生成只读查询 |
| 归档 | 查看压缩包结构、条目、GGUF 元数据 |
| 沙箱 | 在隔离 iframe 中运行页面脚本，展示运行结果 |

### 创作与演绎的界面职责

- **创作页**只负责提交任务与展示过程，真正的规划、分派、验收在服务端链里完成。
- **演绎页**在「人工审阅」阶段停下来，把镜头列表交给前端编辑；你点继续后，链才进入修订与批量绘制。
- 页面不直接调用模型，所有模型工作都通过服务端链与智能体完成。

## 移动端

移动端不是桌面端的缩小版，而是按手机场景裁剪：

- **对话**：轻量消息流，支持文字、语音、图片与引用。
- **语音**：录制、转写、播放；优先保证弱网下也能发出去。
- **文件**：查看最近文件、上传、下载、预览。
- **历史**：按会话查看最近对话，不加载完整资源库。
- **设置**：只保留常用项，模型与连接等重配置留在桌面端。

它的存在意义是「随时说一句」，而不是「在手机上完成创作与资料整理」。

## 前后端怎么通信

| 通道 | 用在哪里 | 特点 |
|------|----------|------|
| 实时连接 | 消息流、工具进度、推理实况、扩展包调用广播 | 双向、可推送、断线需重连 |
| 普通请求 | 历史查询、文件操作、资源库管理、设置读写 | 一问一答，失败可直接提示 |
| 文件上传 | 图片、文档、音视频、附件 | 先上传换句柄，再进入消息 |
| 静态资源 | 前端页面、共享依赖、扩展包资源 | 由服务端直接提供，带缓存 |

实时连接断开时，前端按固定间隔重连，最多尝试若干次；重连期间已发送的消息不会重复提交，未发送的输入保留在本地。普通请求失败时直接显示错误，不假装成功。

扩展包调用走的是实时连接上的广播：服务端把调用推给包页面，页面执行后回执；这条通道和聊天消息共用连接，但消息类型独立，不会混进对话流。

## 渲染与输入能力

### 渲染

- Markdown 正文、代码高亮、表格、引用块。
- 数学公式与流程图按需渲染。
- 图片、音频、视频、文件卡片按类型展示。
- 工具进度与推理实况分区显示，不挤占正文。
- 长消息折叠、代码块横向滚动、图片点击放大。

### 输入

- 文字、粘贴、拖拽、文件选择。
- 区域截图、窗口截图、全屏截图。
- 手绘画板。
- 语音录制与转写。
- 引用回复与多选转发。

## 失败与降级

| 失败 | 表现 | 处理 |
|------|------|------|
| 实时连接断开 | 消息不再实时出现 | 自动重连；期间保留本地输入，恢复后继续 |
| 附件上传失败 | 消息发不出去或缺少附件 | 明确提示哪个附件失败，允许重试 |
| 语音合成失败 | 没有声音 | 只显示文字，不阻塞消息 |
| 图片/视频加载失败 | 卡片空白 | 显示句柄与失败原因，可重新获取 |
| 扩展包页面加载失败 | 覆盖层空白 | 关闭覆盖层并提示；不影响其他卡片 |
| 页面脚本报错 | 沙箱内报错 | 在沙箱面板显示错误，不污染主页面 |
| 服务端未启动 | 页面打不开或接口全失败 | 前端提示连接失败，指引启动主程序 |
| 资源库文件过大 | 预览卡顿 | 只加载摘要或分页，不强行整文件渲染 |

前端的原则是：**保底可用、失败可见、输入不丢**。任何一个界面挂掉，都不应该让已经输入的内容消失。
