## 对话从哪里进来

消息有三类入口：

1. **月华消息终端**：最主要的入口，支持文字、图片、文件、语音和视频片段，走实时连接。
2. **兼容接口**：外部程序按标准对话接口提交请求，系统把它当作一次普通对话处理。
3. **通讯桥接**：QQ 群或好友的消息经桥接转进来，回复再按原会话送回去；只有桥接就绪时，`qq_send` 工具才会出现在月华的工具目录里。

消息进入后先进入**统一时序队列**，而不是直接调用模型。队列负责三件事：按到达顺序排队、把多媒体内容先做识别与转换、把资源统一变成句柄。这样模型看到的永远是一致的文本与句柄，不会因为某条消息带了图片就破坏上下文结构。

## 快速应答与主应答

一次应答周期里有两种「说话」：

### 快速应答：长任务开始前的旁白

当模型决定调用三个复合工具之一——创作任务、联网探索、扩展应用——系统会在工具真正执行前，先推一句简短的话，并尽可能合成语音。它的作用是告诉你「我听到了，正在去做」，避免几十秒没有任何反馈。创作任务融合了故事、文件编辑、演绎、绘画、音乐与截图，无论走哪个分支都会先给出同一套口吻的快速应答。

快速应答有三个特点：

- 台词从候选池拼装，带随机省略，不是模型逐字生成。
- 同一轮内多次调用复合工具只推一次。
- 它被标记为「旁白」，不会消费 QQ 桥接的正式应答份额；群聊里的 @ 回执与引用仍然留给最终回复。

### 主应答：模型真实说出的话

主应答是模型在工具循环中产出的正文和最终回复。模型可以「边说边调工具」：这一轮已经说出的正文会按正常消息推送并合成语音；工具结果回到上下文后，模型继续下一轮，直到不再调用工具或达到轮次上限。

工具轮次上限是 5 轮，之后还有 1 轮不带工具的收尾机会。收尾轮用于让模型解释「为什么没做完」或给出已完成的部分，而不是把失败静默丢掉。

## 人格是怎么拼出来的

月华的人格不是一句「请扮演」临时生成的，而是由五层内容共同构成：

| 层 | 内容 | 什么时候进入 |
|----|------|--------------|
| 固定角色提示词 | 身份、性格、说话方式、行为边界、双方外观 | 每次请求的系统提示词 |
| 追加设定 | 你在配置里补充的偏好与风格，每项一行追加到提示词末尾 | 每次应答周期重建提示词时 |
| 当前状态 | 当前时间、心情、刚做过的事、愿望清单、对话者的情感标识 | 每轮一条运行时消息 |
| 最近对话 | 最近 48 条消息，每轮按此窗口重建上下文（只保留文本与资源句柄） | 每轮重建上下文 |
| 长期记忆 | 与当前话题相关的记忆片段 | 需要时由资源工具检索，不整库注入 |

### 心情与好感怎么进来

心情和好感不写在角色提示词里，而是每轮以「当前状态」的形式放进上下文：

- **心情**有 11 种标签。每次更新取最近 5 轮对话作为样本，与 11 个情绪锚点算相似度，再与当前心情按 0.35 / 0.65 混合，因此几轮情绪明显的对话就能把心情推向对应标签，但原来的心情仍保留三分之一左右的权重。它影响语气、创作方向与论坛发言时的状态；愿望的临近、完成、延期、逾期也会施加小幅偏移。
- **好感**按对话者分别维护，是一套 `[-50, 50]` 的态度积分，默认 20 分；正向是喜欢、信任、关心，负向是讨厌、反感、冷淡，按最近对话的感受程度加分或扣分，标签依次为很喜欢 / 喜欢 / 平淡 / 疏离 / 讨厌。
- **愿望清单**只列尚未了结的愿望与截止时间，让月华能直接回答「我有什么愿望」，而不必再查一次。
- 只有某个对话者已经形成情感认知时，本轮运行时消息才会带上对应的情感标识。

心情、好感与愿望如何被生活回合更新，见 [生活与情绪](./03-生活与情绪.md#固定四步愿望心情好感记忆)。

### 外观与声音

外观决定提示词里如何描述月华与琉璃，也决定前端用哪种角色渲染；声音决定回复是否合成语音、用哪个引擎和音色。两者都是人格表达的一部分，但不改变行为边界。

### 基础人设只有一份

月华的名字、性格、家人与厌恶只写在 `prompts/dialogueRole.md` 的「我是谁」段落。生活、创作、演绎等链的提示词通过 `{base-persona}` 占位符引用它，由 `prompts.Read` 统一注入；外观统一取自 `painterCharacters.md`，对话与绘画共用同一份外观描述。各链只保留自己的表达方式与工作规则，不再复制基础人设，避免出现第二套会过期的描述。

## 多模态输入怎么被理解

不同输入由不同角色处理，处理结果统一回到对话上下文：

| 输入 | 谁处理 | 结果 |
|------|--------|------|
| 图片 | 视觉理解 | 图片内容描述，并与图片句柄关联 |
| 文档 | 文献解析 | 正文、章节或结构化摘要 |
| 语音 | 语音转写 | 文本，再按普通消息进入队列 |
| 视频 | 媒体处理与关键帧 | 关键画面、时间信息与视频句柄 |
| 动图 | 图片链路 | 按图片处理，保留动图资源 |

多模态处理失败时，消息不会整条丢失：能保留的文字和句柄仍然进入上下文，模型会看到「这项内容无法解析」而不是收到一条空消息。

## 工具调用：月华如何把事交出去

月华的工具目录按「复合工具 + 子分支」组织，模型只需要选择大类，再用自然语言写清子任务：

| 复合工具 | 子分支 | 交给谁 |
|----------|--------|--------|
| 创作任务 `creative_work` | `story` 新建故事 / 续写下一章、`files` 文件读写与整理、`storyboard` 把故事变成分镜画面、`painter` 绘画、`musician` 音乐、`screenshoter` 屏幕截图 | 故事创作智能体、文件编辑智能体、演绎链（登记生活事件后异步执行）、绘制者、演奏者、截图者 |
| 联网探索 | 网页检索、B 站观影、互助论坛、QQ 发送 | 搜索链、观影链、论坛链、通讯桥接 |
| 资源中枢 | 按句柄、类型、关键词或记忆语义查询 | 资源与记忆的统一检索入口 |
| 心愿管理 | 愿望管理、最近活动、记录创作意图 | 愿望管理智能体与生活链 |
| 扩展应用 | 已安装扩展包声明的工具 | 扩展包自己的页面与执行逻辑 |

几个边界值得注意：

- **桌面操作不在这个目录里。** 它直接控制真实键鼠，只能由控制台人工启动，月华无法通过工具调用它。
- **工具声明是动态的。** QQ 未就绪时不会出现 `qq_send`；扩展包清单在查询时重新计算，不会把安装状态固化在启动时。
- **工具失败会回到模型。** 执行错误作为工具结果回填，模型可以换一种方式重试、解释原因，或改用别的工具；不会由链直接吞掉。

各能力的内部流程分别见 [05 资源与文件](./05-资源与文件.md#资源中枢让-ai-自己查)、[06 创作与演绎](./06-创作与演绎.md#创作能力的共同骨架)、[07 外部工具与扩展包](./07-外部工具与扩展包.md#联网检索)。

## 回复怎么回到你面前

回复不是等全部生成完才出现，而是边生成边推送：

1. 模型输出的正文按段落流式推送到前端。
2. 需要语音时，文本先做清洗，再交给语音引擎合成；合成失败就只发文字。
3. 消息带上发送者、时间与会话标识，推送到对应终端。
4. 消息被标记为已读，未读队列前进；如果还有排队消息，下一轮对话节拍继续处理。

推理过程本身也会出现在「推理实况」里：哪个智能体在调用模型、正在用什么工具、是否陷入重复输出，都可以在控制台看到。人格回复与推理实况是两条并行的展示线，互不替代。

## 失败与降级

| 失败 | 表现 | 系统怎么处理 |
|------|------|--------------|
| 模型超时 | 本轮迟迟没有输出 | 单次请求有超时；瞬时错误会重试，重试仍失败则上报并结束本轮 |
| 模型输出陷入重复 | 同一段内容反复生成 | 循环监管中断本轮，不再继续烧上下文 |
| 工具执行失败 | 某个能力没有结果 | 错误作为工具结果回填，模型决定解释、重试或换工具 |
| 工具轮次用尽 | 模型还想继续调用 | 停止执行工具，用一轮无工具请求收尾，并说明未完成部分 |
| 语音合成失败 | 没有声音 | 降级为纯文字，不影响正文送达 |
| 多模态解析失败 | 图片/文档/视频读不出来 | 保留文字与句柄，明确标注解析失败 |
| 内部异常 | 应答周期崩溃 | 捕获异常并记录失败原因，不让整个服务退出 |

失败不会被伪装成成功；但也不是所有失败都会打断对话——能降级的降级，能交给模型解释的交给模型解释，只有无法继续时才结束本轮。
