§1从文字到向量：分词与嵌入

1.1 为什么需要 Token

神经网络只能运算数字，因此文本必须先被切成离散单元并映射为整数编号。切分粒度有三种极端：按字符切（序列太长）、按词切（词表爆炸、无法处理新词）。现代 LLM 采用折中方案 BPE（Byte Pair Encoding，字节对编码）：从字节级基础词表出发，迭代地把语料中最高频的相邻符号对合并成新符号，最终得到一张大小可控的词表（minimind-3 为 6400）。

minimind-3 使用 字节级 BPE（GPT-2 风格）：任何 UTF-8 文本先编码为字节流，每个字节都对应词表中的一个基础符号，因此任何字符串都能被表示，不存在"未知词"。编码流程：

文本 → UTF-8 字节 → 字节↔可见字符双射映射
→ 预分词（正则切分：单词 / 数字 / 标点 / 空白四类片段）
→ 每个片段内按合并秩自底向上合并 → 查词表得 id 序列

例如「北京是中国的」被切分为 ['北京', '是中国', '的'] → id [5412, 5081, 296]。你可以在页面上方 MODULE04 的 Token 序列条里直接数出每个输入被切成了多少 token、每块对应的文本。

1.2 嵌入矩阵：把 id 变成几何

词表中的每个 id 对应嵌入矩阵 E ∈ RV×d 中的一行（V=词表大小 6400，d=模型维度 768）。推理的第一步就是查表：

xt = E[idt] ∈ R768　—— 每个 token 变成 768 维向量

这个向量是可学习的：训练中语义相近的词的嵌入向量会被拉到相近的方向。页面 ③ QKV 散点观测中选择「Embedding 输入」，把每个 token 的嵌入向量投影到任意两维（或 PCA 前两主成分）上，就能直观看到 token 在高维空间中的分布。

SPEC · minimind-3 实测参数 词表 V=6400 · 模型维度 d=768 · 嵌入矩阵 6400×768 ≈ 4.92M 参数 · 与输出投影层共享权重（tied embedding，见 §6.1）。

§2位置信息：从正弦编码到 RoPE

2.1 为什么注意力天生"失明"于顺序

§3 将看到，注意力本质是一次集合运算：把 47 个 token 交换顺序，注意力输出也跟着交换顺序，而每个 token 自己的输出内容不变 —— 即注意力对语序完全对称。但"北京吃烤鸭"与"烤鸭吃北京"显然不同，必须显式注入位置信息。

2.2 RoPE：把位置变成旋转

minimind-3（Qwen3 系）采用 RoPE（Rotary Position Embedding，旋转位置编码）。思想：不把位置加到向量上，而是把 Q/K 向量按位置旋转。对 head_dim=96 的向量切成 48 个二维平面，第 i 个平面以角速度

θi = base−2i/96,　base = 1,000,000　（低维平面转得快 ≈ 编码细粒度局部位置；高维转得慢 ≈ 编码长程位置）

旋转。位置为 m 的 token，其 Q/K 向量的第 i 个平面被旋转 m·θi 弧度：

RoPE(q, m)2i,2i+1 = [ cos(mθi)·q2i − sin(mθi)·q2i+1,　sin(mθi)·q2i + cos(mθi)·q2i+1 ]

关键性质：两个旋转后的向量做内积，只依赖位置差 m−n：

⟨RoPE(q,m), RoPE(k,n)⟩ = ⟨R(m)q, R(n)k⟩ = qT R(m)TR(n) k = qTR(n−m) k

也就是说注意力分数天然携带"这两个 token 隔多远"的信息，且形式仍是普通内积 —— 无需额外参数、可外推、相对位置感知。这是 RoPE 成为现代 LLM 标配的原因。

页面实证 · 很好看的现象 在「③ QKV 散点观测」中勾选 PCA 投影、向量类型选 Q（post-RoPE）：所有 token 的 Q 向量在主成分平面上排成一条平滑的对角轨迹 —— 这正是随位置递增的旋转角在低维投影下的样子。句首 token 在线的一端，最新 token 在另一端。改成 K 或 V 则看不到这种规律（V 不做 RoPE）。

2.3 逐头归一化（Qwen3 特有）

Qwen3 在 RoPE 之前，对每个头独立的 96 维 Q 向量做一次 RMSNorm（权重 q_norm、k_norm，各自独立，V 不做）：

q′h = RMSNorm96(qh) ⊙ γq　—— 稳定各头分数尺度，Qwen3 论文指出其有助于训练稳定性

§3自注意力：Q、K、V 与缩放点积注意力

3.1 直觉：一次"软查询"

要更新第 i 个 token 的表示，模型需要从整个上下文中检索相关信息。把每个 token 投影成三种角色：

  • Query（查询）qi：我在找什么？——"需求描述"
  • Key（键）kj：我能提供什么标签？——"索引卡片"
  • Value（值）vj：我实际携带的内容。——"仓库货物"

匹配度 = qi 与 kj 的内积；按匹配度把所有 vj 加权求和，就得到 token i 的新表示。三种角色由三个可学习矩阵从同一输入变换而来：

Q = h·WqT　(K = h·WkT　V = h·WvT)　h 为 RMSNorm 后的隐状态；minimind-3 无偏置项

3.2 缩放点积注意力：完整公式

Attention(Q,K,V) = softmax( QKT / √dhead ) V
对应本页演算台四个阶段：①取向量→点积 ②除以 √96 ③对整行 softmax ④按权重加权和 V

逐步拆解（页面 ④ 成对注意力演算台把每一步都变成可交互数字）：

① 点积　scoreijraw = qi·kj = Σd=1..96 qdkd。96 次乘法 95 次加法，页面上每根绿色/红色柱就是一个维度的贡献（正/负）。

② 缩放　除以 √dhead = √96 ≈ 9.798。为什么必须除？设 q、k 各分量独立、均值 0、方差 1，则点积的方差为：

Var(q·k) = Σd Var(qdkd) = dhead = 96　→ 标准差 ≈ 9.8

不做缩放时，维度越高分数越"尖"，softmax 进入饱和区 → 梯度趋近 0（one-hot 附近无法学习）。除以 √d 恰好把方差归一回 1，使 softmax 始终工作在敏感区。

③ Softmax 归一化　对第 i 行的所有分数做指数归一，得到"注意力权重"分布 wij：

wij = exp(sij − si,max) / Σt≤i exp(sit − si,max)　减最大值仅为防 exp 溢出，不改变结果

权重非负、行和恒为 1（页面上每行右下角实时显示"行和=1.000000"，这正是 softmax 的守恒律）。它回答："为了更新 token i，我该把 100% 的注意力预算怎么分配给之前每个 token？"

④ 加权和　输出 oi = Σj≤i wij·vj。注意 softmax 只作用在"分数"上；v 向量按权重线性混合 —— 这保证了输出仍在 V 的凸包内、数值稳定。

演算台 · 动手实验建议 ① 选一个代词作 Query（如"我"），观察注意力权重是否集中于它指代的名词；② 把 Key 选到 Query 之后的 token，E 区会显示"因果掩码屏蔽"；③ 用行分布条形图对比第 1 层与第 7 层同一天的分布宽度 —— 浅层常出现"对角线+首 token"模式，深层分布更语义化。

§4多头注意力、GQA 与因果掩码

4.1 多头：在多个子空间同时检索

单次 96 维内积只能表达一种"关系"。把 768 维切成 8 个头（每头 96 维），各自独立做注意力，再拼接：

MHA(h) = Concat(head0,…,head7)·WoT,　headh = Attn(h·WqT|h, h·WkT|h, h·WvT|h)

不同头可以专门化：有的头盯语法结构（关注前一个词/标点），有的头做指代消解，有的头几乎只看句首。页面「② 注意力矩阵」切到 8 头平铺 能直接对比 8 个头的"性格"。

4.2 GQA：8 个头共享 4 组 KV

minimind-3 是 GQA（Grouped-Query Attention）：8 个 Q 头，但只有 4 组 K/V 头，每相邻 2 个 Q 头共享一组 KV（KV(h) = ⌊h/2⌋）。收益立竿见影 —— KV Cache 体积减半（§7.3），推理显存与带宽近乎减半，而质量损失极小。这也是本页演算台里 Key 向量只按 KV0..KV3 四组选择的原因。

4.3 因果掩码：不许偷看未来

语言模型的目标是 P(next token | 前文)，所以位置 i 不允许注意 j>i。实现上把违规分数置 −∞：

sij ← −∞　若 j > i　softmax 后权重严格为 0 → 注意力矩阵呈下三角

这一个掩码让同一个模型既能并行训练（一次算所有位置的损失）又能自回归生成。页面热力图中被屏蔽的右上三角以暗色斜线纹标注，点击合法格即可把 (i,j) 送进演算台。

§5Transformer Block 全貌：残差、RMSNorm 与 SwiGLU

5.1 一个 Block 的完整数据流

u = x + WoT·MHA(RMSNorm(x))　—— 注意力子层 + 残差
y = u + Wdown·( silu(Wgate·RMSNorm(u)) ⊙ (Wup·RMSNorm(u)) )　—— FFN 子层 + 残差

以上结构垂直堆叠 8 次（L0→L7），最后接一个全局 RMSNorm 与输出头。

5.2 残差连接：梯度的高速公路

残差 x ← x + f(x) 让每层只需学习"修正量"而非完整表示。直观上信息可以无损耗地直达深层；优化角度上梯度可通过加法直通浅层，这是百层网络可训练的关键。

5.3 RMSNorm：LayerNorm 的极简版

RMSNorm(x)d = xd / RMS(x) · γd,　RMS(x)=√( (1/d)Σxd2 + 1e−6 )

相比 LayerNorm 省去均值中心化（均值项作用很小），计算更省、效果相当，是 LLaMA/Qwen 系的标准选择。模型中共出现三种位置：每层输入侧两个 + 最终一个，每个都是 768 维可学习缩放 γ。注意 RMSNorm 不改变方向只调尺度 —— 归一化后所有向量 RMS=1。

5.4 SwiGLU 前馈网络：带门的记忆槽

FFN 占模型约 2/3 参数量（768→2432→768，三层投影共 ≈5.6M/层）。它被普遍理解为键值式记忆库：Wup/Wdown 存储知识片段，而 Wgate 提供逐维开关：

FFN(h) = ( silu(h·WgateT) ⊙ (h·WupT) ) ·WdownT,　silu(x)=x·σ(x)= x/(1+e−x)

silu 平滑非负门控（负值衰减、正值放行），⊙ 逐维相乘实现"哪些通道参与当前 token"的动态选择 —— 比 ReLU 版 FFN 收敛更快、下游表现更好。页面「⑤ FFN/SwiGLU 视图」实时重算 gate/up/激活三组 2432 维幅度谱，可观察不同 token 激活的通道集合差异。

§6输出头：logits、softmax 与采样

6.1 Tied Embedding 输出头

z = RMSNormfinal(x) · ET ∈ R6400　z 即 logits；E 正是 §1 的嵌入矩阵 —— 输入输出共用，参数省 4.9M

logitv 的直觉：最终隐状态与词表第 v 个词的嵌入"有多同向"。页面 MODULE06 顶部的整词表 log-scale 曲线就是 6400 维 logits 经 softmax 后按大小排序的分布。

6.2 从 logits 到概率：softmax 与温度

P(v|prefix) = exp(zv/T) / Σu exp(zu/T)

温度 T 重参数化分布尖锐度：T→0 退化为 argmax（贪心），T=1 为训练分布，T>1 更平（更随机）。数学上 T 与"除以 logits 标准差"等价，因此它精确控制熵。

6.3 截断采样与重复惩罚

  • Top-K：只保留分数前 K 个候选再归一化。
  • Top-P（核采样）：按概率降序累加，保留累计恰达 P 的最小集合 —— 候选数量随分布形状自适应：分布尖时几乎只剩 1 个，分布平时保留很多。
  • 重复惩罚：对已出现过的 token，正 logit 除以、负 logit 乘以惩罚系数 λ（λ>1 抑制复读）。

页面上每个候选行同时显示 P raw（未截断）与 P post（截断+温度后），被过滤项置灰 —— 可以直观看到 Top-P 如何"剪枝"。小模型纯文本续写常陷入复读循环，把 λ 拉到 1.3 或降温即可观察到分布被重塑、循环被打破的全过程。

6.4 贪心 vs 随机：怎么选？

贪心解码每步取 argmax：确定、可复现，适合事实型问答与测试；但可能陷入循环、文本呆板。随机采样（温度+Top-P）更有创造性，适合对话与写作，代价是不可复现（页面采样器使用可播种的 PRNG）。工程上还常配合存在惩罚/频率惩罚、beam search（舍弃，现代对话模型几乎不用）等。

6.5 困惑度（Perplexity）

PPL = exp( −(1/N) Σt ln P(xt|x<t) )

即"模型平均在多少个等概率候选中犹豫"。页面右上角实时显示下一步分布的熵（bits）与 PPL —— 单步 PPL=1 意味着模型 100% 确定（如成语接龙的下一个字），PPL 很大则表示有多种合理解。

§7推理系统工程：Prefill、KV Cache 与复杂度

7.1 两个阶段

  • Prefill（预填）：整段 prompt 一次性并行前向。注意力为 T×T 全矩阵计算，GPU 利用率高；产出自回归的第一个分布。
  • Decode（解码）：此后每步只有 1 个新 token 前向，注意力行向量 × 缓存矩阵。显存带宽瓶颈，是量化/投机解码等优化的主战场。

7.2 KV Cache：用空间换时间的核心

自回归生成中，前缀 token 的 K/V 每步都被重复使用。若每步重算整段序列，第 t 步成本 O(t²)；缓存后只需 O(t)。minimind-3 每层的 K/V 缓存为：

KV bytes/层 = 2 · nkv · dhead · ctx · 4B = 2·4·96·ctx·4B = 3072·ctx B
全模型（8 层）ctx=224 时 ≈ 5.25 MB　—— 若非 GQA（8 组 KV）将翻倍至 10.5MB；70B 模型上该技术节省的是 GB 级

页面每一步解码都严格使用缓存：可以在「交叉验证」里确认缓存路径与一次性整段前向 logits 偏差为 0（本工程实测 Δ=0）。

7.3 复杂度与上下文窗口

注意力计算/显存均为 O(T²)（prefill 阶段），FFN 为 O(T·d·dffn)；长上下文优化的研究（FlashAttention、MQA/GQA、滑窗、稀疏注意力）几乎都围绕这个平方项。页面上下文限制默认 512、可调至 2048（KV Cache 与 RoPE 表按 2048 预分配），遥测面板实时显示占用率与内存预估。

7.4 内存账单：权重、KV Cache 与可视化捕获

普通 LLM 服务常驻内存只有两块：权重和 KV Cache。而本页面为了"把中间量给你看"，多出第三块——可视化捕获池，它才是吃内存的大头：

① 权重常驻　= 参数量 × 4B = 63.9M × 4B ≈ 256MB（FP32；WebGL 后端另有同量 GPU 副本）。本页面 v2 起内嵌的就是 INT8 权重（文件夹仅 83MB、常驻 61MB，见 §7.6）；加载原始 FP16/FP32 时为 244MB
② KV Cache　= 2 × 层数 × KV头数 × 头维 × ctx × 4B = 2×8×4×96×T×4B ≈ 24.6KB × T
　T=512 → 12.6MB；T=2048 → 50MB —— 这就是 GQA 把 KV 头从 8 砍到 4 的直接收益（否则翻倍）
③ 捕获池·线性项 = 每 token（嵌入+残差流+final-norm 3×768；每层 ln1/ln2/两路贡献/Q 共 5×768）
　≈ (3 + 8×5) × 768 × 4B ≈ 132KB / token
④ 捕获池·二次项 = 注意力权重行（8层×8头 × 行长 t 的三角阵）≈ 64 × T²/2 × 4B
　T=512 全保留 → 约 33MB；T=2048 全保留 → 约 537MB —— 二次项是真正的炸弹

为什么捕获池这么大？因为服务端推理算完就丢，而教学分析仪要把"每层每头的注意力矩阵、每个 token 的残差流、Q/K/V 向量"全部留在内存里随取随看 —— 相当于把一次前向的所有中间激活都缓存下来。工程上给出了三个阀门（MODULE02「资源」区）：

  • 可视化捕获开关（默认开）：关闭后仅保留权重 + KV Cache，可跑满 2048 上下文，代价是散点/热力图/演算台停止更新；
  • 可视化窗口 W（默认 128）：只保留最近 W 个 token 的捕获，二次项从 64×T²/2 变为 64×W×T/2 —— T=2048、W=128 时从 537MB 骤降到约 64MB；更早的 token 沙盘数据被"滚动丢弃"，但 KV Cache 完整保留，生成质量不受任何影响；
  • 内存预估警示：遥测面板按上面②③④式实时估算"满上下文"开销，超过 150MB 黄色提醒、超过 400MB 红色预警。

7.5 一句话总结推理循环

LOOP · 直到 EOS 分布 = softmax(最终隐状态·ET) → 采样/贪心选 token → 查嵌入 → 追加进 KV Cache → 回到开头。页面的「单步 +1 Token」「自动播放」就是这个循环的手动档与自动档。

7.6 权重量化（INT8）：把 244MB 压到 61MB

部署侧最常用的压缩手段是权重量化：把 FP32 权重存成 8 位整数，计算时再反量化。本页面在 MODULE02「精度」下拉里实现了工业界标准的 W8A16 逐通道对称量化（权重 INT8、激活 FP32），可实时切换并对照：

对每个输出通道 o（权重矩阵的一行）：
scale[o] = maxi|W[o,i]| / 127
q[o,i] = round(W[o,i] / scale[o]) ∈ [−127, 127]
计算时：y[t,o] = scale[o] × Σi x[t,i] × q[o,i]　—— 整数只在存储层，乘加仍在 FP32/FP64 累加

本页面的内嵌格式（v2）：构建脚本 tools/gen_weights_int8.py 直接把量化后的 int8 数据 + 逐通道 scale 打包成普通 JS 文件（js/weights/q_XX.js，共 57 个张量 + FP32 归一化参数）——磁盘从 164MB 降到 83MB，常驻内存从 244MB 降到 61MB，且双击打开零交互。原始 FP16 权重（minimind-3/model.safetensors）保留在原处，供 FP32 基线对照与重新生成使用。

为什么逐通道而不是整个张量一个 scale？Transformer 权重里存在少数"离群通道"（数值比其他行大一个数量级）。若全张量共享 scale，离群值会把 scale 抬高，其余 99% 的权重被压到极小的整数区间，误差爆炸；逐行 scale 让每一行的满量程都被利用。为什么对称（zero-point=0）？权重分布近似零均值对称，不需要偏移，省掉 offset 项且整数乘加更干净。

误差从哪来、有多大？每个权重被舍入到相邻格点，误差 ≤ scale/2，且与权重值无关地均匀分布。本页 minimind-3 实测（可在顶栏「交叉验证」复现）：

指标 FP32 基线 INT8（W8A16）
权重大小 244MB 61.2MB（3.98×）
单权重最大量化误差 — 8.8×10⁻⁴
末位 logits max|Δ| — 0.44（量程 ±15，约 3%）
Top-1 / Top-5 一致性 — 一致 / 5-of-5

直觉解释：768 维点积中 768 个独立舍入误差按 √768 ≈ 28 倍 相互抵消（误差平均化），再被 softmax 的归一化进一步吸收 —— 所以"每个权重都变了"但"输出几乎没变"。这也是为什么 INT8 权重量化几乎无损、成为推理部署的默认动作。真正的挑战在别处：激活离群值（某些通道动辄上百，迫使 LLM.int8 这类混合精度方案）与 KV Cache 量化（会影响长上下文的注意力分布，本页 KV 保持 FP32）。

动手实验 ① 默认（双击打开）加载的就是 INT8 内嵌原生权重 —— 看 SYS 遥测权重行 61MB；② 点顶栏「交叉验证」→ 报告 TF/JS 后端一致性（INT8 模式下同样 2.77e-5 量级）；③ 用 ./start.sh 以 HTTP 模式运行时，可在精度下拉选「FP32（从 minimind-3/ 原始权重加载）」→ 自动拉取 122MB 原始权重并执行 FP32↔INT8 对照（max|Δlogits|、Top-1、分布重合度 ≈98%）。
