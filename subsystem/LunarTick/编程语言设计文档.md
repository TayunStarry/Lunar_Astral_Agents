# LunarTick 轻量级调度语言规范（v5.0 · 精简实用版）

## 0. 设计概览

### 0.1 一句话定位
LunarTick 是一门**单线程、tick 驱动的反应式调度语言**——所有逻辑被编译为按固定节拍推进的状态机，用字符串变量 + 指针引用解耦控制流，天然适合嵌入各种宿主环境。

### 0.2 核心功能边界

| 维度 | 包含 | 不包含 |
|------|------|--------|
| **数据类型** | 字符串（唯一类型） | 数值、布尔、列表、字典 |
| **并发模型** | 逻辑并发（多代码块分时步进） | 系统级线程/协程 |
| **外部交互** | 进程调用、文件读写、HTTP 访问 | 数据库、图形界面 |
| **控制流** | 条件分支、循环、惰性函数 | 异常捕获、协程挂起 |
| **扩展机制** | 插件注册新指令 | 修改核心 tick 语义 |

### 0.3 用户场景
1. **CI/CD 流水线编排**：定义编译→测试→部署步骤链，每个步骤异步等待
2. **服务健康监控**：周期性检查进程/端口状态，发现异常触发通知
3. **文件批处理**：监听目录变化→触发转换→归档→通知
4. **嵌入式自动化**：IoT 设备的定时任务调度（传感器采集→本地处理→上报）

### 0.4 关键性能指标
| 指标 | 目标值 | 说明 |
|------|--------|------|
| Tick 间隔 | 10~5000 ms（默认 100 ms） | 可配置 |
| 最大并发代码块 | 10000 | 超出触发警告 |
| 单 tick 处理延迟 | < tick_interval * 0.5 | 超时产生警告 |
| 内存占用（空闲） | < 10 MB | 停摆状态下 |
| 启动时间 | < 50 ms | 从加载到首个 tick |

## 1. 语言概述
LunarTick 是一门专为**反应式调度与自动化**设计的轻量级脚本语言。语言只使用一种数据类型——字符串；变量无需声明即全局可用，并保证原子访问。v4.0 引入**强制 tick 时钟模型**：所有代码块的执行被统一到固定频率的离散时间刻中，解释器按 tick 节奏推动状态流转。语法仍由 `@` 指令、`#` 变量、`*` 指针组成，可嵌入 Markdown 或 JSON 宿主格式。

v5.0 精简了设计文档结构，新增了技术架构、数据流图和实现路径规划章节，使文档从纯规范变为**规范+实现指南**的综合性文档。

**设计理念**：  
把异步任务、等待、重试、分支都编码为以 tick 为节拍的状态机。每个 tick 解释器推动所有活跃代码块前进一步，条件不满足则自动跳过，周而复始，直到所有块终止；若无活跃块，系统进入停摆（suspend），等待新块注入后再次启动。

## 2. 词法约定

### 2.1 前缀符号
- `@` ：执行指令（如 `@run`、`@if`、`@def`、`@lazy`）
- `#` ：变量操作或变量引用
- `*` ：指针引用（代码库、快照）

### 2.2 字面量与标识符
- **字符串字面量**：使用单引号 `'...'` 或双引号 `"..."`，可交替包含引号。
- **变量名**：`#` 后跟字母、数字、下划线，如 `#result`、`#file2`。
- **指针名**：`*` 后规则同上，如 `*backup`、`*snap1`。
- **数字**：仅作为字符串内容，无独立数字类型。
- **变量求值**：在表达式中 `#var` 替换为变量的当前值；若变量未定义或处于只写模式，则替换为 `""`。

### 2.3 分隔与注释
- 每条指令独占一行，行首尾空白忽略。
- `//` 开头的行是注释。
- 空行忽略。

### 2.4 代码块定义
- **Markdown**：每一对 ` ```LunarTick ` 和 ` ``` ` 之间的行构成一个代码块。
- **JSON**：通过宿主 API `LunarTick.loadJSON(string[][])` 加载。

## 3. tick 调度模型

### 3.1 时钟频率与节奏
- **默认 tick 间隔**：**100 毫秒** (10 Hz)。可通过系统变量 `#TICK_MS` 在启动时修改（范围：10 ms ~ 5000 ms）。
- 每个 tick 为一个原子调度周期，解释器严格按以下阶段循环：
  1. **注入阶段**：将上一 tick 中 `*指针` 调用产生的新代码块加入就绪列表。
  2. **执行阶段**：遍历所有**就绪**代码块，每个块执行**恰好一条指令**。
  3. **就绪检查阶段**：检查所有**等待**中的代码块，将条件满足的块转移回就绪列表。
  4. **终止检查**：移除已终止的块。若就绪列表和等待列表均为空，系统进入**停摆**状态。
  5. **休眠至下一 tick 边界**。

### 3.2 代码块生命周期
每个代码块拥有以下状态：
- **就绪**：下一 tick 可被调度执行。
- **等待**：被阻塞指令挂起，等待条件满足。
- **终止**：执行完毕或被显式终止，从系统中移除。

### 3.3 阻塞语义的统一化
所有可能造成等待的指令（`@wait`、`@sleep`、`@catch`、独立的 `@run`）不再真正挂起线程，而是将当前代码块标记为等待，并注册唤醒条件。

### 3.4 系统停摆与唤醒
当解释器处于停摆状态时，宿主可通过 `LunarTick.inject(lines[])` 或 `LunarTick.invoke(pointerName)` 注入新代码块来唤醒。

## 4. 变量与数据模型

### 4.1 全局变量
- 无需声明，首次赋值即创建，默认值 `""`。
- 所有代码块共享同一张全局变量表。
- 系统保留变量（只读）：
  - `#TICK` ：当前 tick 序号
  - `#TICK_MS` ：tick 间隔毫秒数

### 4.2 赋值与模式控制
| 指令 | 行为 |
|------|------|
| `SET #变量 表达式` | 覆盖赋值，模式不变 |
| `ADD #变量 表达式` | 追加赋值（字符串拼接） |
| `WRT #变量 表达式` | 写入值并设变量为**只写** |
| `RON #变量 表达式` | 写入值并设变量为**只读** |
| `UNL #变量 表达式` | 解除限制，追加到现有值末尾 |

## 5. 指针与快照

### 5.1 指针类型
| 指针类型 | 创建方式 | 调用行为 |
|---------|---------|---------|
| class 指针 | `@build *ptr class` / `@lazy *ptr` | 在下一 tick 创建代码块副本 |
| snapshot 指针 | `@build *ptr snapshot` / `@end *ptr` | 立即恢复所有变量状态 |

### 5.2 `@lazy` — 静态惰性指针定义
`@lazy *指针名` 必须出现在一个代码块的**第一行**。该代码块加载时不进入调度，而是注册为 class 指针，仅在显式调用时执行。

### 5.3 `@def` — 前向声明
`@def *指针名` 将指针名注册为空（已定义但无指令），用于提前占位，保证互递归中指针存在性检测为 `"true"`。

## 6. 内置指令参考

### 6.1 进程调用与捕获
- **@run** `路径 [参数...]`：异步执行外部程序，当前块进入等待直到进程退出。
- **@catch** `#变量 '子串'` + `@run ...`：包装 `@run` 以捕获输出行。命中目标子串时立即将完整行写入变量并解除等待。
- **@call** `#变量 *指针名` + `@run ...`：包装 `@run`，进程每输出一行即写入变量并调用指定指针。

### 6.2 阻塞指令
- **@wait** `#变量`：等待变量值不为 `""`。
- **@sleep** `毫秒数`：异步休眠指定毫秒数。

### 6.3 变量处理
- **@filter** `#变量 '正则'`：正则提取，覆盖写入。
- **@math** `#变量 '算术表达式'`：算术运算，结果以字符串覆盖写入。

### 6.4 控制流
- **@if** `'条件' ? *真分支 : *假分支`：条件分支。
- **@cycle** `'条件' *循环体`：条件循环。
- **@retry** `冷却毫秒 最大次数 #错误变量`：错误重试。

### 6.5 文件与输出
- `@write #路径变量 #内容变量`：覆盖写入文件。
- `@read #路径变量 #目标变量`：读取文本文件。
- `@log '内容'` 或 `@log #变量`：输出到标准输出。

### 6.6 其他
- `@web #变量`：用浏览器打开 URL。
- `@stop`：立即终止当前代码块。
- `@limit 毫秒数`：最大生存时间。
- `@def *指针名`：前向声明空指针。
- `@lazy *指针名`：惰性指针定义。
- `@build *指针名 class|snapshot`：动态构建指针。
- `@end *指针名`：构建 snapshot 并终止所有块。

### 9.1 模块划分

```

│                  宿主层                      │

│  ┌──────────┐ ┌──────────┐ ┌────────────┐  │
│  │ 调度器    │ │ 注入器   │ │ 停摆管理器  │  │
│  │(Ticker)   │ │(Injector)│ │(Suspender) │  │
│  └──────────┘ └──────────┘ └────────────┘  │
├────────────────────────────────────────────┤
│                核心执行层                     │
│  ┌──────────┐ ┌──────────┐ ┌────────────┐  │
│  │ 代码块   │ │ 指令解析  │ │ 表达式求值  │  │
│  │(Block)   │ │(Parser)  │ │(Expression) │  │
│  ├──────────┤ ├──────────┤ ├────────────┤  │
│  │ 指针管理  │ │ 变量存储  │ │ 进程执行器  │  │
│  │(Pointer) │ │(Variable) │ │(Executor)  │  │
│  └──────────┘ └──────────┘ └────────────┘  │
├────────────────────────────────────────────┤
│              基础设施层（复用 subsystem/）     │
│  ┌──────────┐ ┌──────────┐ ┌────────────┐  │
│  │ logger   │ │ config   │ │ proxy      │  │
│  │(subsystem│ │(subsystem│ │(subsystem  │  │
│  │ /logger) │ │ /config) │ │ /proxy)    │  │
│  └──────────┘ └──────────┘ └────────────┘  │
└────────────────────────────────────────────┘
```

### 9.2 组件交互流程

```
用户代码 → 解析器(Parser) → 代码块(Block[]) → 注入器 → 就绪列表
                                                         ↓
外部进程 ← 进程执行器(Executor) ← 指令执行 ← Tick调度器(Ticker)
    ↓                                        ↓
输出捕获 → 变量存储(Variable) ← 指针管理(Pointer) → 新代码块注入
```

### 9.3 数据流图（单 tick）

```
Tick N 开始
  ├→ [注入阶段] 暂存区新块 → 就绪列表尾部
  ├→ [执行阶段] 遍历就绪列表
  │     ├→ 取代码块当前指令
  │     ├→ 解析指令类型
  │     ├→ 执行指令处理器
  │     │    ├→ @run/@catch → 启动进程 → 块→等待列表
  │     │    ├→ @wait → 检查变量 → 块→等待列表(条件不满足)
  │     │    ├→ @sleep → 注册定时器 → 块→等待列表
  │     │    ├→ @if → 求值条件 → *指针调用 → 暂存区
  │     │    ├→ SET/ADD/... → 更新全局变量表
  │     │    └→ @stop → 块→终止
  │     └→ 块内PC+1（若未阻塞）
  ├→ [就绪检查] 遍历等待列表
  │     ├→ 进程退出 → 块→就绪列表
  │     ├→ 变量非空 → 块→就绪列表
  │     └→ 定时器到期 → 块→就绪列表
  ├→ [终止检查] 移除已结束的块
  └→ [休眠] 等待下一tick边界
Tick N 结束
```

### 9.4 关键数据结构

```go
// 代码块
type CodeBlock struct {
    ID          string
    Instructions []Instruction
    PC          int          // 当前指令指针
    Status      BlockStatus  // Ready/Waiting/Terminated
    WaitReason  WaitCondition
    Origin      string       // 来源指针名（@lazy 调用时）
}

// 全局变量
type VarStore struct {
    mu    sync.RWMutex
    vars  map[string]VarEntry
}

type VarEntry struct {
    Value string
    Mode  VarMode  // Normal/ReadOnly/WriteOnly
}

// 指针注册表
type PointerRegistry struct {
    mu      sync.RWMutex
    pointers map[string]PointerEntry
}

type PointerEntry struct {
    Type       PointerType  // Class/Snapshot
    Lines      []string     // class: 指令行; snapshot: 变量快照
    TickStamp  int          // snapshot 的创建 tick
}
```

## 11. 实现要求

- **原子性**：单变量读写操作必须无撕裂。
- **快照**：保存值、模式及 tick 序号，恢复时全局替换。
- **错误处理**：运行时错误不崩溃解释器，仅终止所在块。
- **复合指令处理**：解释器在解码阶段必须识别 `@catch` 后紧跟 `@run` 的组合，将其内部表示为一个复合等待指令。
- **加载阶段特殊处理**：解释器必须在加载代码块后立即检查首条非空非注释行。若为 `@lazy *指针名`，则将该块存储为 class 指针，不加入就绪列表。
- **`@lazy` 覆盖规则**：若指针名已存在，静默覆盖。
- **扩展性**：插件可注册新指令，但不得改变核心指令的 tick 语义。

## 12. tick 驱动示例

### 示例 1：`@catch`/`@run` 非阻塞行为
```LunarTick
@log 'Start monitoring...'
@catch #found 'READY'
@run './long_task.exe'
@log 'Captured line: ' + #found
@sleep 5000
@log 'Done'
```

### 示例 2：`@lazy` 惰性函数
```LunarTick
@lazy *backupTask
SET #src '/data'
SET #dst '/backup'
@run 'cp' '-r' #src #dst
@wait #?
@log 'Backup completed'

@log 'System ready...'
*backupTask
@stop
```

### 示例 3：互递归与 `@def` 占位
```LunarTick
@def *B
@lazy *A
@log "Enter A"
@if 'true' ? *B : *A

@lazy *B
@log "Enter B"
@if 'true' ? *A : *B
```
