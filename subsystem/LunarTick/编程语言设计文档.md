# LunarTick 轻量级调度语言规范（v4.1 · tick 驱动）

## 1. 语言概述
LunarTick 是一门专为**反应式调度与自动化**设计的轻量级脚本语言。语言只使用一种数据类型——字符串；变量无需声明即全局可用，并保证原子访问。v4.0 引入**强制 tick 时钟模型**：所有代码块的执行被统一到固定频率的离散时间刻中，解释器按 tick 节奏推动状态流转。语法仍由 `@` 指令、`#` 变量、`*` 指针组成，可嵌入 Markdown 或 JSON 宿主格式。

v4.1 新增 `@lazy` 指令，允许将整个代码块静态定义为一个 **惰性 class 指针**，加载时不进入调度，仅在显式调用或条件触发时才在 tick 中执行，使函数式抽象更自然。同时澄清了 `@catch`/`@run` 复合阻塞语义。

**设计理念**：  
把异步任务、等待、重试、分支都编码为以 tick 为节拍的状态机。每个 tick 解释器推动所有活跃代码块前进一步，条件不满足则自动跳过，周而复始，直到所有块终止；若无活跃块，系统进入停摆（suspend），等待新块注入后再次启动。

## 2. 词法约定

### 2.1 前缀符号
- `@` ：执行指令（如 `@run`、`@if`、`@def`、`@lazy`）
- `#` ：变量操作或变量引用
- `*` ：指针引用（代码库、快照）

### 2.2 字面量与标识符
- **字符串字面量**：使用单引号 `'...'` 或双引号 `"..."`，可交替包含引号。
- **变量名**：`#` 后跟字母、数字、下划线，如 `#result`、`#file2`。
- **指针名**：`*` 后规则同上，如 `*backup`、`*snap1`。
- **数字**：仅作为字符串内容，无独立数字类型。
- **变量求值**：在表达式中 `#var` 替换为变量的当前值；若变量未定义或处于只写模式，则替换为 `""`。

### 2.3 分隔与注释
- 每条指令独占一行，行首尾空白忽略。
- `//` 开头的行是注释。
- 空行忽略。

### 2.4 代码块定义
- **Markdown**：每一对 ` ```LunarTick ` 和 ` ``` ` 之间的行构成一个代码块。  
  ```markdown
  ```LunarTick
  @run './task1'
  @wait #done
  ```
  ```
- **JSON / JavaScript**：最外层数组的每个元素是一个代码块，每个代码块是字符串数组（每行一个指令）。解释器按数组顺序加载，但所有块将在第一个 tick 统一进入调度系统（`@lazy` 块除外）。
  ```json
  [
    ["@run './task1'", "@wait #done"],
    ["@log 'All tasks started'"]
  ]
  ```

## 3. tick 调度模型

### 3.1 时钟频率与节奏
- **默认 tick 间隔**：**100 毫秒** (10 Hz)。可通过系统变量 `#TICK_MS` 在启动时修改（范围：10 ms ~ 5000 ms）。
- 每个 tick 为一个原子调度周期，解释器严格按以下阶段循环：
  1. **注入阶段**：将上一 tick 中 `*指针` 调用产生的新代码块加入就绪列表。
  2. **执行阶段**：遍历所有**就绪**代码块，每个块执行**恰好一条指令**（若指令非阻塞，该块仍保持就绪；若指令为阻塞型，该块转入等待并挂起）。
  3. **就绪检查阶段**：检查所有**等待**中的代码块（睡眠到期、进程退出、变量非空、`@catch` 输出捕获等），将条件满足的块转移回就绪列表。
  4. **终止检查**：移除已执行完最后一条指令或被 `@stop` / `@end` 终止的块。若就绪列表和等待列表均为空，系统进入**停摆**状态（不再消耗 CPU），直到外部通过宿主接口注入新的代码块或指针调用。
  5. **休眠至下一 tick 边界**：系统休眠剩余时间，使相邻 tick 起点间隔稳定为设定值。若某 tick 处理时间超出间隔，则下一 tick 立即开始（无额外休眠），并产生一条警告。

### 3.2 代码块的生命周期与状态
每个代码块拥有以下状态：
- **就绪**：下一 tick 可被调度执行。
- **等待**：被阻塞指令挂起，等待条件满足。
- **终止**：执行完毕或被显式终止，从系统中移除。

**就绪列表的调度顺序**：代码块以加载顺序（或指针调用创建顺序）固定排序，每个 tick 从前往后各执行一步，做到确定性并发。

### 3.3 阻塞语义的统一化
所有可能造成等待的指令（`@wait`、`@sleep`、`@catch`、独立的 `@run`）不再真正挂起线程，而是将当前代码块标记为等待，并注册唤醒条件。解释器在每个 tick 的“就绪检查阶段”统一评估这些条件。这使得解释器可以用单线程 + 事件循环实现，极易嵌入各种宿主（浏览器、嵌入式设备）。

### 3.4 指针调用与 tick 边界
- 在 tick N 中遇到 `*ptr` 调用指令时，若 `*ptr` 为 class 指针（包括 `@lazy` 定义的），则其代码块**不会立即执行，而是放入暂存区**，在 tick N 结束后的“注入阶段”（即 tick N+1 的开头）成为就绪代码块。
- 若为 snapshot 指针，则恢复动作**立即在当前 tick 生效**（因为恢复属于即时的全局状态操作），但新指针代码块的创建规则同上。

### 3.5 系统停摆与唤醒
当解释器处于停摆状态时，宿主可通过以下方式注入新代码块来唤醒：
- 调用 `LunarTick.inject(lines[])` 注入一个新代码块（字符串数组）。若新块首行非 `@lazy`，则正常加入就绪列表；若为 `@lazy`，则注册为惰性指针后不唤醒系统（除非后续有 `invoke` 等操作）。
- 调用 `LunarTick.invoke(pointerName)` 直接触发某个 class 指针的执行（等同于在停摆期间模拟一个 `*ptr` 调用，下一个 tick 生效）。
唤醒后 tick 循环立即从下一个边界恢复。

## 4. 变量与数据模型

### 4.1 全局变量
- 无需声明，首次赋值即创建，默认值 `""`。
- 所有代码块共享同一张全局变量表，读写全开放，且保证原子性（无撕裂读写）。
- 系统保留变量（只读，不可由用户指令修改）：
  - `#TICK` ：当前 tick 序号（从 1 开始计数，字符串形式）。
  - `#TICK_MS` ：tick 间隔毫秒数（加载时设定，默认 `"100"`）。

### 4.2 赋值与模式控制
指令均为三字母大写单词，可能改变变量的读写模式：

| 指令 | 行为 |
|------|------|
| `SET #变量 表达式` | 覆盖赋值，模式不变 |
| `ADD #变量 表达式` | 追加赋值（字符串拼接），模式不变 |
| `WRT #变量 表达式` | 写入值并设变量为**只写**（读取永远返回 `""`） |
| `RON #变量 表达式` | 写入值并设变量为**只读**（后续赋值均被忽略） |
| `UNL #变量 表达式` | 解除只写/只读限制（变为普通模式），并将表达式追加到现有值末尾 |

- 表达式中 `+` 表示字符串拼接，见 8.1 节。
- 模式保护在 tick 调度下同样具有强制性。
- 特殊读取规则：未定义变量或只写变量读取均返回 `""`。

## 5. 指针与快照

### 5.1 指针引用语法
- **作为值**：`*指针名` 在条件中返回 `"true"`（已定义）或 `"false"`（未定义）。
- **作为指令**：直接书写 `*指针名` 一行，若为 class 指针则于**下一 tick** 创建新代码块；若为 snapshot 指针则**立即恢复**所有变量状态。
- **前向声明**（`@def`）：`@def *指针名` 将指针名注册为空（已定义但无指令），不产生运行效果，且不会被 `@build` 捕获。用于提前占位，保证互递归或分支中的指针存在性检测为 `"true"`。
- **静态惰性定义**（`@lazy`）：见 5.3。

### 5.2 动态构建指针
- `@build *指针名 class`  
  将当前代码块的所有指令行（不含 `@build` 自身及任何 `@def` 行）保存为 class 指针。若指针已存在（包括 `@def` 声明），则覆盖。
- `@build *指针名 snapshot`  
  将当前时刻所有已定义变量（含值、读写模式）保存为 snapshot 指针，并附带当前 `#TICK` 值作为元数据。若指针已存在则覆盖。
- `@end *指针名`  
  自动构建一个 snapshot 指针，然后终止**所有**代码块的执行（系统进入停摆前保存状态）。

### 5.3 `@lazy` — 静态惰性指针定义（v4.1 新增）
`@lazy *指针名` 必须出现在一个代码块的**第一行**（不含注释和空行）。它表示该代码块整体不作为可执行实体进入调度，而是在加载时直接被注册为一个 **class 指针**。规则如下：
- 整个代码块的所有指令（含第一行 `@lazy` 之后的部分）都隶属于该指针。
- 加载阶段：解释器遇到 `@lazy` 开头的代码块时，提取指针名，将剩余行保存为 class 指针，**不将该块加入就绪列表**。
- 运行时：任何其他代码块执行 `*指针名` 调用，或通过 `@if`/`@cycle` 触发该指针，等价于调用一个 class 指针：在下一 tick 的注入阶段创建该代码块的一个副本并进入就绪列表。
- 同一个指针名若已存在（包括 `@def`、`@build` 或另一个 `@lazy`），`@lazy` 会直接覆盖（替换指针内容）。
- 在 `@lazy` 块内部可以正常使用 `@build`、`@def` 等指令，这些指令将在**该块被调用时动态执行**。
- 禁止在 `@lazy` 块内再次使用 `@lazy`（加载时报错），因为一个代码块只能定义一次自己的属性。
- 与 `@def` 的区别：`@def` 仅声明空指针（不含指令体），主要用于前向引用；`@lazy` 定义的是具有完整逻辑的惰性函数。

示例：
```LunarTick
@lazy *doBackup
SET #target '/data'
@run './backup.exe' '--path' #target
@wait #result
@log #result
```

## 6. 执行模型并发细节

- **并行粒度**：不同代码块在不同 tick 步进，形成逻辑并发；同一 tick 内每个块执行一条指令，避免独占。
- **错误隔离**：运行时错误（如 `@run` 进程不存在）仅终止当前代码块（触发重试逻辑前），不影响其他块。
- **确定性**：因为每个块每 tick 只执行一条指令，且就绪列表顺序固定，系统状态变迁可复现（只要外部命令输出和时机可控）。
- **惰性块的加载**：`@lazy` 块在加载时完成指针注册，不参与任何 tick 调度，直到被显式调用。其内部定义的 `@retry` 等保护指令在该块被调用时生效。

## 7. 内置指令参考

### 7.1 参数规则
指令参数以空格分隔，含空格参数需用引号。除非是字面量或条件表达式，否则最后一个参数必须是变量或指针。禁止内嵌指令文本。

### 7.2 程序调用与捕获（tick 适配）

**@run** — 异步执行外部程序  
```
@run 路径 [参数1 [参数2 ...]]
```
- **独立使用**（无前置 `@catch` 时）：启动外部进程后，当前代码块立即进入**等待**状态，直到进程退出才在未来的 tick 恢复就绪。标准输出和标准错误合并可供捕获（但无 `@catch` 捕获时输出被丢弃）。
- 进程退出码会存入虚拟变量 `#?`（当前块局部可见，下一条指令前有效；`@if` 判断后自动清除）。
- **受 `@catch` 包装时**：见 `@catch` 说明。

**@catch** — 包装 `@run` 以捕获输出行（复合阻塞指令）
```
@catch #变量 '目标子串'
@run ...                          // 必须紧接在下一行
```
- `@catch` 与紧随其后的 `@run` 构成一个**复合指令对**。执行到 `@catch` 行时，当前代码块进入**等待**状态；解释器确认下一行是 `@run` 后，启动指定外部进程，并将该进程的输出流与 `@catch` 的条件绑定。
- **阻塞主体**：阻塞当前块的是 `@catch`，而非被包装的 `@run`。`@run` 在此不产生独立的阻塞行为。
- **唤醒条件**：
  - 若进程输出的任何一行（实时读取）包含目标子串，则将该**完整行**以追加模式写入 `#变量`，**立即解除当前块的等待**，代码块恢复就绪，并从 `@run` 的下一行继续执行。此时 `@run` 启动的进程**仍在后台继续运行**，但不再影响该代码块的后续调度（除非后续又有新的 `@catch` 或 `@wait` 与该进程相关，标准行为是不再理会）。
  - 若进程结束而始终未出现目标子串，`@catch` 同样解除等待（不写入任何内容），代码块继续执行后续指令。
- 因此，`@catch` 的等待时长 ≤ 进程的生命周期，一旦命中即提前返回，不会一直等到进程退出。
- **错误处理**：若 `@catch` 的下一行不是 `@run`，解释器应终止当前代码块并报错（结构错误）。

### 7.3 其他阻塞指令

**@wait** — 等待变量非空
```
@wait #变量
```
- 当前块进入等待，直到指定变量值不为 `""`。**注意**：只写变量永远返回 `""`，将导致永久等待。

**@sleep** — 基于时钟的休眠（非阻塞异步实现）
```
@sleep 毫秒数
```
- 当前块进入等待，持续指定的真实毫秒数（基于系统时钟），到期后恢复就绪。最小精度为一个 tick 的时长。
- **实现机制**：使用 Go 的 `time.After()` 异步通知机制，不会阻塞 tick 循环。当睡眠时间到期时，通过通道异步唤醒代码块，避免了轮询带来的性能开销和精度问题。

### 7.4 输出捕获与回调（v4.1 新增）

**@call** — 包装 @run 以捕获输出并触发指针调用
```
@call #变量 *指针名
@run 路径 [参数1 [参数2 ...]]
```
- `@call` 与紧随其后的 `@run` 构成一个**复合指令对**。执行到 `@call` 行时，设置输出捕获上下文。
- **输出处理**：`@run` 启动的进程每输出一行，该行内容被写入指定变量，然后立即调用指定的 class 指针。
- **非阻塞特性**：`@call` 本身不阻塞代码块执行，代码块会继续执行后续指令。进程输出通过异步方式处理。
- **使用示例**：
  ```LunarTick
  @lazy *logHandler
  @log 'Received line: ' + #output
  
  @call #output *logHandler
  @run 'tail' '-f' '/var/log/app.log'
  @log 'Command started'
  ```
- **错误处理**：若指针不存在或不是 class 指针，解释器会记录错误但不终止代码块。

### 7.5 变量处理

**@filter** — 正则提取
```
@filter #变量 '正则表达式'
```
- 对变量值应用正则，将第一个捕获组（或整体匹配）以覆盖模式写入变量（模式不变）。
- 示例：`@filter #html 'href="([^"]+)"'`

**@math** — 算术运算
```
@math #变量 '算术表达式'
```
- 计算算术表达式，结果以字符串覆盖写入变量。非数字字符串视为 0。支持 `+ - * / % ()` 及 `int(expr)` 向下取整。
- 示例：`@math #x '#x + 1'`

### 7.6 控制流（完全通过指针和变量解耦）

**@if** — 条件分支
```
@if '条件表达式' ? *真分支指针 : *假分支指针
```
- 若条件为真，于**下一 tick** 执行 `*真分支指针` 对应的 class 代码块；否则执行 `*假分支指针`。不允许内联指令串，必须使用指针。

**@cycle** — 条件循环
```
@cycle '条件表达式' *循环体指针
```
- 每个 tick，若条件为真（非空且非 `"false"`），则在**当前 tick** 内调用 `*循环体指针`（产生新代码块，于下一 tick 运行）。当条件为假时，该 `@cycle` 指令视为完成，继续执行下一条指令。

**@retry** — 错误重试
```
@retry 冷却毫秒 最大重试次数 #错误变量
```
- 当前代码块因运行时错误终止时，等待冷却时间后，**克隆整个原始代码块**作为新块从第一条指令重新执行（全局变量保持原状）。若原始块来自 `@lazy`，则克隆其定义体。
- 错误信息以追加写入 `#错误变量`。重试次数 <1 视为不重试。

### 7.7 文件与输出

- `@write #路径变量 #内容变量`：覆盖写入文件（内容变量若为只写则写空串）。
- `@read #路径变量 #目标变量`：读取全部文本，以覆盖写入目标变量。
- `@log '内容'` 或 `@log #变量`：输出到标准输出，自动换行。

### 7.8 其他

- `@web #变量`：用系统默认浏览器打开变量中的 URL。
- `@stop`：立即终止当前代码块（不触发重试）。
- `@limit 毫秒数`：为当前块设置最大生存时间（真实时间），超时强制终止并视为错误。
- `@def *指针名`：声明一个空指针（已定义但无指令体），用于前向引用。不被 `@build` 捕获。
- `@lazy *指针名`：（必为代码块首行指令）将当前代码块静态绑定为该 class 指针，加载时注册而不执行。详见 5.3。

## 8. 表达式语法

### 8.1 字符串拼接（ + ）
`SET #msg 'Hello ' + #name + '!'`  
从右向左拼接，变量只写则视作空串。

### 8.2 条件表达式
用于 `@if` 和 `@cycle`。支持比较 `= != > < >= <=`（字符串字典序）、逻辑 `& | !` 及括号。数值比较前请用 `@math` 格式化（补零对齐等）。

## 9. 嵌入宿主格式

解释器 API：
- `LunarTick.loadMarkdown(mdText)` ：扫描 ` ```LunarTick ` 代码块。遇到 `@lazy` 块，加载为惰性指针，不产生就绪代码块。
- `LunarTick.loadJSON(jsonArray)` ：接收 `string[][]`。每个子数组作为一个代码块，同样识别 `@lazy`。
- `LunarTick.setTickInterval(ms)` ：设置 tick 间隔（需在启动前调用）。
- `LunarTick.start()` ：启动 tick 循环。
- `LunarTick.inject(lines[])` ：在停摆或运行时动态注入代码块。若首行为 `@lazy`，则仅注册指针，不唤醒循环；否则加入就绪列表并唤醒系统（若原为停摆）。
- `LunarTick.invoke(pointerName)` ：停止停摆并调用 class 指针（含 `@lazy` 定义的指针）。

## 10. tick 驱动示例

### 示例 1：`@catch`/`@run` 非阻塞行为
```LunarTick
@log 'Start monitoring...'
@catch #found 'READY'
@run './long_task.exe'
@log 'Captured line: ' + #found
@sleep 5000
@log 'Done'
```
- `@catch` 行使块等待；`@run` 启动 `long_task.exe`。
- 如果进程输出中包含 `READY`，则 `#found` 被赋值，块立即恢复，打印捕获行，然后进入 `@sleep`。此时 `long_task.exe` 仍在后台运行，但块不再等待它退出。
- 如果进程结束也从未输出 `READY`，则 `@catch` 解除等待（`#found` 保持旧值或空），块继续执行后续指令。

### 示例 2：`@lazy` 惰性函数
```LunarTick
@lazy *backupTask
SET #src '/data'
SET #dst '/backup'
@run 'cp' '-r' #src #dst
@wait #?
@log 'Backup completed'

// 另一个正常块触发
@log 'System ready...'
*backupTask
@stop
```

### 示例 3：互递归与 `@def` 占位
```LunarTick
@def *B                       // 前向声明，使下面 @if 中 *B 为 "true"
@lazy *A
@log "Enter A"
@if 'true' ? *B : *A

@lazy *B
@log "Enter B"
@if 'true' ? *A : *B
```

## 11. 实现要求

- **原子性**：单变量读写操作必须无撕裂。
- **快照**：保存值、模式及 tick 序号，恢复时全局替换，但若当前 tick 有活跃的快照恢复操作，解释器需在该 tick 内暂停其他块执行以避免竞态。
- **错误处理**：运行时错误不崩溃解释器，仅终止所在块。
- **复合指令处理**：解释器在解码阶段必须识别 `@catch` 后紧跟 `@run` 的组合，将其内部表示为一个复合等待指令。执行时遇到 `@catch` 即进入等待，不再将 `@run` 作为一个独立步进指令。
- **加载阶段特殊处理**：解释器必须在加载代码块后立即检查首条非空非注释行。若为 `@lazy *指针名`，则将该块剩余行（及该行自身）存储为 class 指针，并不加入就绪列表；否则按正常流程加入就绪列表。`@lazy` 块内的语法错误可在加载时或首次调用时检测，推荐尽早报错。
- **`@lazy` 覆盖规则**：若指针名已存在，静默覆盖（与 `@build` 行为一致）。
- **扩展性**：插件可注册新指令，但不得改变核心指令的 tick 语义。
