# Sticker 子系统文档

## 1. 系统概述

Sticker 是 Lunar Astral Agents 的表情包模型训练器子系统，主要功能是处理图片目录中的表情包，通过调用视觉模型生成描述标签，调用嵌入模型生成向量表示，并将结果保存到知识库中，用于表情包的识别和响应。

## 2. 功能特点

- **图片处理**：自动扫描指定目录中的图片文件
- **视觉识别**：调用多模态模型生成图片描述标签
- **描述优化**：对已有描述的图片进行优化更新
- **向量生成**：调用嵌入模型生成图片描述的向量表示
- **知识库管理**：读取和保存知识库文件，支持增量更新
- **统计分析**：提供详细的处理结果统计信息
- **服务器交互**：与主系统服务器进行交互，上传图片和保存知识库
- **错误处理**：提供详细的错误信息和处理建议

## 3. 核心组件

### 3.1 配置常量

| 常量 | 值 | 描述 |
|------|-----|------|
| ServerPort | "36789" | 服务器端口 |
| ServerURL | "https://localhost:36789" | 服务器URL |

| MetaVersion | "25.1230" | 元数据版本 |

| DefaultImageDir | "../../meme-images" | 默认图片目录 |

### 3.2 数据结构

- **InferencePayload**：推理请求负载
- **TextMessage**：纯文本消息
- **MultimodalMessage**：图文混合消息
- **ImageContent**：图片内容块
- **TextContent**：文本内容块
- **HistoryMessage**：历史消息
- **HistoryDocument**：历史会话导出文档结构
- **ChatCompletionResponse**：聊天完成响应
- **EmbeddingResponse**：嵌入响应
- **SaveFileResponse**：保存文件响应
- **Config**：配置信息

### 3.3 核心方法

- **saveImageToServer()**：上传图片到服务器
- **callVisionModel()**：调用视觉模型生成描述
- **callVisionModelOptimize()**：调用视觉模型优化描述
- **callEmbeddingModel()**：调用嵌入模型生成向量
- **readExistingKnowledge()**：从服务器读取现有知识库
- **saveKnowledgeFile()**：保存知识库文件到服务器
- **processImage()**：处理单张图片
- **scanImageDir()**：扫描图片目录

## 4. 工作流程

1. **初始化**：解析配置，显示系统信息
2. **服务器测试**：测试与服务器的连接
3. **知识库读取**：从服务器读取现有的知识库文件
4. **图片扫描**：扫描指定目录中的图片文件
5. **图片处理**：
   - 上传图片到服务器
   - 检查是否已有记录
   - 调用视觉模型生成或优化描述
   - 调用嵌入模型生成向量
   - 构建历史消息
6. **知识库更新**：将处理结果保存到服务器
7. **统计分析**：显示处理结果统计信息

## 5. 使用方法

### 5.1 基本用法

```bash
# 使用默认图片目录（../../meme-images）
./sticker.exe

# 指定自定义图片目录
./sticker.exe ./my-meme-folder

# 使用绝对路径指定图片目录
./sticker.exe D:\path\to\memes
```

### 5.2 操作流程

1. **准备图片**：将需要处理的表情包图片放置在指定目录中
2. **启动服务器**：确保 Lunar Astral Agents 主服务器已启动并运行在默认端口
3. **执行命令**：运行 sticker 工具，指定图片目录（可选）
4. **等待处理**：工具会自动处理每张图片，显示详细的处理过程
5. **查看结果**：处理完成后，查看统计信息和处理结果
6. **使用知识库**：更新后的知识库会被主系统用于表情包的识别和响应

## 6. 支持的图片格式

- **.jpg**、**.jpeg**：JPEG 图片格式
- **.png**：PNG 图片格式
- **.gif**：GIF 动画格式
- **.bmp**：BMP 图片格式
- **.webp**：WebP 图片格式

## 7. 处理模式

### 7.1 新增模式

当处理新图片时：
1. 上传图片到服务器
2. 调用视觉模型生成描述标签
3. 调用嵌入模型生成向量表示
4. 创建新的历史消息记录
5. 添加到知识库中

### 7.2 优化更新模式

当处理已有记录的图片时：
1. 上传图片到服务器
2. 调用视觉模型生成新的描述标签
3. 结合新旧描述，调用视觉模型生成优化描述
4. 调用嵌入模型生成向量表示
5. 更新现有的历史消息记录
6. 保存到知识库中

## 8. 依赖关系

- **Lunar Astral Agents 主服务器**：提供模型推理和文件存储服务
- **多模态模型**：用于生成图片描述
- **嵌入模型**：用于生成文本向量
- **Go语言**：开发语言，需要Go环境编译
- **HTTP客户端**：用于与服务器通信

## 9. 注意事项

- **服务器连接**：确保主服务器已启动并运行在默认端口（36789）
- **图片目录**：确保指定的图片目录存在且包含支持的图片文件
- **模型可用性**：确保多模态模型和嵌入模型已正确配置并可用
- **网络连接**：处理过程需要与服务器进行多次通信，确保网络连接稳定
- **处理时间**：处理大量图片时，可能需要较长时间，取决于图片数量和服务器性能

## 10. 统计信息

处理完成后，工具会显示详细的统计信息：

- **总图片数**：扫描到的图片总数
- **成功处理**：成功处理的图片数量
- **处理失败**：处理失败的图片数量
- **新增记录**：新增的知识库记录数量
- **优化更新**：优化更新的知识库记录数量
- **总记录数**：知识库中的总记录数量

## 11. 故障排除

- **服务器连接失败**：检查主服务器是否已启动，端口是否正确
- **图片上传失败**：检查网络连接，确保服务器有足够的存储空间
- **模型调用失败**：检查模型是否已正确配置，服务器是否有足够的资源
- **知识库读取失败**：检查知识库文件路径是否正确，服务器是否有权限访问
- **知识库保存失败**：检查服务器是否有足够的存储空间，权限是否正确
- **图片扫描失败**：检查指定的图片目录是否存在，是否有读取权限

## 13. 性能考虑

- **处理速度**：每张图片需要多次模型调用，处理速度取决于服务器性能
- **内存使用**：处理大量图片时，需要存储历史消息和处理结果，可能使用较多内存
- **网络带宽**：需要上传图片到服务器，处理大量图片时需要足够的网络带宽
- **服务器负载**：同时处理大量图片会增加服务器负载，可能影响其他服务

## 14. 扩展建议

- **批量处理优化**：添加批量处理选项，减少服务器请求次数
- **并行处理**：支持多线程并行处理图片，提高处理速度
- **图片预处理**：添加图片预处理功能，如调整大小、裁剪等
- **描述审核**：添加描述审核功能，过滤不合适的内容
- **模型选择**：支持用户选择不同的模型进行推理
- **本地处理**：添加本地模型处理选项，减少对服务器的依赖

## 15. 故障排除

- **服务器连接失败**：检查服务器是否启动，端口是否正确，防火墙是否阻止连接
- **图片上传失败**：检查图片文件是否损坏，服务器存储空间是否充足
- **模型调用失败**：检查模型是否已正确配置，服务器是否有足够的资源
- **知识库保存失败**：检查服务器权限，存储空间是否充足
- **处理速度慢**：减少同时处理的图片数量，或优化服务器性能

## 16. 安全考虑

- **系统密钥**：SystemKey 硬编码在代码中，建议在生产环境中使用环境变量或配置文件
- **HTTPS连接**：使用HTTPS连接服务器，确保通信安全
- **图片内容**：处理的图片内容应符合相关法律法规，避免处理不合适的内容
- **服务器认证**：确保服务器有适当的认证机制，防止未授权访问
