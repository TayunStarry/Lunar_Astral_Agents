## 一、这是什么

句柄系统是星月智能给每一份资料发放的「长期身份证」。无论是源码、文档、表格、图片、动图、视频、音频，还是网页链接，只要进入过对话，就会得到一个形如 `@D.003`、`@I.007` 的短编号；之后你可以用它反复指代这份资料，而不用重新上传。

句柄只记「这是哪一份资料」，资料原文由内容仓库单独保存。因此同一份资料只存一份、序号永不复用，程序重启后旧句柄依然指向同一份内容。

### 句柄文法

```
@<类型码>.<序号>[|锚点]
```

| 类型码 | 含义 | 示例 |
|--------|------|------|
| `@D` | 文档（源码 / Markdown / 纯文本 / 配置 / 表格） | `@D.003` |
| `@I` | 图片 | `@I.007` |
| `@G` | 动图（GIF / APNG / 动态 WebP） | `@G.002` |
| `@V` | 视频（历史句柄，仅保证旧资料可读） | `@V.001` |
| `@A` | 音频（只保留转写描述，不落盘） | `@A.004` |
| `@U` | 链接（网页 / 网络视频 / BV 号，记地址与缓存摘要） | `@U.006` |

可选锚点用于精确到段落或行：

| 锚点 | 含义 | 示例 |
|------|------|------|
| `\|§n` | 第 n 节（按文档标题结构编号） | `@D.003\|§4` |
| `\|L起-止` | 第 起 至 止 行（从 1 开始，含两端） | `@D.003\|L120-168` |

序号不足三位补零（`@D.003`），超过 999 后自然变为四位。

## 二、核心用途

- **长期引用**：一次收录、反复提问，不必重复上传大文件。
- **精确检索**：能直接定位到某份文档的某一节或某几行，避免整篇塞进上下文。
- **统一管理**：文本、图片、动图、音频、链接共用同一套编号，方便记忆与转述。
- **节省成本**：大文件只注入「资源卡片」，需要细节时再按需读取。

## 三、使用方法

### 3.1 让资料进入句柄体系

| 资料类型 | 你的操作 | 系统行为 |
|----------|----------|----------|
| 文本文件 / 代码 / 表格 | 在上传区选择或拖入文件 | 收录并建立章节结构，回执 `[已收录] @D.003 文件名.md` |
| 工作区文件 | 在消息里写 `@相对路径/文件名.ext` | 按需收录，原文件只读保留，不移动不删除 |
| 图片 | 直接发送图片 | 登记为 `@I.00x`，在图片旁附句柄 |
| 动图 | 发送 GIF / APNG / 动态 WebP | 登记为 `@G.00x`，按抽帧管线下理解后附描述 |
| 视频 | 发送视频，或由 QQ 等渠道转入 | 登记为 `@U.00x`（视频按链接资源记录），正文替换为「句柄 + 文件名」 |
| B 站视频 / BV 号 | 消息里出现 B 站地址或 BV 号 | 复用或新建 `@U.00x`，首次出现时自动生成视频印象 |
| 网页链接 | 消息里出现网址 | 复用或新建 `@U.00x`，首次出现时自动生成页面摘要 |
| 音频 / 语音 | 发送语音或音频 | **不保存原文件**，接入时即转写，登记为带描述的 `@A.00x` |
| 工具产出 | 截图、绘图、超分结果 | 登记为对应类型句柄，可继续被引用 |

按文件名直接引用时：

- 只支持文本类扩展名，单个文件不超过 100MB。
- 同一路径重复引用复用同一句柄；同名不同路径互不干扰（用 `@sub/build.ps1` 这类前缀区分）。
- 文件内容改动后再次引用会生成新句柄。

### 3.2 在对话中使用句柄

1. **点击引用**：点击消息里资源图标旁的按钮，句柄会载入输入框上方，随后写下你的问题即可。
2. **直接书写**：也可以手写句柄，例如 `@D.003|§4 这一节讲了什么？`、`@I.007 改成雪景`。
3. **组合提问**：可同时引用多份资料，系统会分别读取后再回答。
4. **引用消息**：消息悬浮操作条上的「引用」可选中最多 5 条历史消息一并带入上下文。
5. **移除引用**：在输入框上方的图标条里点掉不需要的句柄。

### 3.3 让 AI 帮你查阅资源

- **列出资料**：让月华「看看有哪些资料」或「只看图片」，会返回句柄、类型与描述。
- **按关键词找**：会定位到「哪份资料的哪一节」，再取正文。
- **看文档大纲**：返回每节的锚点、行区间与字数，便于精确引用。
- **取正文**：按句柄取回完整段落；图片/动图/视频返回内容描述，音频返回转写，链接返回地址与摘要。

引用时正文注入分三档：

| 资料情况 | 行为 |
|----------|------|
| 小文件（≤6000 字符且无标题结构） | 收录后自动注入全文 |
| 有标题结构的文档 | 按问题筛出最相关的若干节（预算 12000 字符），每节带锚点 |
| 大文件（超预算，或无结构且 >6000 字符） | 只注入资源卡片（标题、体积、节数、摘要），正文按需读取 |

### 3.4 用图片作绘图参考

1. 在含图消息里说明绘图意图，例如「把 `@I.003` 改成雪景」。
2. 系统把该图片准备为本次创作的参考图，交给绘制者做图生图。
3. 参考图是任务级状态：每次创作开工时重新绑定，不会沿用上一次的图。
4. 输出尺寸随参考图比例自动推导。

图生图强度可按目标选择：

| 目标 | 建议强度 |
|------|----------|
| 只改画风 / 光影 | 0.2 ~ 0.4 |
| 换服饰配色 | 0.4 ~ 0.6 |
| 换背景 / 地点 | 0.8 ~ 0.9（常用 0.85） |
| 0.95 以上 | 会重排人物姿态，谨慎使用 |

### 3.5 图片超分

让月华对某张图片「放大 / 超分」，或直接点选最近作品，即可按句柄执行 4 倍超分辨率重建。

## 四、功能特性

| 特性 | 说明 |
|------|------|
| 统一编号 | 六类资料共用 `@类型码.序号`，可带章节或行区间锚点 |
| 序号不复用 | 收录时分配，程序重启后从资源名录重建计数 |
| 内容去重 | 相同内容无论来源只保留一份 |
| 文档结构 | 按标题层级建立章节与行区间，引用时整段取回，不会半句截断 |
| 源文件保护 | 一律只读收录，绝不移动或删除来源文件 |
| 本体回收 | 按配额与保留等级回收原文；只回收副本，失效句柄同步移除 |
| 派生缓存不占句柄 | 视觉读取副本、视频解读切片属于可重建的中间产物，不进入资源名录 |
| 图片可见性 | 模型能看到最近 20 张图片本身，更早的只以文字描述呈现 |
| 失效句柄清理 | 源文件丢失或损坏的句柄，在读取、列表、大纲任一入口被触碰时即移除 |

## 五、运行参数

句柄本身无需配置，与资源归档相关的参数如下。

| 参数 | 说明 | 默认值 | 建议 |
|------|------|--------|------|
| `-archive-db` | 统一句柄库文件（句柄映射、元数据、段落结构、缓存） | `local_data/database/handles.db` | 一般无需修改 |
| `-archive-quota-mb` | 内容仓库容量上限（MB），超限按「保留等级 → 最久未用」回收 | `2048` | 磁盘紧张时下调；回收后句柄仍可解析 |
| `-archive-max-blob-mb` | 单份资料入仓体积上限（MB） | `20` | 大文件较多时上调 |
| `-archive-gc-interval-min` | 自动回收周期（分钟），`0` 表示关闭 | `30` | 磁盘紧张时缩短 |
| `agent.vision_max_side` | 视觉读取副本的最大边长（像素） | `1024` | 需要更清晰理解时上调 |
| `agent.vision_cache_cap_mb` | 视觉副本缓存池上限（MB），超限按最久未用淘汰 | `512` | 磁盘紧张时下调 |
| `agent.image_input` | 图片送入模型的形式：`url` 视觉读取端点 / `base64` 内联副本 | `url` | 本地模型保持 `url` |

内容仓库目录结构（`local_data/` 下）：

| 目录 | 内容 |
|------|------|
| `documents/` | 文档类原文 |
| `multimedia/` | 图片、动图、视频、背景图、图标 |
| `multimedia/memory/<分组>/` | 记忆库图片（与普通图片隔离） |
| `audios/` | 音频实体 |
| `unknown/` | 不可读二进制（zip / 7z / exe / gguf 等） |

## 六、常见问题

| 现象 | 可能原因 | 处理办法 |
|------|----------|----------|
| 句柄取不到内容 | 句柄序号不存在，或资料已被显式删除 | 先让 AI 列出可用句柄，不要手写编号 |
| 提示「本体已回收」 | 原文已被内容仓库按配额回收，仅剩名录与描述 | 句柄仍有效，可按描述使用；需要原文件请重新发送或上调配额 |
| 文档引用只回了摘要与大纲 | 同上：正文已回收 | 上调 `-archive-quota-mb`，或重新发送该文件 |
| 文档只回了开头几段 | 与你问题相关的段落未命中 | 把问题写得更贴近文档用词，或先看大纲再用 `\|§n` 定向引用 |
| 写 `@文件名` 后 AI 没读到 | 名录无记录，且工作区与数据目录都没有该文件 | 确认路径相对项目根书写，确认扩展名属文本类 |
| 名录里出现多条同名资料 | 同名但路径不同的两个文件（预期行为） | 引用时带上目录前缀 |
| 图片不显示 | 原图已失效，或已超出最近 20 张的可见窗口 | 重新发送图片获取新句柄 |
| 导入文件后原文件不见了 | 早期版本缺陷（会把来源文件移入仓库） | 升级后不再发生；若确认丢失，检查 `local_data/multimedia/` |
| 动态图不能播放 | 动图按静态帧理解，窗口内不做动画播放 | 属预期行为；需要逐帧理解请发送视频 |
