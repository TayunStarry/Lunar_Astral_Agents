## 1. 环境要求

- **运行时**：Windows 10 21H2+（64 位），WebView2 Runtime（Win11 预装），可选 NVIDIA CUDA / FFmpeg / Vulkan。
- **构建**：Go 1.24+、Node.js + npm（TypeScript 编译）、GCC（MinGW-w64/TDM-GCC，CGO 模块）、rsrc（`go install github.com/akavel/rsrc@latest`）、CMake（qwen3_tts C++ 阶段）。

---

## 2. 一键构建

```powershell
# 统一构建脚本（位于仓库根，构建全部发行产物）
cd d:\Lunar_Astral_Agents
.\build.ps1                # 可选 -TargetOS windows|linux|darwin -TargetArch amd64|arm64
```

`build.ps1` 依次调用各子构建脚本：`core_personality`（核心人格：月华 + 琉璃合并工程）→ `ltp9_keygen`（LTP9 密钥生成器）→ `update_applier`（更新器）。共享的 Go 探测逻辑位于 `subsystem/build_common.ps1`（`Find-Go` / `Resolve-Go`）。

---

## 3. 单独编译

```powershell
# 核心人格（月华 + 琉璃合并工程）：唯一的程序形态——控制台 TUI 版
#   内部依次：rsrc 图标 → 关闭运行中的主程序 → TTS 引擎库按需构建 →
#             TypeScript 打包（tsc + rollup → agentSystem.js）→ 端点文档生成 → CGO 编译
cd d:\Lunar_Astral_Agents\subsystem\core_personality
.\build.ps1                    # 可选 -WithTTS（强制重建引擎库）/ -SkipTTS

# LTP9 权限密钥生成器
cd d:\Lunar_Astral_Agents\subsystem\ltp9_keygen
.\build.ps1

# 更新器（含主程序的更新包经它覆盖并重启主程序）
cd d:\Lunar_Astral_Agents\subsystem\update_applier
.\build.ps1
```

各 `build.ps1` 均为自包含脚本，内部自动处理前置步骤（rsrc 图标、TS 编译、CGO 参数等）。构建脚本支持 `-TargetOS`（windows/linux/darwin）× `-TargetArch`（amd64/arm64）交叉编译参数；运行目标平台为 Windows。

> **单一形态**：程序只有控制台（TUI）版，没有独立的桌面版/无控制台版本，`main.go` 不带任何构建标签。
> 月华与琉璃是控制台代为打开的两个前端窗口（见 [13-控制台TUI系统](13-控制台TUI系统.md)），窗口全部关闭不退出程序。

## 4. 编译产物

产物统一输出到项目根 `d:\Lunar_Astral_Agents\`：

| 文件 | 说明 |
|------|------|
| `Lunar_Astral_Agents.exe` | 核心人格主程序（控制台 TUI；月华 + 琉璃 + 运维功能合并工程） |
| `Lunar_Update_Applier.exe` | 更新器：更新包含主程序时被主程序拉起，等待文件占用释放后解压覆盖并重启 |
| `subsystem/LTP9Keygen.exe` | LTP9 权限密钥生成器 |

运行期旁挂产物：`local_data/models/Qwen3-TTS/qwen3tts.dll`、`local_data/models/OmniVoice/omnivoice.dll`（TTS 引擎库，运行时动态加载）；月华智能体脚本 `agentSystem.js` 经 Go embed 内嵌于主程序，不单独分发。

---

## 5. 运行模式

```powershell
.\Lunar_Astral_Agents.exe              # 直接运行：全屏控制台 + 自动打开月华/琉璃前端窗口
.\Lunar_Astral_Agents.exe -developer   # 开发模式（日志不限流）
.\Lunar_Astral_Agents.exe -basic-port 36800   # 指定基础端口
```

月华默认端口 `36789`；llama-server 使用 `ModelPort`（36790）；琉璃固定端点 `EnginePort`（36792）。控制台内以 `z` / `Ctrl+C` 退出，退出时优雅关闭全部子系统。

## 6. 双层配置架构

1. **命令行参数（flag）** —— 第一优先级（如 `-basic-port`、`-developer`）
2. **`local_data/lunar_config.json`** —— 按字段覆盖默认值（`server.developer` / `diffusion.allow_diffusion` 例外：文件存在时以文件值为准）

配置结构详见 [04-公共子系统 §4.1](04-公共子系统.md)。

### lunar_config.json 关键分组

| 分组 | 字段 | 说明 |
|------|------|------|
| `models` | diffusion_model / variational_model / prompt_analysis_model / real_esrgan_model | 辅助/生成类**模型文件路径**（主模型服务分段在 `models.ini`） |
| `server` | developer / allow_lan / insecure_tls | 服务运行与调试（`allow_lan` 放开局域网绑定、`insecure_tls` 跳过插件网络 TLS 校验，未配置均保持安全默认） |
| `agent` | user_name / embedding_model/url/key / multimodal_model/url/key / video_input | 月华身份（用户显示名）、模型路由（默认走 `http://127.0.0.1:36789/v1`）与视频解读输入模式（`file` 默认 / `frames`，取值非法回退 `file`） |
| `memory` | embedding_model/url/key / multimodal_model/url/key | 记忆库模型路由，可独立指向其它服务 |
| `chat` | chat_vram_guard / chat_vram_guard_mib / chat_vram_guard_interval | 聊天显存守卫（仅月华 TS 读取）：可用显存不足时卸载本地模型释放 KV 缓存 |
| `diffusion` | allow_diffusion / image_vram_guard / image_vram_guard_mib / sd_offload_to_cpu / sd_te_on_cpu / sd_vae_tiling / sd_vae_tile_size / sd_vae_tile_overlap / sd_max_vram / sd_sampler / sd_scheduler / sd_flow_shift / sd_diffusion_fa / sd_steps / sd_image_size | 图像生成（sd.cpp）行为与资源策略。尺寸/步数/采样器/VAE 分片/显存预算的取值约定与调优方向见 [12-图像生成参数策略](12-图像生成参数策略.md) |
| `bridging` | bridging_type / bridging_path / bridging_token / bridging_users / bridging_group_keywords / bridging_group_trigger_probability | NapCat QQ 桥接（由月华 `bridging/napcat` 解析） |
| `tts` | engine / ref_audio / ref_text / voice / mix / speed / lang / instruct / seed / disable_postproc / idle_unload_minutes | 语音合成引擎选择与统一效果参数（各引擎共用字段，不支持的参数自动忽略） |
| `web_search` | save_screenshots / screenshot_dir / max_pages / max_results / results_scroll_captures / page_scroll_captures / summary_max_chars / max_run_seconds | 琉璃内置 Web-LTP 网络搜索智能体（见 [09 §5.4](09-LTPX协议-月华工具包.md)）：截图是否落盘与目录、进入结果页数上限（≤10）、结果页/单页滚动截图张数、单页摘要硬切断字符数（≤4096）、单次运行总时长软上限；每次运行热读取，字段缺失用默认值 |
| `client` | character_renderer / live2d_model | 前端角色渲染方式（`bedrock` 默认 / `live2d`），由前端页面直接读取 |
| `release` | gitee_owner / gitee_repo / gitee_token / include / exclude / exclude_dirs_with / backup_keep / program_files / restart_args / target_dir / package_dir | **Gitee Release 发布通道**（控制台「资源更新 管理」与「LTPX 应用市场」共用）：仓库信息只有一套，更新包与市场包在仓库内以「描述标记 + 附件名前缀」严格区分（见 [13 §13.4](13-控制台TUI系统.md)）。`gitee_token` 通常留空，发布时在控制台手动输入、不落盘 |

> 分组即职责边界：`models` 只放模型文件路径、`server` 只管服务运行，其余每组对应且仅对应一个功能域；只有一个字段的小节不再单列（视频解读模式并入 `agent.video_input`）。
> 各组的字段标签（供琉璃配置编辑器显示）维护在 `local_data/config_labels.json`。
>
> **旧节兼容**：`update_pack` / `ltpx_market`（已并入 `release`）与 `multimodal`（已并入 `agent`）仍可被读取，启动时会打印迁移提示；`tui` 节已随桌面版一并取消。出厂配置 [local_data/lunar_config.json](../../local_data/lunar_config.json) 已是新结构。

### 模型预设文件（models.ini）

`local_data/models/models.ini` 为 llama.cpp `--models-preset` 格式的多模型预设，由月华启动 llama-server 时传入。每个段即一个模型服务：

| 段 | 说明 |
|----|------|
| `[system-multimodal]` | 多模态模型（`model` / `mmproj`，可含 `ctx-size`、推测解码 `spec-type` / `model-draft` 等参数） |
| `[system-embedding]` | 嵌入模型（`model`，`embeddings = true`） |

段名与 `general_config` 的默认模型名（`system-multimodal` / `system-embedding`）对应。

---

## 7. 添加 / 切换模型

1. 将 GGUF 模型放入 `local_data/models/`。
2. 语言/嵌入模型：编辑 `local_data/models/models.ini` 对应段路径。
3. ASR/扩散等辅助模型：编辑 `lunar_config.json` 的 `models` 分组。
4. 重启程序生效。

---

Qwen_ASR 运行时环境变量（可选）：`PORT`（默认 36791）、`QWEN_VERBOSE`、`QWEN_BF16_CACHE_MB`（默认 1024）。
