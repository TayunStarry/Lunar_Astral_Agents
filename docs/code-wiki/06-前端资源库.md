> [🏠 手册门户](README.md) ｜ [◀ 上一模块](05-独立AI引擎与运维工具.md) ｜ [下一模块 ▶](07-依赖关系.md)

## 一、功能介绍

前端资源库是星月智能所有前端页面与面板（月华、琉璃及其承载的各类工作台、演示包、插件包）共用的本地资源底座：它集中存放页面所需的第三方依赖库（Markdown 渲染、图表、流程图、代码高亮、公式、二维码、图标、多媒体预览等），同时作为各类自定义 UI 模块与扩展包的统一落位目录。所有页面都只从这一处按需取用资源，因此页面既不必各自内嵌依赖，也不必联网下载，离线可用性与依赖版本一致性都得到保证。它解决的问题是：让每个前端页面以最低成本获得所需能力，而不必关心资源的来源与维护；并以统一的扩展包形态承载自研工具、演示与插件，使「新增一个工具页面」变成安装一个包的简单动作。

## 二、使用方法

### 页面如何按需引用共享资源

1. 页面在自身结构里声明所需能力：需要渲染 Markdown 就引入 marked，需要画图就引入 ECharts，只引入页面真正用到的库。
2. 资源统一经本地资源路径前缀 /file/read/package/ 获取，脚本按脚本引用、样式按样式引用分别接入。
3. 未使用的库一律不加载，避免全量注入拖慢页面加载速度。

### 如何安装 / 启用扩展包

1. 在琉璃的包管理与 LTPX 应用市场界面中浏览并安装扩展包，安装后包即落入本地资源目录。
2. 前端在加载时自动读取各包的元数据，据其声明的标识、标签与工具登记卡片与可用能力。
3. 声明了后台保活的包在关闭覆盖层后保留页面现场（输入内容、编辑状态）；普通包关闭后即释放，下次打开重新加载。

### 如何新增一个 UI 模块（面向使用者与创作者）

1. 在本地资源目录中新建一个以模块标识命名的目录，放入入口页面及其脚本、样式。
2. 编写元数据：声明模块标识、面板显示标题、图标、所属分支标签；若希望被月华调用，再声明对外工具的名称与说明。
3. 刷新（重新加载）琉璃前端，模块即以卡片形式出现在面板中，可像内置模块一样打开使用。

## 三、功能特性

### 标准依赖库（按能力划分）

| 能力 | 依赖库 |
|------|--------|
| Markdown 渲染 | marked.js |
| 数据图表 | ECharts |
| 流程图 / 时序图 | Mermaid |
| 代码高亮 | highlight.js（含 GitHub 主题样式） |
| 数学公式 | KaTeX（含自动渲染扩展与样式） |
| 二维码 | QRCode.js |
| 图标 | Font Awesome |
| 图片 / 音视频预览 | multimedia_preview（提供统一的预览模态与全局图片预览能力） |

### 自定义 UI 模块

| 模块 | 提供的能力 |
|------|-----------|
| 小说创作工作台 | AI 辅助小说创作（提示词、素材导入、段落审核、导出） |
| 图像生成工作台 | 文生图参数配置（正向 / 负向提示词） |
| 知识库工作台 | 结构化知识库的可视化查询 |
| 记忆库工作台 | 向量记忆库浏览与语义搜索 |
| 翻译工作台 | 多语言逐行对照与整段翻译 |
| 语音工作台 | 文本转语音前端（Qwen3-TTS / Kokoro） |
| 月岩引擎与基座 | Bedrock 风格实体渲染与物理模拟工作室 |
| 节点图工坊 | 自由拖放节点、四向端口连线、就地编辑文字的设计制作工具 |
| 引擎编排管理器 | LTP3 引擎节点可视化编排、LTP9 蓝图 / 节点测试工作台 |
| 文件管理器 | 本地文件的浏览与操作 |
| 检索类页面 | 天气 / 新闻搜索、必应网络检索 |
| 按键可视化 | 虚拟键盘按键实时可视化 |

### 扩展包体系

| 类别 | 说明 |
|------|------|
| 标准页面包 | 以「页面 + 元数据 + 工具定义」组织的协议基座包，经前端加载运行 |
| 自带智能体包 | 为特定应用定制指令理解与操作序列的专用页面智能体 |
| 通用 / 自主操作包 | 由宿主注入的通用页面操作智能体，与在页面内自循环的自主智能体 |
| 演示包 | 自包含的网页演示与游戏合集 |
| 插件包 | 运行在沙箱中的 LTP3 / LTP9 插件，事件驱动、权限强绑定 |
| 归档包 | 以压缩归档形式分发、可安装的扩展 |

## 四、运行参数

| 约定项 | 说明 | 建议 |
|--------|------|------|
| 本地路径前缀 | 共享资源统一经 /file/read/package/ 前缀提供，页面据此拼接资源名 | 统一使用该前缀，勿自造绝对路径 |
| 按需引用 | 页面只加载实际用到的库 | 引用越精简，页面越稳越快 |
| 扩展包启用 | 包以元数据声明身份与工具；声明了工具清单的包才能被月华调用 | 需要被月华调用时保持工具清单非空 |
| 后台保活 | 声明后台保活的包在关闭覆盖层后保留页面现场 | 需要保留输入 / 编辑状态时开启 |
| 资源缓存 | 内嵌前端资源统一按不使用缓存处理，改动一次刷新即可生效 | 修改页面后刷新，而非仅重开 |

资源加载的路径约定与扩展包安装、启用相关的具体设置项，参见 [08 安装、运行与配置](08-构建运行与配置.md)。

## 五、常见排故

| 现象 | 可能原因 | 处理办法 |
|------|----------|----------|
| 页面样式 / 脚本未加载（排版错乱、无交互） | 未声明对应库，或资源路径前缀拼写有误 | 确认页面已声明该能力、资源以统一前缀拼接；刷新重试 |
| 公式或图表不渲染 | 未按需引入对应库，或其样式 / 自动渲染扩展缺失 | 补引 KaTeX（含自动渲染）与样式、ECharts，并检查引用顺序 |
| 扩展包未生效 / 卡片缺失 | 元数据缺失或格式错误，或包未放入本地资源目录 | 核对元数据的标识、标题、标签字段；重装或放入后刷新前端 |
| 包打开后被智能体调用无响应 | 包未声明对外工具，或页面缺少接收执行指令的入口 | 确认包声明了工具清单，且页面能接收执行指令 |
| 改动前端后行为没变化 | 浏览器仍在运行旧页面 | 刷新页面一次即可（内嵌资源已按不使用缓存处理） |
