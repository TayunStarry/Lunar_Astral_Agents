## 6.1 standard_dependency —— 标准依赖库

所有页面的统一依赖入口，仅两行引用即获得全量第三方能力：

```html
<link rel="stylesheet" href="/file/read/package/standard_dependency/styles.css">
<script src="/file/read/package/standard_dependency/script.js"></script>
```

### script.js 注入的 7 个脚本（loadScriptDependencies）

| 库 | 路径 | 用途 |
|----|------|------|
| marked.min.js | `package/marked.min.js` | Markdown 渲染 |
| echarts.min.js | `package/echarts.min.js` | 数据图表 |
| highlight.min.js | `package/highlight/highlight.min.js` | 代码高亮 |
| qrcode.min.js | `package/qrcode.min.js` | 二维码 |
| katex.min.js | `package/katex/katex.min.js` | 数学公式 |
| auto-render.min.js | `package/katex/contrib/auto-render.min.js` | KaTeX 自动渲染 |
| multimedia_preview/script.js | `package/multimedia_preview/script.js` | 图片/音视频预览 |

### styles.css 引入的样式

Font Awesome 图标、highlight GitHub 主题、KaTeX、multimedia_preview 主题。

> `package/mermaid.min.js` 位于包根目录，未纳入标准注入列表，可按需单独引用。

## 6.3 lunar.engine_manager-ltp9 —— LTP9 可视化测试工作台

纯前端的 LTP9 引擎蓝图/节点式测试工具（`tags` 为 `Zero-LTP`，引擎不加载；琉璃前端在 iframe 中打开其 `index.html`）。

- **画布**：拖入节点，金线为时钟/执行链、灰虚线为数据信号；逻辑门 AND/OR/NOT/NAND/NOR；`start` / `event_start` / `clock_start` 入口；一键运行/停止。
- **节点能力映射引擎信封**：`ltp9/event`、`ltp9/broadcast`、`ltp9/call`、`ltp9/test`（action=agent|db|memory|file|crypto|jwt|llm|http），另有本地格式转换、sleep、三段音频均衡器、视频关键帧节点。
- **持久化**：画布保存到 `local_data/database/lunar.engine_manager_ltp9.graph.json`，启动时自动加载。
- **通信**：经 `websocket.js` 走主 `/ws` 总线。
- **结构**：`index.html` + `css/`（4 文件）+ `js/`（15 文件：core → node-types → utils → websocket → log → render → editor → modal → envelope → image-confusion → audio-equalizer → video-keyframe → execute → persistence → main）。

## 6.4 ws_bridge.js —— 统一通信客户端

包根目录的跨页面/iframe 通信客户端，API 与 BroadcastChannel 一致（`name` / `readyState` / `onmessage` / `postMessage` / `close`），暴露为全局 `window.WsBridge`。

- **接收**：连接同源 `/ws`，后端广播 `{type, data}`，客户端按频道名过滤；`onmessage` 未设置前缓冲入站消息。
- **发送**：`postMessage` 走 `HTTP POST /write/engine`，后端本地广播 + 转发智能体侧。
- **其它**：`?ws=host:port` 覆盖连接地址；自动重连（指数退避，最大 30s）。
- **使用方**：`lunar.rendering_engine` 与 `lunar.rendering_engine-studio`。

## 6.5 lunar.rendering_engine —— 月岩引擎物理渲染核心

面向 Minecraft Bedrock 风格实体渲染 + 物理模拟，是 `lunar.rendering_engine-studio` 工作室的引擎层。`engine.js` 为入口，初始化 `core/` 下 22 个模块：

| core/ 模块 | 职责 |
|------|------|
| `molang-runtime.js` | Bedrock MoLang 表达式解释器（token→AST→缓存编译），支持 q./v./t. 变量、数学函数 |
| `animation-runtime.js` / `anim-group-runtime.js` / `special-animation-runtime.js` | 动画/动画组播放运行时，按骨骼通道插值 |
| `controller-vm.js` / `controller-codec.js` | 动画控制器状态机虚拟机（转移条件 + on_entry/on_exit MoLang）与编解码 |
| `character-physics.js` | 角色竖直胶囊碰撞桥接（CANNON.Body Compound：圆柱 + 双球，落地检测） |
| `physics-manager.js` | cannon-es 物理世界（SAPBroadphase、固定逻辑步进） |
| `third-person-control.js` | 第三人称越肩操控：WASD 相对视角移动 / 跳跃 / 鼠标环绕转向 |
| `interpolator.js` / `keyframe.js` | 关键帧插值算法与数据结构 |
| `renderer.js` | Three.js 渲染器 |
| `geometry-loader.js` | Bedrock 坐标转换 + `index_geometry.json` 几何解析（约束 format_version ≥ 1.10） |
| `outliner.js` | 骨骼/立方体元素场景树 |
| `material-system.js` | Bedrock render method 材质 |
| `texture-manager.js` / `primitives.js` / `camera-controller.js` / `movement-controller.js` / `body-rotation-interpreter.js` / `animation-classifier.js` | 纹理、图元、相机、移动、朝向解释与动画分类 |

模型引用采用 Bedrock 运行时格式：`index_geometry.json`（几何）+ `index_texture.png`（纹理），约束模型 `format_version` ≥ 1.10。`vendor/`：`three.module.js` + `cannon-es.module.js`（本地）。`index.html` 通过 URL 参数 `?mode=editor`、`?channel=xxx`、`?model=` 配置嵌入模式与通信频道。

## 6.6 通信链路总结

```
lunar.rendering_engine-studio(基座) → iframe → lunar.rendering_engine(引擎) + panels
  → ws_bridge.js → /write/engine（发送）· /ws（接收）
lunar.engine_manager-ltp9 → websocket.js → /ws → ltp9/* 信封 → StarLTP 引擎
lunar.novel-studio → /v1/（模型代理）· /memory/（向量记忆）
standard_dependency → 所有页面的统一依赖入口
```
