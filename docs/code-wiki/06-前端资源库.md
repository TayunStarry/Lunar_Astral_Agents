## 6.4 ws_bridge.js —— 统一通信客户端

引擎/工作室的通信客户端，**替代浏览器 BroadcastChannel**，解决跨页面/跨 iframe 通信。API 与 BroadcastChannel 一致（`name` / `readyState` / `onmessage` / `postMessage` / `close`）。

- **接收**：连接同源 `/ws`，后端无差别广播 `{type,data}`，客户端按频道名过滤；`onmessage` 未设前缓冲入站消息。
- **发送**：`postMessage` 走 `HTTP POST /write/engine`，后端本地广播 + 转发智能体侧。
- **其它**：支持 `?ws=host:port` 覆盖连接地址；自动重连（指数退避，最大 30s）；暴露为全局 `window.WsBridge`。

## 6.5 simple_physics —— Molang 机器人物理引擎

面向 Minecraft Bedrock 风格实体渲染 + 物理模拟，是 `integrated` 工作室的引擎层。`engine.js` 为入口，初始化 15+ 核心模块。

| core/ 模块 | 职责 |
|------|------|
| `molang-runtime.js` | Bedrock MoLang 表达式最小化解释器（token→AST→缓存编译），支持 q./v./t. 变量、18 个数学函数 |
| `animation-runtime.js` | 动画播放运行时，按骨骼通道插值 |
| `controller-vm.js` | 动画控制器状态机虚拟机（转移条件 + on_entry/on_exit MoLang） |
| `character-physics.js` | 角色 AABB 物理桥接（CANNON.Body、落地检测） |
| `physics-manager.js` | cannon-es 物理世界（SAPBroadphase、120Hz 逻辑步进） |
| `interpolator.js` / `keyframe.js` | 关键帧插值算法与数据结构 |
| `renderer.js` | Three.js 渲染器（重写自 Blockbench，不依赖 DOM/Vue） |
| `geometry-loader.js` | BedrockCoordinate 坐标转换 + `.bbmodel` 几何加载 |
| `outliner.js` | 骨骼/立方体元素场景树 |
| `material-system.js` | 4 种 Bedrock render method 材质 |
| 其它 | `movement-controller.js` / `body-rotation-interpreter.js` / `animation-classifier.js` / `camera-controller.js` / `texture-manager.js` / `primitives.js` |

`vendor/`：`three.module.js` + `cannon-es.module.js`（本地）。`index.html` 通过 URL 参数 `?mode=editor`、`?channel=xxx`、`?model=` 配置嵌入模式与通信频道。

## 6.6 通信链路总结

```
integrated(基座) → iframe → simple_physics(引擎) + panels → ws_bridge.js → WebSocket /write/engine
engine → 独立美术向 3D 工坊（Three.js + cannon-es）
novel.pro → 深度集成向量记忆库 + 多级审核流水线
standard_dependency → 所有页面的统一依赖入口
```
