## 七条链

链只回答「什么时候、按什么顺序、调哪个智能体」，不自己拼提示词，也不自己解析模型流。

| 链 | 触发 | 内部角色 | 产物 |
|----|------|----------|------|
| 思维链 | 有新消息、需要应答 | 对话者、回应者、通讯桥接 | 回复、工具调用、会话状态 |
| 搜索链 | 对话调用检索、观影选片、生活需要资料 | 搜索规划、抓取执行体、搜索摘要 | 带来源的检索报告 |
| 观影链 | 生活抽中观影、对话指定视频 | 阅片、审查、观感、评论、分享 | 观后感、评论、分享、日记素材 |
| 生活链 | 对话空闲超过阈值、工具/命令强制事件 | 固定四步 + 四类权重事件 + 演绎强制子链路；创作事件直接调用文件操作智能体 | 愿望结算与提醒、心情/好感变化、生活经历、待整理记忆 |
| 演绎链 | 生活系统、`life_planning` 的 storyboard 分支、资源库演绎页 | 分镜资料、分镜拆解、图像绘制 | 分镜文档 + 一组图片 |
| 论坛链 | 生活论坛事件、对话要求 | 互助论坛智能体 | 论坛回答与后续互动 |
| 桌面链 | 控制台人工启动 | 七段桌面操纵角色 | 桌面操作结果与执行记录 |

几条容易混淆的边界：

- **观影不是独立 Tick。** 它是生活回合里的一个事件，由生活链按五步编排；没有生活节拍就不会自己开始。
- **愿望不是第九条链。** 愿望、心情与好感由 `chain/wishchain` 作为共享状态维护：生活链负责定期结算，思维链每轮读取，生活创作与观影在结果落地时回报。它没有自己的 Tick，也不参与事件抽签。
- **搜索没有独立 Tick。** 它由对话工具或生活事件同步触发，一次检索在时间预算内跑完。
- **论坛和桌面也不会自行循环。** 论坛由生活事件或对话触发；桌面只能人工启动，并且对话一开始就自动停止。

## 一套常驻节拍

### 单 Tick 调度器

所有需要「分步推进」的链注册在同一个调度器上，按优先级决定下一步推进谁：

| 优先级 | 系统 | 作用 |
|--------|------|------|
| 300 | 对话 | 处理未读消息、推进应答 |
| 280 | 后勤修复 | 上下文导出、故障修复等维护工作 |
| 260 | 外部应答 | 处理外部接口提交的推理请求 |
| 220 | 资源库创作 | 推进创作任务 |
| 200 | 演绎 | 推进分镜阶段 |
| 100 | 生活 | 固定四步与生活事件 |

调度器保证**同一条链不会并发推进**，避免两个步骤同时改同一份状态。演绎与生活的长步骤在后台执行：`Run` 立即返回，步骤结束前该系统不再就绪，调度器可以继续推进其它链和处理响应请求；所以一次几分钟的分镜规划不会把整个后端挡停。长任务依然可以暂停、恢复、取消。

### 特许响应车道

外部接口提交的推理请求没有独立循环，也没有自己的定时器。它们进入响应者队列后，由同一个调度器里的响应系统（优先级 260）在正常 Tick 中处理：主链空闲时，它和对话、生活等系统一起参与调度。主链长步骤（创作、分镜规划）执行期间，响应系统同样可以插入，外部请求不必等整条链结束。

特殊之处只发生在对话阻塞时。对话者调用 LTPX 工具后会一直等到包页面把结果回执回来，这段时间模型是空闲的。此时它开启一次**特许运行**，调度器在下一次 Tick 发现特许有效且主链仍忙，就只放行一个响应步骤，其他链一律不插队。工具返回后撤销特许，并做一次**有界等待**，也就是返回屏障：确认在途响应步骤已经结束，才让对话恢复模型调用，避免两条模型请求并发。

三条边界：

- 特许有 35 分钟有效期，超时由调度器强制回收，避免状态泄漏把系统卡死。
- 结束等待上限 60 秒；超时只记错误并继续，宁可少等一次也不反向卡死对话。
- 没有主步骤却仍有特许时，视为泄漏，Tick 直接回收。

### 谁决定下一步

- 对话链看未读队列：有消息就推进一轮应答。
- 生活链看空闲 Tick、优先级与每日配额：满足条件才抽事件。
- 创作与演绎看任务状态：运行中、待确认、已完成、已取消。
- 后勤修复看是否有待导出上下文或待修复故障。

没有就绪任务时，调度器空转，不调用模型。

## 智能体的四层

30 个智能体按职责分为四层。分层的目的不是好看，而是让失败有归属、工具目录可控、模型入口唯一。

### 第一层：入口与人格

| 智能体 | 职责 |
|--------|------|
| 对话者 | 组装人格与上下文，决定直接回答还是调用工具 |
| 回应者 | 处理外部接口的推理请求 |
| 通讯桥接 | 理解 QQ 投递需求，转成结构化发送指令 |

### 第二层：生活、记忆与内容

| 智能体 | 职责 |
|--------|------|
| 愿望管理 | 理解对话中的愿望增删改需求，转成结构化愿望操作 |
| 记忆整理 | 处理记忆待合并组，决定如何整理 |
| 记忆标签 | 为记忆生成检索标签 |
| 记忆融合 | 把一组相似记忆融合成一条 |
| 互助论坛 | 阅读问题、判断是否参与、起草回答 |
| 观影阅片 | 选片、切片、形成整体印象 |
| 观影审查 | 判断内容风险与是否适合互动 |
| 观影观感 | 把片段理解转成第一人称观后感 |
| 观影评论 | 发表评论、处理评论区互动 |
| 观影分享 | 决定是否分享并组织文案 |

### 第三层：技法与执行

| 智能体 | 职责 |
|--------|------|
| 图像绘制 | 组装提示词与参考图，调用图像生成引擎 |
| 音乐演奏 | 按乐理生成 MIDI 事件并渲染音频 |
| 屏幕截图 | 自动、窗口、全屏、显示器、区域截图 |
| 文件操作 | 拆解文件任务并派发四个原子子智能体 |
| 文件操纵 | 按行替换、追加、删除、创建空白文件、删除文件 |
| 归档操纵 | 创建、删除、列出、提取、追加归档条目 |
| 代码执行 | 运行 HTML/JavaScript、解析函数与依赖 |
| 内容回滚 | 列出历史版本、回滚到指定版本 |
| 文献解析 | 读文档、按章节定向抽取 |
| 视觉理解 | 图片与动图内容理解 |
| 音频转写 | 语音与音频转文字 |
| 语句生成 | 把自然语言问题转成只读 SQL |
| 分镜资料 | 查角色、场景、时代背景与视觉参考 |
| 分镜拆解 | 把故事拆成镜头、画面描述与台词 |

### 第四层：诊断与高风险

| 智能体 | 职责 |
|--------|------|
| 故障诊断 | 在其他智能体失败后修复状态、导出上下文 |
| 桌面操纵 | 七段角色接力，控制真实键鼠 |

搜索规划与搜索摘要属于第二层的外部信息能力，分别负责路由决策与摘要提取；它们与抓取执行体一起构成搜索链，不单独出现在对话工具目录里。

## 唯一模型入口

模型推理只允许发生在推理基座里。基座统一负责请求组装、流式解析、工具调用分片聚合、超时、重试、推理实况与失败上报。

这条边界带来三个直接结果：

- **链里没有提示词拼接与流式解析。** 链只把上下文整理成智能体的入参，再把智能体的结果映射回链内状态。
- **引擎不直接调用智能体。** 记忆标签、记忆融合、语音转写这类引擎需要模型能力的地方，只声明函数钩子，由装配层注入智能体方法。
- **服务端只做透传。** 对话接口把请求入队给对话者，不在 handler 里拼模型请求。

只有三类能力不走对话协议，因此留在引擎侧：文本嵌入、token 级补全（用于音乐）、本地扩散出图。它们的输出不是文本或工具调用，封装成智能体不会带来推理实况收益。

## 工具注册与调用

工具目录不是写死在链里的，而是由智能体自己声明：

1. 智能体在自己的工具目录里注册工具名、说明与执行函数。
2. 对外暴露的目录从注册表派生，新增工具不需要改链。
3. 装配层把「角色 → 智能体 ID」和「工具目录」登记到控制台，推理实况才能显示是谁、用了什么工具。
4. 复合工具负责把自然语言子任务分派给具体智能体；模型只选大类，不需要记住每个内部工具名。

几个硬边界：

- 链不得硬编码工具目录，也不得绕过注册表直接调用工具。
- 新增模型能力必须先有智能体，再由链调用；不能把提示词塞进链里「临时调一次」。
- 新增工具型智能体必须同时登记角色映射与工具目录，否则控制台看不到、故障也修不到正确目标。

## 推理实况与故障诊断

### 推理实况

每次模型调用都会出现在推理实况里：哪个智能体、什么角色、调用了哪些工具、是否在重试、是否被中断。实况是展示层，不参与业务状态；关掉它不会影响对话，但会让故障定位变难。

### 故障归属

失败按「角色 → 智能体 ID」归属。链只上报「哪一步失败」，修复层根据角色映射找到具体智能体，导出它的提示词、上下文与最近运行记录，再决定如何修。

### 上下文导出与修复

- **导出**：把指定智能体的系统提示词、工具目录、最近消息与失败信息写成可读文件，便于人工检查或交给诊断智能体。
- **修复**：只在该智能体已经出错之后进行状态修复，不做事前拦截，也不改写策略。
- **边界**：诊断智能体不能替其他智能体「预防性」拒绝调用；重复调用本身不是错误，只有检测到循环输出或超出额度才允许中断。

### 对话时间线

对话状态以事件时间线记录，关键节点做快照。这样在上下文损坏、进程重启或修复回滚时，可以恢复到最近一个一致状态，而不是从零开始。

## 循环输出监管

模型可能陷入两种循环：同一段文字反复生成，或反复调用同一个工具。系统分别处理：

| 循环 | 检测 | 处理 |
|------|------|------|
| 文本重复 | 连续片段高度重复 | 中断本轮，标记循环，必要时重试一次；仍重复则上报失败 |
| 工具循环 | 工具轮次达到上限 | 停止执行工具，用一轮无工具请求收尾，说明未完成部分 |
| 链空转 | 连续多个节拍没有状态变化 | 生活事件自然结束；创作/演绎标记停滞并等待重试或取消 |
| 外部等待 | 工具调用长时间无回执 | 超时返回失败，不无限挂起 |

监管的目标是「止损」，不是「替模型做决定」。它只中断明显失控的循环，不因为重复调用就提前拦截正常工具使用。

## 失败与降级

| 失败 | 归属 | 处理 |
|------|------|------|
| 模型超时/连接失败 | 对应智能体 | 重试有限次数，仍失败则上报并结束该步 |
| 工具执行失败 | 工具所属智能体 | 错误回填给模型，由模型解释、重试或换工具 |
| 链阶段失败 | 链 | 保留已完成步骤与过程记录，允许从断点继续或取消 |
| 上下文损坏 | 思维链 | 从事件时间线恢复到最近快照 |
| 智能体反复出错 | 故障诊断 | 导出上下文、修复状态；修复本身失败则停止并报告 |
| Tick 长时间无进展 | 调度器 | 标记停滞，等待下一次就绪或人工取消 |
| 服务重启 | 全局 | 从持久化状态恢复；能还原现场的从原阶段继续，无法还原的标记中断并说明原因 |

底层原则是：**一个智能体失败不等于整条链失败；一条链失败不等于整个系统失败。** 能续跑的续跑，能降级的降级，不能继续的明确报告。
