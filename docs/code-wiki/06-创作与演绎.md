## 创作能力的共同骨架

绘画、音乐、演绎、自由创作看起来是四种能力，内部都遵循同一条骨架：

1. **需求进入**：一句话、一个故事、一组参考图，或一个已批准的计划。
2. **规划**：确定产物类型、风格、步骤和需要的资料；复杂任务先出计划，简单任务直接执行。
3. **取材**：从资源库、记忆、参考图或现场检索里取素材；取不到时明确降级，而不是编造。
4. **执行**：交给对应技法智能体或执行者；长任务按阶段推进，过程可观察。
5. **验收**：检查产物是否完整、是否满足约束；演绎和自由创作还会有人工确认点。
6. **归档**：产物登记为句柄，写入对应资源目录，需要时进入记忆或对话。

差别主要在「谁执行」和「有没有人工确认点」，而不是四套互不相干的流程。

## 绘画

### 触发

- 对话中调用技法创作的绘画分支。
- 生活里的创作事件发起绘画任务。
- 演绎链在分镜阶段批量生图。

### 参与者

- **人格对话**：判断要不要画、抽取主题与风格，把需求整理成绘画入参。
- **图像绘制**：真正调用图像生成引擎的智能体，负责组装提示词、参考图与参数。
- **资源体系**：把参考图与成图登记为句柄。

### 数据怎么流动

1. 需求先变成一段可执行的画面描述，而不是原样丢给模型。
2. 参考图最多三张，按顺序传给生成引擎；可选是否把参考图也作为画面内容。
3. 选择比例：16:9、4:3、1:1、9:16、3:4。
4. 选择风格开关：开启后追加固定的风格提示词；关闭则只用你的描述。
5. 生成引擎出图，结果登记为 `@I` 句柄。
6. 需要时追加 4 倍超分，超分结果作为新的图片句柄，不覆盖原图。

### 失败与降级

- 生成引擎不可用：明确告知失败原因，不返回空白图或旧图。
- 参考图无法读取：跳过该参考图并说明，而不是让整次绘制失败。
- 超分失败：保留原图，提示超分未完成。
- 内容被安全策略拦截：返回拦截原因，不重试绕过。

## 音乐

音乐不是「生成一段音频」，而是让模型按乐理逐 token 写出一段可演奏的 MIDI：

1. **定结构**：先确定曲式、调性、拍速、段落与情绪。
2. **写事件**：按时间顺序生成音符、时值、力度与乐器事件。
3. **合成**：把事件交给本地音源渲染成音频。
4. **归档**：音频登记为 `@A`，同时保留可再次演奏的结构信息。

这样做的结果是：同一首曲子可以改段落、换音色、重新演奏，而不是只能得到一段不可编辑的波形。音乐能力由「音乐演奏」智能体承担，对话中通过技法创作的音乐分支触发；生活里的创作事件也可能产出音乐。

失败时优先保留已生成的结构，音频渲染失败只影响试听，不会让整首曲子丢失。

## 演绎：从故事到分镜

「演绎」面向的是「把一段故事变成一组可看的画面与分镜文档」，不是直接生成视频。它是一条有七个阶段的链：

| 阶段 | 在做什么 | 谁参与 | 是否停顿 |
|------|----------|--------|----------|
| 资料研究 | 查角色、场景、时代背景与视觉参考 | 分镜规划-资料 | 否 |
| 分镜拆解 | 把故事拆成镜头，写画面描述与台词 | 分镜规划-拆解 | 否 |
| 人工审阅 | 你修改镜头、增删场次、调整描述 | 你 + 前端 | **是** |
| 分镜修订 | 按你的修改重写受影响镜头 | 分镜规划-修订 | 否 |
| 批量绘制 | 按最终分镜逐镜生图 | 图像绘制 | 否 |
| 文档撰写 | 把分镜、画面、说明整理成文档 | 分镜规划-修订 | 否 |
| 完成 | 文档与图片归档，可继续编辑 | 资源体系 | 否 |

### 为什么中间要停

分镜拆解完成后，链会暂停并等待你确认。原因是：分镜一旦进入批量绘制，成本远高于改文字。让你在文字阶段改镜头、改台词、改画面描述，比生成几十张不满意的图再重来便宜得多。

审阅阶段支持：

- 修改单个镜头的画面描述、台词、时长与备注。
- 增删镜头或调整顺序。
- 暂停与取消；取消会保留已完成的过程记录，但不再继续后续阶段。
- 继续后只重算受影响的镜头，不整批重来。

### 产物

最终产出是一份分镜文档加一组图片句柄，存放在资源库的演绎目录。文档可以继续被引用、编辑或作为下一次创作的输入。

## 自由创作：规划与执行

自由创作处理的是「没有现成表单」的任务：写一篇东西、做一个小工具、整理一份资料、完成一个多步骤的整活计划。

### 规划

「创作调度」先判断任务类型，再从计划目录里选一条合适的计划。计划可能只有一步，也可能包含多个阶段；每个阶段声明要找谁、产出什么、如何验收。生活发起的自由创作会直接参考当前愿望清单，心情偏正向时更容易沿用旧思路；产物命中愿望时自动完成，整体失败只产生类似逾期的失望联动。

### 执行

计划里的步骤分派给不同执行者：

| 执行者 | 负责 |
|--------|------|
| 创作调度 | 拆计划、分派、汇总、验收 |
| 文献解析 | 查资料、读文档、整理事实 |
| 图像绘制 | 需要配图时生图 |
| 音乐演奏 | 需要配乐时演奏 |
| 文件编辑 | 写文件、改文件、运行项目内脚本 |

执行过程会留下过程记录：每一步做了什么、产出了哪个句柄、失败在哪里。这样长任务中断后可以从中断点继续，而不是从头再来。

### 验收

不是「文件写出来了就算完成」。验收会检查：

- 产物是否存在、能否打开。
- 是否满足计划里声明的约束（数量、格式、章节、引用）。
- 需要配图/配乐时，对应产物是否齐全。
- 失败步骤是否已经重试或明确放弃。

验收不通过时，创作调度可以选择补做、换执行者或把未完成部分报告给你，而不是把半成品当成完成品。

验收通过的作品会回报给心愿系统：与待处理愿望匹配上的自动完成，并轻推心情。规则见 [心愿清单](./03-生活与情绪.md#心愿清单)。

## 作品去哪里

| 产物 | 归档位置 | 句柄类型 |
|------|----------|----------|
| 绘画、截图、超分图 | 资源库图片目录 | `@I` |
| 音乐、语音 | 资源库音乐/音频目录 | `@A` |
| 演绎分镜与说明文档 | 资源库演绎目录 | `@D` |
| 自由创作文档、代码、资料 | 资源库创作目录 | `@D` |

归档后的作品和普通资料没有区别：可以被对话引用、被资源中枢检索、被下一次创作当素材，也可以被删除或回收。作品不会因为「是 AI 做的」而被特殊对待。

## 中断、失败与重试

| 情况 | 表现 | 处理 |
|------|------|------|
| 用户取消 | 任务停在当前阶段 | 保留已完成产物与过程记录，后续可重新发起 |
| 服务重启 | 长任务中断 | 从已保存的阶段继续；未落盘的中间结果需要重做 |
| 单个镜头绘制失败 | 分镜文档缺一张图 | 标记该镜头失败，可单独重试，不阻塞其他镜头 |
| 资料研究失败 | 分镜缺少背景依据 | 降级为基于现有描述的拆解，并标注资料不足 |
| 计划步骤失败 | 自由创作卡住 | 重试、换执行者或报告未完成部分，不伪造产物 |
| 验收不通过 | 产物存在但不合格 | 补做或明确报告缺口，不把半成品归档为完成 |

创作系统的原则是：**过程可观察、产物可追溯、失败可续跑**。长任务允许停，但不允许悄悄丢。
