## 1. Go Module 依赖图

各 Go 模块通过 `go.mod` 的 `replace` 指令引用 `subsystem/` 下的同级目录，共享 `GeneralConfig` 与 `LoggerGeneral`。

```
lunar_astral ──→ GeneralConfig, BrowserClient, FileManager, MultimodalAnalysis,
                 LoggerGeneral, Qwen3-TTS, LunarGoja, MediaTools

crystal_astral ─→ GeneralConfig, BrowserClient, FileManager, MultimodalAnalysis,
                  LoggerGeneral, MediaTools
                  ├── 内置引擎: agent/AutoLTP, agent/WebLTP, agent/StarLTP (LTP9),
                  │            agent/YaraLTP (LTP3), kokoro_tts (ONNX), qwen_asr (cgo)
                  └── bridge_probe 为独立调试程序，无宿主

agent_search ───→ FileManager, GeneralConfig, LoggerGeneral   （独立子系统，暂无宿主接入）
qwen3_tts ──────→ GeneralConfig, LoggerGeneral
qwen_asr ───────→ BrowserClient, GeneralConfig, LoggerGeneral
environment_repair → GeneralConfig
media_tools ────→ GeneralConfig, LoggerGeneral
lunar_goja ─────→ GeneralConfig（goja 运行时环境）
lunar_decoder ──→（零内部依赖）
file_manager ───→ GeneralConfig, LoggerGeneral        (基础)
browser_client ─→ GeneralConfig
ltp3_keygen / ltp9_keygen → GeneralConfig, BrowserClient, LoggerGeneral
LTP9-StarLTP ───→ GeneralConfig, FileManager, LoggerGeneral, LunarDecoder（独立发布副本，仓库内程序未引用）
```

> `logger_general`、`general_config`、`lunar_decoder` 为零外部依赖根节点，被全项目复用。

## 5. WebSocket 消息链路

```
月华后端 → BroadcastMessage → bridgeToQQ(NapCat) + 所有在线 WS 客户端
         （context / image / engine 等类型）

琉璃 /ws (StudioHub) ← 前端面板与包页面
  ├── {type:"engine"} 引擎命令广播
  ├── ltpx_call / ltpx_result / ltpx_run（页面智能体 AtoA）
  ├── ltp3/hook|event|command|manage|ping（YaraLTP 信封）
  └── ltp9/event|call|tool|stats|broadcast|probe|test（StarLTP 信封）
```

## 6. 静态资源加载约定

- 前端资源一律通过 `/file/read/package/` 加载。
- 标准依赖：`/file/read/package/standard_dependency/{script.js,styles.css}`。
- TS 智能体编译产物 `agentSystem.js` 通过 Go `embed` 内嵌于可执行文件，随主程序分发；琉璃前端 `assets/` 同样 embed 内嵌。
