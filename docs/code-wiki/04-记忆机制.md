## 记忆解决什么问题

模型的上下文窗口有限，对话一长就会丢细节；只靠当前会话，它无法记住你上周说过的偏好，也无法积累看过的内容。记忆机制提供的是**跨会话的长期记忆**：

- 把对话、生活经历、图片和音频转成可检索的条目。
- 按内容主题自动归组，不需要你指定分类。
- 写入时发现高度相似的旧条目，先挂起，再由生活回合慢慢融合。
- 需要回忆时，用关键词与语义一起找，把最相关的原文取回来。

记忆不是「把聊天记录全存下来」。它保存的是**被提炼过的经历与事实**：一条对话可能变成一条偏好，一次观影可能变成一段观后感，而不是逐字记录整段会话。

## 三类记忆

| 类型 | 存什么 | 典型来源 |
|------|--------|----------|
| 文本 | 对话中值得记住的事实、偏好、经历，生活记录，知识片段 | 聊天、生活事件、观后感、日记 |
| 图像 | 表情包、截图、图片素材、绘画作品 | 发图、截图、绘图 |
| 音频 | 语音、音乐、环境声的描述与引用 | 语音消息、音频资料 |

三类记忆共用同一套检索入口，但类型过滤是独立的：问「我之前说过什么」默认查文本，问「那张图」才会查图像。音频通常只保留转写描述与句柄，不长期保存原始音频。

## 记忆从哪里来

记忆有四类写入来源：

1. **对话**：你说「记住：我常用 4K 显示器」这类明确要求，或对话中出现值得长期保留的偏好、事实、关系变化。
2. **生活**：生活事件与活动流产生的经历，例如看过的视频、逛论坛的见闻、创作意图与作品说明。
3. **观影**：选片、观看与评论过程中形成的印象、评价和分享内容。
4. **媒体资料**：图片、截图、绘画作品、表情包等，按主题归入对应的媒体分组。

写入时做两件事：

- **归组**：先算内容向量，与预置的语义分组比较，放进最相关的一组。分组不是查询表，只是归类；检索默认也不限定分组。
- **判重**：与同组旧条目比较相似度。足够相似时不直接新增，而是把新旧条目放进「待合并组」，等待生活回合的固定步骤三处理。

带标签写入时，标签向量用于检索，正文向量用于判重、聚类与整理校验；两者不混用。

## 合并与淘汰

记忆不会无限膨胀，靠的是「待合并 + 融合 + 兜底放行」：

| 机制 | 规则 |
|------|------|
| 待合并组 | 写入命中高度相似的旧条目时产生，只处理这些组，不按条数或入库时间挑选 |
| 单组规模 | 一组最多 8 条、6000 字；超出后新写入照常落库 |
| 待合并队列 | 最多 200 条；超出后不再新增待合并组，但正常写入不受影响 |
| 融合 | 把一组内容整合成更短、更完整的一条，保留人物、地点、事件与关键细节，重算正文向量 |
| 融合后长度 | 单条上限 512 字；超出时优先按句读截断，句读过早才硬切并补省略号 |
| 失败兜底 | 连续失败 3 次，或待合并状态持续 72 小时，自动解除挂起、放行可见 |
| 淘汰 | 不做「按条数定时删除」；主要通过融合压缩，以及你对条目的手动清理 |

这里的设计取向是「先合并，再谈淘汰」：宁可把多条相似经历压成一条更完整的记忆，也不轻易丢掉人物、地点和事件。融合失败也不会让记忆永久隐身，兜底机制会把它放回可见状态。

## 检索怎么走

回忆只有一条入口：资源中枢的 `memory` 模式。它只读长期记忆，不会因为「想起来」而去联网或现场读取文件。

一次检索大致经过：

1. **关键词与向量并行召回**：关键词负责精确命中，向量负责意思相近的说法。
2. **融合与去重**：两路结果合并，去掉重复内容，按相关度排序。
3. **分组索引辅助**：系统内部用语义分组缩小候选范围；分组只是加速与归类，不要求你指定。
4. **裁剪返回**：默认返回 5 条，调用方可以要求更多，上限 50 条。
5. **原文回答**：返回的是记忆原文与命中来源，模型只能依据这些原文回答；原文不足时要明确说「不记得」，不能编造，也不能转去现场读文件。

所以「搜不到」通常有两种原因：确实没存过，或者存的是图片/音频而问的是文本。需要时可显式要求按图像或音频类型检索，或要求全局再找一遍。

## 记忆库工作台

琉璃桌面的「记忆库」面板提供图形化管理：

| 操作 | 作用 |
|------|------|
| 查看分组 | 列出全部分组及条目数 |
| 新建 / 删除 / 清空分组 | 删除分组会同时清理条目与无人引用的图片 |
| 导入文本 / 图片 | 批量写入记忆 |
| 按类型检索 | 在文本、图像、音频之间切换 |
| 浏览条目 | 查看全部条目或某个分组 |
| 删除条目 | 删除单条，并清理没有其它条目引用的图片 |
| 改写正文 | 只改文本，不重算向量；需要语义一致时要重建分组向量 |
| 重建向量 | 对单个分组重算内容向量 |

图片统一放在记忆专属目录，与生成图、截图、背景图隔离；同内容图片只存一份；删除条目或分组时，只清理**没有其它条目引用**的图片实体。

## 失败与降级

| 失败 | 影响 | 处理 |
|------|------|------|
| 嵌入服务不可用 | 新记忆无法算向量 | 写入失败并记录原因；已有记忆仍可按关键词检索 |
| 归组失败 | 条目无法确定分组 | 不丢内容，进入默认分组或等待重试 |
| 融合失败 | 待合并组继续排队 | 连续 3 次或 72 小时后自动放行，避免永久不可见 |
| 检索无结果 | 模型没有可依据的原文 | 明确回答「不记得 / 没找到」，不编造 |
| 图片实体丢失 | 条目还在，图片打不开 | 返回条目文本与失效提示；不会假装图片存在 |
| 改写正文后检索变差 | 向量未更新 | 在记忆库面板重建该分组向量 |
| 记忆库面板打不开 | 服务未启动或记忆库未初始化 | 确认主程序运行后重试；初始化失败会记录在日志 |

记忆机制的原则是：**宁可说不知道，也不编造记忆；宁可放行一条未整理的记忆，也不让它永久隐身。**
