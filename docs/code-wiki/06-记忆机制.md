# 06 记忆机制

> [🏠 手册门户](README.md) ｜ [◀ 上一模块](05-绘画机制.md) ｜ [下一模块 ▶](07-扩展包.md)

## 一、这是什么

记忆机制是月华的**长期记忆**：它把对话、生活经历、图片与音频转成向量，分门别类地存进本地记忆库；需要回忆时，用语义相似度把最相关的内容找回来。

记忆库不按「谁说的、什么时候说的」建档，而是按**内容主题**自动归组。你不需要指定分类，也不需要维护标签——系统会把每条内容放进语义上最接近的分组。

---

## 二、核心用途

- **跨会话回忆**：记住你说过的偏好、经历过的事、看过的内容。
- **语义检索**：用意思相近的说法也能找回原文，不依赖关键词完全一致。
- **素材归档**：表情包、截图、绘画作品、语音等媒体资料按主题存起来。
- **固定整理**：写入时命中高度相似的旧条目会留下待合并组，由生活回合的固定步骤三逐组整合，避免记忆无限膨胀。

---

## 三、使用方法

### 3.1 在对话里使用记忆

- **回忆**：直接问「你还记得我上次说的那个配置吗」「我们之前看过什么视频」。
- **写入**：告诉月华「记住：我常用 4K 显示器」，它会作为一条文本记忆保存。
- **边界**：回忆类工具**只读**已有记忆，不会因为「想起来」而去联网或现场读取文件；需要看文件请用句柄引用。

### 3.2 三类记忆

| 类型 | 内容 | 典型来源 |
|------|------|----------|
| 文本 | 对话原文、知识片段、生活记录 | 聊天、生活事件、日记 |
| 图像 | 表情包、截图、图片素材、绘画作品 | 发图、截图、绘图 |
| 音频 | 语音、音乐、环境声 | 语音消息、音频资料 |

### 3.3 自动分组长什么样

记忆库预置 20 个语义分组，覆盖对话与媒体两大类：

| 大类 | 分组 |
|------|------|
| 对话与人物 | 日常闲聊、人物信息、关系互动、情感心情、兴趣爱好、偏好习惯、观点态度、动作行为 |
| 经历与事务 | 事件经历、计划日程、工作学习、知识见闻、地点场景 |
| 媒体 | 表情包、图片素材、截图、绘画作品、语音消息、音乐音频、环境声音 |

- 入库时先算内容向量，与全部分组名向量比较，放进最相关的一组。
- 分组不是查询表，只是归类；检索默认也不限定分组。

### 3.4 检索是怎么走的

1. **快速检索（默认）**：先查与问题语义最接近的分组；命中后补查第 2~5 名分组。
2. **全局检索**：首分组没有达标结果时自动回退全量扫描；也可以显式要求「全部找一遍」。
3. **类型过滤**：只返回你需要的类型（文本 / 图像 / 音频）。

日常建议：

- 一般提问不需要关心分组，默认路径最快。
- 明确知道「一定存过」但没搜到时，要求它「全局找一遍」。

### 3.5 用记忆库工作台管理

琉璃桌面的「记忆库」面板提供图形化管理：

| 操作 | 说明 |
|------|------|
| 查看分组 | 列出全部分组及条目数 |
| 新建分组 | 手动新增一个语义分组 |
| 删除分组 | 删除分组及其条目，并清理无人引用的图片 |
| 清空分组 | 保留分组，清空内容 |
| 导入文本 | 批量写入文本记忆 |
| 导入图片 | 批量写入图片记忆 |
| 按类型检索 | 文本 / 图像 / 音频跨全部分组检索 |
| 浏览条目 | 查看全部条目或某分组条目 |
| 删除条目 | 删除单条，并清理无引用的图片实体 |
| 改写正文 | 只改文本内容，不重算向量 |

### 3.6 图片存到哪里

- 记忆图片统一放在 `local_data/multimedia/memory/<分组名>/`，与生成图、截图、背景图隔离。
- 删除条目、清空或删除分组时，会同步清理**没有其它条目引用**的图片文件。
- 同内容图片只存一份（按内容哈希命名）。

## 四、功能特性

| 特性 | 说明 |
|------|------|
| 三类记忆 | 文本、图像、音频统一接口 |
| 自动归组 | 按内容向量与分组名向量比较，自动落到最相关分组 |
| 双路径检索 | 快速检索（首分组 + 补查）与全局检索 |
| 类型化过滤 | 查询只返回指定类型 |
| 内容去重 | 同内容只保留一份 |
| 媒体清理 | 删除条目/分组时清理无引用图片 |
| 向量重建 | 可对单个分组重建内容向量 |
| 分块持久化 | 条目与向量分块存储，支持逐条列举与分页 |
| 权重融合 | 可把分组内超高相似度的文本条目合并为一条并重算向量 |
| 固定整理 | 生活回合的固定步骤三逐组处理待合并组（写入相似条目时产生），不占事件权重 |

## 五、运行参数

记忆库没有独立的模型路由参数：嵌入与多模态统一使用本地固定模型（嵌入模型为 `text_embedding`）。

| 参数 | 位置 | 说明 | 默认值 |
|------|------|------|--------|
| `-memory-db` | 启动参数 | 记忆库目录 | `local_data/database/memory` |
| 检索条数 | 调用参数 | 单次检索返回条数 | 5（上限 50） |
| 分组名 | 调用参数 | 新建分组时指定 | 预置 20 组 |
| 整理对象 | 内建 | 只处理待合并组（Pending + 伙伴） | 无条数/时间门槛 |
| 单组规模 | 内建 | 单个待合并组的条目上限 | 8 条 |
| 待合并队列上限 | 内建 | 超出后新写入照常落库，不做时间淘汰 | 200 条 |

记忆库接口一览（供排障与开发调试）：`/memory/init`、`/memory/stats`、`/memory/collections`、`/memory/messages`、`/memory/entries`、`/memory/fuse`、`/memory/{分组}`（删除）、`/memory/{分组}/stats|documents|rebuild|reload|clear`。

## 六、常见问题

| 现象 | 可能原因 | 处理办法 |
|------|----------|----------|
| 说「不记得」 | 确实没存过，或存的是图片/音频而问的是文本 | 换一种问法；明确要求按图像/音频类型检索 |
| 搜不到但确定存过 | 快速检索的分组路由没有命中 | 要求「全局检索一遍」 |
| 记忆越用越多 | 自动整理需要时间与额度 | 属正常；可在记忆库工作台手动清理无用条目 |
| 记忆库面板打不开 | 记忆库未初始化，或服务端口不通 | 确认主程序在运行；重启后在面板重试 |
| 图片删了但条目还在 | 该图片仍被其它条目引用 | 属预期；先删除所有引用它的条目 |
| 改写正文后语义搜索变差 | 改写不重算向量 | 需要语义一致时请重建该分组向量 |
| 分组里内容很杂 | 自动归组按语义近似判断 | 可手动新建更细的分组，或整理条目 |
| 记忆库占用越来越大 | 图片与音频实体累积 | 清理无用条目与分组；必要时在磁盘上清理 `multimedia/memory/` |
