## 为什么需要统一句柄

如果每份资料都靠「重新上传」或「贴路径」来引用，会出现三个问题：同一份文件被反复读取、模型看到的路径各说各话、长文档一次塞满上下文。句柄系统解决的是**资料身份**问题：

- 一份资料只登记一次，得到一个短编号，之后反复引用。
- 编号永不复用，重启后旧编号仍指向同一份内容。
- 原文与编号分离：编号只记「这是哪一份」，正文由内容仓库单独保存。
- 可以精确到章节或行区间，避免整篇塞进上下文。

## 句柄文法

```text
@<类型码>.<序号>[|锚点]
```

| 类型码 | 含义 | 示例 |
|--------|------|------|
| `@D` | 文档（源码、Markdown、纯文本、配置、表格） | `@D.003` |
| `@I` | 图片 | `@I.007` |
| `@G` | 动图（GIF、APNG、动态 WebP） | `@G.002` |
| `@V` | 视频历史句柄，仅保证旧资料可读 | `@V.001` |
| `@A` | 音频（保留转写描述，不长期落盘） | `@A.004` |
| `@U` | 链接（网页、网络视频、BV 号，记地址与缓存摘要） | `@U.006` |

可选锚点用于精确定位：

| 锚点 | 含义 | 示例 |
|------|------|------|
| `\|§n` | 第 n 节（按文档标题结构编号） | `@D.003\|§4` |
| `\|L起-止` | 第起至止行，从 1 开始，含两端 | `@D.003\|L120-168` |

序号不足三位补零，超过 999 后自然变成四位。同一路径重复引用复用同一句柄；同名但路径不同的文件互不干扰；文件内容改动后再次引用会生成新句柄。

## 六类资源

| 类型 | 存什么 | 引用时模型看到什么 |
|------|--------|--------------------|
| 文档 | 正文、章节结构、行区间 | 相关章节正文，或资源卡片 |
| 图片 | 图片实体与视觉描述 | 最近图片可直接看，较早的看描述 |
| 动图 | 抽帧后的静态理解与描述 | 描述与句柄，窗口内不播放动画 |
| 视频 | 地址、关键帧、观看管线描述 | 句柄、标题、关键画面描述 |
| 音频 | 转写文本与描述 | 转写内容，不返回原始音频 |
| 链接 | 地址、标题、缓存摘要 | 地址与摘要；需要时现场读取 |

一个容易被忽略的规则：**模型能看到最近 20 张图片本身，更早的图片只以文字描述呈现**。这不是遗忘，而是控制上下文与显存成本。

## 资料怎么进入系统

| 资料 | 你的操作 | 系统行为 |
|------|----------|----------|
| 文本、代码、表格 | 上传或拖入 | 收录并建立章节结构，回执句柄 |
| 工作区文件 | 消息里写 `@相对路径/文件名` | 按需收录；原文件只读保留，不移动不删除 |
| 图片 | 直接发送 | 登记为 `@I`，附视觉描述 |
| 动图 | 发送 GIF / APNG / 动态 WebP | 登记为 `@G`，抽帧理解后附描述 |
| 视频 | 发送视频或经桥接转入 | 按链接资源记录为 `@U`，正文替换为句柄与文件名 |
| B 站视频 / BV 号 | 消息里出现地址或 BV 号 | 复用或新建 `@U`，首次出现时生成视频印象 |
| 网页链接 | 消息里出现网址 | 复用或新建 `@U`，首次出现时生成页面摘要 |
| 语音、音频 | 发送语音或音频 | 接入时即转写，登记为带描述的 `@A`，不长期保存原文件 |
| 工具产出 | 截图、绘图、超分结果 | 登记为对应类型句柄，可继续被引用 |

按文件名直接引用只支持文本类扩展名，单文件不超过 100MB。源文件一律只读收录，系统不会移动或删除你的原文件。

### 引用时注入多少正文

不是所有资料都把全文塞进模型，而是分三档：

| 资料情况 | 行为 |
|----------|------|
| 小文件（不超过 6000 字符且无标题结构） | 收录后自动注入全文 |
| 有标题结构的文档 | 按问题筛出最相关的若干节，总预算约 12000 字符，每节带锚点 |
| 大文件或超预算 | 只注入资源卡片（标题、体积、节数、摘要），正文按需读取 |

这就是为什么引用一本大文档时，模型会先看到目录和摘要，而不是从头读到尾。

## 资源中枢让 AI 自己查

月华不需要你每次手动贴句柄。她有一个统一的资源检索工具，按四种模式工作：

| 模式 | 你给什么 | 返回什么 |
|------|----------|----------|
| `memory` | 1–4 个关键词 | 长期记忆原文与命中来源 |
| `handle` | 一个或多个句柄 | 句柄对应的正文、描述或失效提示 |
| `path` | 文件名或相对路径 | 定位并读取对应资料 |
| `list` | 留空、类型码或过滤词 | 符合标准的句柄清单与简述 |

资源中枢内部按类型分派：

- 文档交给文献解析，按问题做定向探查，而不是整篇返回。
- 图片与动图交给视觉理解，返回与问题相关的描述。
- 视频交给观看管线，返回关键画面与内容描述。
- 网页现场读取标题与摘要；B 站地址走直驱印象。
- 压缩包与 GGUF 走确定性归档解析，不让模型直接读二进制。

任何一类解读能力缺失时，只会影响该类型；其他模式仍然可用，已缓存的描述或纯文本仍能返回。

## 文件与归档操作

文件操作归「文件编辑」智能体，作用范围是文档库。它能做：

- 列出目录、读取文本、分批读取大文件、读取文件属性。
- 写入、整篇覆盖、按行置换、全文检索。
- 运行项目内的脚本或命令，并回收输出。
- 把二进制容器与跨域理解交给子智能体：归档操作、归档解析、文献解析、视觉理解。

压缩包与 GGUF 有专门边界：

- 普通文件工具拒绝直接读写压缩包或 GGUF。
- 创建、删除压缩包、增删条目走归档操作。
- 查看压缩包结构、读取条目、解析 GGUF 元数据走归档解析。
- 这样模型不会把二进制当文本读，也能在失败时拿到明确原因。

资源库还提供确定性的文件能力：服务端压缩与解压、ZIP 元数据、文件移动与重命名、按内容哈希命名、批量整理、图片格式转换、文件预览。这些能力不依赖模型，失败时返回具体错误，而不是让模型猜。

## 知识库与自然语言查询

资源库的数据库页面对的是本地 SQLite 库，包含通用知识库与内建领域库（文本索引、自定义角色档案）。它提供三层能力：

1. **表清单与表结构**：只读查看有哪些库、哪些表、每张表有哪些列。
2. **行数据分页**：按排序、偏移与条数读取，不一次性拉全表。
3. **自然语言转 SQL**：把问题与当前表结构一起交给语句生成智能体，只生成一条只读语句；后端校验只允许查询类语句，写操作和多语句会被拦截。

语句生成智能体**只生成、不执行**。它返回的可能是 SQL，也可能是「无法生成」的说明；执行权始终在后端校验之后，避免模型绕过只读边界。

## 媒体处理能力

| 能力 | 用途 |
|------|------|
| 统一截图 | 自动、窗口、全屏、指定显示器、指定区域 |
| 视觉读取副本 | 把图片缩放到约束尺寸并叠印句柄标签，供模型查看 |
| 图片格式转换与缩放 | 批量或单张转换、按边长缩放 |
| 视频关键帧提取 | 从视频中抽关键画面，供理解与引用 |
| 图片超分 | 对已有图片做 4 倍超分，或生成后追加超分 |
| 语音转写 | 把语音与音频转成文本 |
| 哈希命名 | 按内容哈希生成稳定文件名，天然去重 |

这些能力大多由工具产出直接登记为句柄，后续可以像普通资料一样被引用、绘图参考或继续加工。

## 回收与失效

内容仓库有容量上限与回收策略，避免磁盘被历史资料吃满：

- 默认容量上限约 2GB，超限时按「保留等级 → 最久未用」回收。
- 回收的是**原文副本**，不是句柄名录；句柄仍然可以解析，但会提示「本体已回收」。
- 启动时结算一次，运行期按周期继续；资源库打开文件与 AI 读取都算一次取用。
- 图片、动图、视频与哈希命名的临时音频参与积分回收，长期不用会降到负分并触发回收；有描述时只删本体，句柄与描述保留。
- 派生缓存（视觉读取副本、视频解读切片）不进入资源名录，可以随时重建。
- 源文件丢失或损坏的句柄，在读取、列表、大纲任一入口被触碰时即移除。

所以「句柄失效」通常不是编号错了，而是原文被回收或源文件已不存在；需要原文件时重新发送或调高容量上限即可。

## 失败与降级

| 失败 | 表现 | 处理 |
|------|------|------|
| 句柄不存在 | 读取返回无效提示 | 让 AI 先列出现有句柄，不要手写编号 |
| 原文已回收 | 只剩名录与描述 | 句柄仍可用；需要原文时重新发送或调高配额 |
| 文档相关段落未命中 | 只返回开头或摘要 | 先把问题写得更贴近原文，再用章节锚点定向引用 |
| 视觉解读失败 | 图片没有描述 | 保留图片句柄，返回解析失败提示 |
| 视频地址失效 | 无法读取 | 保留句柄与标题，提示远程地址已失效 |
| 压缩包损坏 | 归档解析失败 | 返回具体错误，不按文本强行读取 |
| 文件写入失败 | 目标目录不存在或是目录写法 | 明确提示补文件名或检查路径，不产生同名空文件 |
| 数据库写操作 | 被后端拦截 | 只允许查询类语句；提示改写为只读查询 |

资源体系的原则是：**编号稳定、原文可回收、失败可解释**。句柄可以失效，但不能指向错误的内容。
