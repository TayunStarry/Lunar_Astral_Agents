## 联网检索

### 解决什么问题

模型的知识有截止时间，也无法直接访问当前网页。检索链把「一句自然语言需求」变成「一份带来源的摘要报告」，让月华能回答新闻、价格、教程、天气这类需要现场信息的问题。

### 触发

- 对话中调用联网探索的网页检索分支。
- 观影选片阶段需要查影片信息。
- 生活事件中需要补充背景资料。

### 参与者

- **搜索规划**：判断这次需求该走搜索、直连天气，还是根本不需要联网；产出检索词与策略。
- **抓取执行体**：按检索词访问搜索引擎与详情页，负责引擎降级、正文提取与时间预算。
- **搜索摘要**：把搜索结果页与多个详情页一次性提取成针对原始问题的摘要，剔除噪音。
- **天气引擎**：命中天气直连时直接查询并渲染，跳过搜索引擎。

### 数据怎么流动

1. 规划智能体先做路由决策：搜索、天气直连或无需检索。
2. 命中天气时，直接调用本地天气查询，成功就返回，不进入抓取。
3. 否则抓取执行体按检索词采集结果页与若干详情页；某个引擎不可用时自动降级到下一个。
4. 摘要智能体以**原始问题**为准绳，从全部正文中提取答案、关键事实与来源。
5. 摘要即最终报告；只有摘要失败时才走确定性兜底，把已抓到的标题、链接和片段整理成报告。

### 失败与降级

- 规划失败：按兜底决策继续，不直接终止。
- 所有引擎都不可用：返回明确的检索失败，不编造答案。
- 部分详情页打不开：用已打开的页面继续摘要，并标注来源缺失。
- 摘要失败：返回确定性报告，至少保留来源与关键片段。
- 超时：整次检索有时间上限，到点停止抓取并汇总已有内容。

## B 站观影

### 解决什么问题

观影不是「播放视频」，而是让月华像观众一样完成一整段观看经历：选片、判断是否适合、抽取片段、形成观感、决定是否评论或分享。它同时为生活系统提供经历，为记忆提供观后感。

### 触发

- 生活回合抽中「观影」事件。
- 对话中明确要求看某个视频或某个 UP 主的内容。
- 消息中出现 B 站链接或 BV 号，需要形成首次印象。

### 参与者

| 角色 | 负责 |
|------|------|
| 观影阅片 | 选片、切片、形成整体印象与片段摘要 |
| 观影审查 | 判断内容是否适合评论、分享与进入日记；命中风险则换片或只看看 |
| 观影观感 | 把片段理解转化为第一人称的观后感与评论草稿 |
| 观影评论 | 在视频下发表评论、处理评论区的回复 |
| 观影分享 | 决定是否分享到动态或群聊，并组织分享文案 |

### 数据怎么流动

1. **选片**：从待看列表、搜索或对话指定中确定候选，并形成初步印象。
2. **审查**：对候选做内容风险判断；高风险内容不评论、不分享、不进日记。
3. **观看**：按视频时长切成若干片段（通常 1–5 段），逐段抽帧理解，而不是把整段视频塞进模型。
4. **观感**：每个片段形成简短观感；普通片段按概率触发评论，最后一段必发收束评论。
5. **互动**：按审查结论决定是否发布评论、是否回复评论区、是否分享；每看满若干完整视频，更新一次「我刚刚在干的事情」。
6. **归档**：视频登记为 `@U`，观感与评论进入生活记录与记忆候选。

看完或判定没看成时，观影链会把结果回报给心愿系统：内容对得上的待处理愿望自动完成，判定为不合适或最终失败的标记逾期。愿望与心情的结算规则见 [心愿清单](./03-生活与情绪.md#心愿清单)。

观影有严格的预算：整轮观看有时间上限，采集阶段最多用掉其中约三分之二；预算耗尽时提前结束，已完成的结果保留，未处理的候选不留下半成品记录。

### 失败与降级

- 登录失效：暂停互动，只做本地理解，不强行发布。
- 视频下架或地区限制：换下一个候选，并记录失败原因。
- 抽帧失败：降级为标题、简介与评论摘要，不假装看过。
- 审查命中风险：跳过评论与分享，仍可保留「看过」的经历。
- 预算耗尽：提前收尾，保留已完成部分，不把未完成候选写成已看。

## 互助论坛

### 解决什么问题

论坛给月华一个「主动帮助别人」的场景：看别人的问题，判断自己是否能帮上忙，写回答并参与后续讨论。它不是客服机器人，不追求有问必答。

### 触发

- 生活回合抽中「论坛」事件。
- 对话中明确要求去论坛看看或回复某个问题。
- 论坛中有新的评论、@ 或引用需要处理。

### 参与者

- **互助论坛**智能体：阅读问题、判断是否参与、起草回答、处理后续互动。
- **论坛链**：负责拉取问题、控制节奏、发布与重试。
- **通讯桥接**：需要时把论坛动态同步到 QQ。

### 数据怎么流动

1. 拉取近期问题与新互动，过滤已处理内容。
2. 判断哪些问题值得参与：能回答、有信息增量、不涉及敏感内容。
3. 起草回答；需要事实时调用检索，不凭空编造。
4. 发布回答，并记录问题、回答与后续互动。
5. 有新评论或 @ 时，按配置决定是否继续回复；连续失败会重试，超过上限则放弃并记录。

### 失败与降级

- 论坛未启用或账号未绑定：整个能力不出现，不报错打扰。
- 拉取失败：本轮跳过，等待下一次生活回合。
- 发布失败：重试有限次数；仍失败则保留草稿并记录，不重复刷屏。
- 内容敏感：放弃参与，不绕过审核。

## QQ 桥接

### 解决什么问题

让月华能通过 QQ 与真实联系人、群聊互动，而不是只能在自己的终端里说话。桥接同时负责把消息送进来、把回复送回去，并处理群聊的上下文与防打扰。

### 触发

- NapCat 桥接已连接，且收到私聊、群聊 @、关键词命中或引用消息。
- 月华主动调用联网探索的 QQ 发送分支。

### 参与者

- **通讯桥接**智能体：理解「发给谁、发什么」，把自然语言需求转成结构化投递。
- **桥接层**：维护连接、消息缓存池、收发队列、重连与白名单。
- **人格对话**：实际生成回复内容。

### 数据怎么流动

1. 桥接层连接 NapCat WebSocket；断线后按固定间隔重连，超过次数则进入断开状态。
2. 私聊消息先在短窗口内合并，避免图片与文字被拆成两轮；群聊按关键词与触发概率决定是否进入队列。
3. 消息进入待处理队列，串行推送给月华；同一时间只处理一个请求，避免并发写 QQ 导致报告互相覆盖。
4. 月华生成回复后，桥接层按原会话送回；图片与文件分批发送，单次有数量上限。
5. 主动投递默认走白名单：目标不在名单内会被拦截，并提示需要明确确认才能绕过；绕过确认有时间限制。

### 失败与降级

- 桥接未连接：`qq_send` 不出现在工具目录里，月华不会误以为能发。
- 连接中断：有限次重连；仍失败则停止投递并记录，不无限重试。
- 目标不在白名单：拒绝发送，返回固定提示。
- 消息过长或图片过多：分批发送；超限部分明确告知，不静默截断。
- 回复超时：结束当前请求，避免队列永久卡住。

## 桌面操纵

### 解决什么问题

有些操作没有 API，只能在真实 Windows 桌面上点、输、拖。桌面操纵让系统能完成这类任务，但它直接控制键鼠，风险远高于其他能力，因此被单独隔离。

### 触发

- **只能由控制台人工启动**，月华的工具目录里没有桌面操纵。
- 对话者开始新的对话回合时，正在运行的桌面任务会自动停止，避免和聊天抢键鼠。

### 参与者

桌面操纵不是单个模型调用，而是七个角色接力：

| 角色 | 负责 |
|------|------|
| 桌面操纵·编纂 | 把口语化需求整理成结构化任务说明 |
| 桌面操纵·启动 | 定位或启动目标程序 |
| 桌面操纵·UIA | 读取当前窗口的 UI 自动化树 |
| 桌面操纵·规划 | 综合 UI 情报与真实窗口状态决定下一步 |
| 桌面操纵·键盘 | 键入文本、按键、组合键 |
| 桌面操纵·鼠标 | 点击、拖拽、滚动、移动 |
| 桌面操纵·UIA操作 | 直接对 UI 元素点击或写入 |

### 数据怎么流动

1. 编纂者把「帮我用记事本写个东西」变成明确步骤。
2. 启动者找到或打开目标程序。
3. UIA 理解者优先读取控件树；读不到时用带坐标网格的截图做视觉定位。
4. 规划者每一步只决定一个动作，交给键盘、鼠标或 UIA 操作者执行。
5. 执行后重新观察窗口状态，再进入下一步；最多 10 轮，连续两轮没有可见变化就判定停滞并停止。

### 失败与降级

- 程序找不到：尝试开始菜单、常见目录与 PATH，仍失败则报告。
- UIA 不可用：降级到截图网格 + 鼠标键盘。
- 操作无效果：连续两轮无变化即停止，不无限重试。
- 用户开始对话：自动停止；第一次请求优雅收尾，再次请求才强制中断。
- 任何一步失败：保留执行记录，报告停在哪一步，不假装完成。

## 扩展包

### 解决什么问题

扩展包让新页面、新工具不改编主程序就能接入。一个包可以只是一个展示页面，也可以声明工具，让月华在对话中调用它。

### 扩展包是什么

扩展包是放在资源库包目录里的独立页面，带一份 `metadata.json`：

- **基本信息**：名称、标题、说明、入口地址或入口文件。
- **标签**：决定桌面分组与能力形态。`Zero-LTP` 是纯人类操作页面；`Node-LTP` 声明工具、可被月华调用；`Mini-LTP` 注入通用页面操作助理；`Self-LTP` 注入自主页面操作智能体；另有 `LTP9`、`DeepSeek`、`DeepDemos` 等分组标签。
- **工具声明**：工具名与一句话说明，不声明复杂参数结构；调用时只传一段自然语言指令。

### 安装与创建

- 可以安装已有包，也可以从 URL、本地路径或 ZIP 创建新模块。
- 创建模块时可以选择是否注入 Mini-LTP 页面操作助理；注入后页面具备被自然语言操作的基础能力。
- 创建模块前可以先检查 HTML 项目内容，读取标题、结构与样式，用于生成元信息。
- 包目录会被扫描并加载到琉璃桌面；桌面按标签分组，图标位置与空行可以持久化。

### 调用怎么发生

1. 月华的工具目录里有一个统一的「扩展应用」入口，列出当前已安装包声明的工具。
2. 模型选择工具并写清指令，调用时附带包名、工具名与指令。
3. 服务端受理后立即返回一个请求标识，并把调用广播给该包的页面。
4. 页面执行工具，把结果回执给服务端。
5. 发起调用的等待方在进程内拿到结果，继续本轮对话。

**这里没有轮询取结果这一步。** 调用是「受理 → 页面执行 → 回执 → 等待方取结果」的事件式流程；服务端即使保留了待处理列表，也只用于调试观察，不承担结果轮询。

如果包页面还没打开，系统会唤起琉璃桌面并等待页面订阅就绪，再投递调用；等待超时则返回失败，而不是无限挂起。

### 生命周期

| 操作 | 行为 |
|------|------|
| 安装 / 创建 | 写入包目录，扫描并加入桌面 |
| 打开 | 在桌面覆盖层 iframe 中打开，不整页跳转 |
| 导出 | 打包当前包内容，便于备份或分享 |
| 归档 | 先导出备份，成功后再删除当前包 |
| 删除 | 移除包目录与桌面入口 |
| 停用助理 | 切换标签，关闭 Mini-LTP / Self-LTP 自动操作 |

### 失败与降级

- 包页面未打开：尝试唤起桌面，超时后返回失败。
- 工具未声明或已删除：工具目录动态刷新，不会继续调用不存在的工具。
- 页面执行报错：错误回执给等待方，由月华解释或换工具。
- 包结构损坏：安装前检查拦截；已安装包加载失败时跳过该包，不影响其他包。
- 导出失败：归档中止，不删除原包。

## 时间天气与位置

这些信息不需要模型「想起来」，而是作为运行时状态提供：

- **时间**：每轮对话与生活回合注入当前本地时间，模型不需要自己做日期推算。
- **天气**：天气查询支持多家数据源，归一化成当前天气、预报与空气质量；检索链命中天气意图时直接查询，跳过网页抓取。
- **位置**：当前地址作为运行时状态参与提示词与天气查询；位置不明确时，天气查询会退回按城市名检索。

天气查询失败不会阻塞对话：本轮可以不带天气信息继续，或明确说明「天气暂时查不到」。

## 失败与降级

| 失败 | 影响 | 处理 |
|------|------|------|
| 搜索全部引擎不可用 | 没有检索结果 | 明确报告失败，不编造来源 |
| 天气源全部失败 | 没有天气 | 跳过天气直连，回退检索或说明查不到 |
| 观影登录失效 | 无法评论/分享 | 只做本地理解，暂停互动 |
| 论坛发布失败 | 回答没有发出去 | 有限重试，保留草稿，不刷屏 |
| QQ 断线 | 无法收发 | 有限重连，失败后停止投递 |
| 桌面操作失控 | 键鼠行为异常 | 无变化即停、轮次上限、对话开始自动终止 |
| 扩展包页面未就绪 | 工具调用无结果 | 唤起桌面并等待，超时返回失败 |
| 扩展包执行报错 | 本轮工具失败 | 错误回传模型，由模型解释或换工具 |

外部能力的原则是：**能降级就降级，不能降级就明确失败；不把「没做到」说成「做到了」。**
