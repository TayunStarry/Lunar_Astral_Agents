# 02 核心系统——钛宇-月华（lunar_astral）

> [🏠 文档地图](README.md) | [◀ 上一章](01-项目架构总览.md) | [下一章 ▶](03-扩展系统-钛宇-琉璃.md)

AI 桌面智能体核心系统，集成多模态对话、TTS 语音合成与图像生成。

---

## 0. 功能概述

| 功能 | 说明 |
|------|------|
| AI 智能对话 | 基于本地 GGUF 模型的角色扮演对话，支持多模态输入（文本/图片/视频） |
| TTS 语音合成 | 文本转语音，AI 回复实时合成音频 |
| 图像生成 | 基于 stable-diffusion.cpp 的文生图 |
| 富文本渲染 | 对话中 Markdown / Mermaid / ECharts / KaTeX 渲染 |
| 网络搜索 | 经 LTPX 工具 `use_the_program`（tool=`web_search`）路由到琉璃 Web-LTP 执行真浏览器检索（见 [09 §5.4](09-LTPX协议-月华工具包.md)） |
| QQ 适配器 | 接入 QQ 群聊，关键词唤醒 AI 对话 |

## 2. 启动时序

```
main.go
  └── server.InitializeServer()
        ├── LoggerGeneral.SetDevMode()         ← 初始化日志（开发模式开关）
        ├── MIME 表注册 + 创建 LocalDir
        ├── registerHandlers()                 ← 注册所有 HTTP 路由 + 启动图像任务协处理器
        ├── llama.Init()                       ← 启动 llama-server + 等待就绪（5 分钟超时）
        ├── initTTSEngine()                    ← 初始化 Qwen3-TTS 语音引擎
        ├── websocket.SetupWebSocketHandler()  ← 注册 /ws 端点
        ├── adapters.RunAgentContext()         ← 创建 goja 运行时并执行 agentSystem.js
        └── initBridgeAdapter()                ← 加载 NapCat 桥接配置并启动扫描
  ├── SetupSignalHandling()                    ← 系统信号监听
  ├── StartServerListener()                    ← 端口监听
  └── WaitForShutdown()                        ← 优雅关闭（系统信号或 WebView 关闭）
```

**优雅关闭顺序**（`server/manage.go`）：`LunarGoja.Close()`（JS agent context）→ NapCat 桥接 → llama.cpp → WebSocket → WebView → `http.Server.Shutdown`（5 秒超时）。

WebView 窗口：1080×810，标题 `[星月智能] : 钛宇-月华`，地址 `http://127.0.0.1:<BasicPort>`。

### 3.5 bridging/napcat/ —— QQ 群聊适配器

NapCat ↔ 月华消息转发（WebSocket 客户端，`Authorization: Bearer <token>`；接口文档 <https://napcat.apifox.cn/5430207m0>）。配置位于 `lunar_config.json` 的 `server` 分组：

| 字段 | 说明 |
|------|------|
| `bridging_type` | `"napcat"` 时启用 |
| `bridging_path` | NapCat WebSocket 地址（如 `ws://localhost:4567`） |
| `bridging_token` | 鉴权令牌 |
| `bridging_users` | 私聊允许的用户 ID / 允许响应的群号列表 |
| `bridging_group_keywords` | 群聊唤醒关键词 |
| `bridging_group_trigger_probability` | 关键词命中外的群聊随机触发概率（默认 0.3） |

重连间隔 5 秒、最多 3 次；发送队列 FIFO 单线程。WS 读取循环与消息解析通过带缓冲通道 + 单消费协程解耦（解析含 HTTP API 调用，不阻塞读取，且保持消息顺序）。

**入站文本格式**（月华看到的消息）：

- @ 段渲染为 `[对 <用户名> 说]`：@ 全体成员 → `[对 全体成员 说]`；@ 机器人自身 → `[对 我 说]`；@ 其他成员 → 查 `get_group_member_info`（群名片优先）/ `get_stranger_info` 兜底，最终退回 QQ 号。成员名缓存在 `memberNameCache`（群号 → QQ号 → 名称），并按群异步预热一次 `get_group_member_list`。
- 回复引用经 `get_msg` 还原为 `[回复 <发送者>: <内容摘要>]`（摘要超 120 字截断）。
- 合并转发经 `get_forward_msg` 递归展开（嵌套最深 3 层），逐行 `发送者: 内容摘要`；图片/视频/语音/文件/卡片/链接以 `[图片]` `[视频]` `[语音]` `[文件: 名]` `[卡片: 标题]` `[链接: 标题]` 占位。
- QQ 表情输出文本含义 `[表情: 呲牙]`：优先 NapCat 下发的 `raw.faceText`（形如 `/呲牙`，真实抓包中必然携带），其次 `raw.faceIndex`，最后按 `id` 查 `face.go` 的 `qqFaceTextMap`；均无法识别时退回 `[表情]`。大表情同样以 `face` 段下发（`raw.faceType` 为 2），故走同一路径。对照表由 [subsystem/bridge_probe/gen_face_go.js](subsystem/bridge_probe/gen_face_go.js) 从 NapCat 官方 [face_config.json](https://github.com/NapNeko/NapCatQQ/blob/main/packages/napcat-core/external/face_config.json) 的 `sysface` 段生成（329 项、id 非连续、跨度 0~484，0 惊讶 / 13 呲牙 / 14 微笑，QQ 下架表情留空号），官方更新后重跑脚本即可同步。回复引用与转发摘要沿用同一渲染。
- 群文件：图片（按扩展名 + 文件头嗅探）转 base64 data URI 进入多模态内容；文本文件打包为 ```文件名 围栏块```（超 64KB 截断），由阅读者切片入库；其余仅报名称与大小。
- 红包：识别 `raw.elements[].walletElement`；口令红包延迟 0.5~3 秒推送并附带复读指令，月华复读口令即领取（私聊同样生效）；无可理解内容的空消息不入池不触发。

**出站回应格式**（月华 → QQ）：

- 群聊文本中的 `[对 xxx 说]` 反向转换为真实 @ 段（`mentionPattern` 正则 + 成员名称缓存反查）；`[对 全体成员 说]` → @全体成员；无法解析的提及保留原文。
- 被 @ 触发的群聊回应，回合内首次发言自动在消息最前 @ 回触发者（`BridgeTarget.ReplyToUserID`，转发时消费一次）。
- 超过 4000 字符的文本自动在换行处分片连续发送；图片支持 base64 data URI 与 http 直链两种载体。

## 4. TypeScript 智能体（编译为 agentSystem.js）

### 4.1 编译链路

```
TypeScript/agent/constructor.ts → tsc (→ node_modules/deliverable/) → rollup (iife) → hierarchy/assets/agentSystem.js
```

- `package.json` 的 `server.side` 脚本完成上述编译；`release.min` 为 `tsc && rollup -c`
- 入口为 `./TypeScript/agent/constructor.ts`
- 模块间引用一律点对点直连目标模块（不设聚合 barrel），新增全局导出在 `constructor.ts` 显式聚合；`DialogueRole` 的描述者/记忆者依赖经构造注入，`capabilities/media.ts` 的角色单例经 `registerMediaRoles` 注入

## 6. HTTP API 与 WebSocket 协议

路由统一注册于 `SystemEndpoints`（[server/variable.go](../../lunar_astral/server/variable.go)）；`/ws` 由 `websocket.SetupWebSocketHandler` 单独注册。端点与提供方总览见 [07-依赖关系 §4](07-依赖关系.md)。

### 6.1 HTTP 端点

| 路径 | 方法 | 功能 |
|------|------|------|
| `/v1/` | ANY | 智能体代理接口（OpenAI 兼容，转发 llama.cpp / 云端） |
| `/write/message` | POST | 消息写入队列 |
| `/write/videourl` | POST | 视频 URL 写入 |
| `/write/engine` | POST | 引擎系统消息（动画列表缓存、遥测） |
| `/write/agent_position` | POST | 智能体 3D 位置更新 |
| `/write/agent_event` | POST | 引擎事件推送至 AI 上下文 |
| `/generate` / `/generate/wait` | POST / GET | 图像生成 / 等待生成结果 |
| `/capture`（ANY）· `/capture/displays` | POST/GET · GET | 统一截图 / 显示器列表 |
| `/resize` | POST | 图片缩放 |
| `/tts` | POST | TTS 语音合成 |
| `/memory/` | ANY | 记忆库（实例初始化/集合管理/消息增删查） |
| `/file/write` · `/file/read/` | POST · GET | 文件写入 / 读取（含静态资源） |
| `/background` | GET | 随机背景图 |
| `/proxy` | POST | 通用代理访问 |
| `/ws` | GET | WebSocket 连接升级 |

视频经 `videoMedia` 本地化到 llama-server 媒体目录（长视频自动 60 秒分段），由感知者角色以 file:// 引用逐段理解。
动态图（多帧 GIF / APNG / 动态 WebP）经 `isAnimatedImage` 判定后由 `animatedImageToVideo` 编码为慢放视频，
与视频共用同一条感知者理解链路（详见 4.4 multimodal_analysis 的动态图理解链路）。

### 6.2 WebSocket 消息协议

服务端广播 `WSResponse`，JSON 字段：`type`（消息类别）、`data`（负载）、`context`（对话上下文）、`image`（图片负载）。QQ 桥接处理 `context` 与 `image` 两类；前端按 `type` 分发渲染。

## 7. 常见问题

**如何切换语言模型？** 将 GGUF 模型放入 `local_data/models/`，编辑 `local_data/models/models.ini`：`[system-multimodal]` 段配置多模态模型的 `model` / `mmproj` 路径，`[system-embedding]` 段配置嵌入模型的 `model` 路径。修改后重启程序生效。

**llama-server 启动失败？** 检查 `llama-server.exe` 是否存在（`-infer-engine` 参数或默认 `local_data/models/llama.cpp/`）、`models.ini` 中模型路径配置正确、端口未被占用、查看控制台 llama 日志。

**JS 智能体代码在哪里修改？** 源码位于 `TypeScript/` 目录，在 `lunar_astral` 下执行 `npm run server.side` 后生成 `hierarchy/assets/agentSystem.js`（或直接执行 `.\build.ps1` 走完整构建）。
