# 04 观影机制

> [🏠 手册门户](README.md) ｜ [◀ 上一模块](03-搜索机制.md) ｜ [下一模块 ▶](05-绘画机制.md)

## 一、这是什么

观影机制是月华「刷 B 站」的完整流程：它用真实浏览器打开哔哩哔哩，按偏好挑几条视频，先看简介、评论和弹幕形成印象，再逐段观看、写评价，最后发一条自己的观影动态，并把这一轮经历写进长期记忆。

它由生活系统驱动，属于「看视频」这一生活类型；也可以在对话里直接让它「去看看视频」，由联网探索工具安排到下一轮。

---

## 二、核心用途

- **自主消遣**：在空闲时自己找内容看，形成连续的生活经历。
- **内容理解**：把视频画面按切片理解成文字印象，而不只是记录标题。
- **轻量互动**：发一条自己的观后动态，并回应收到的 @ 与追评。
- **记忆沉淀**：每轮观影会生成日记式记忆，供后续对话回忆。

---

## 三、使用方法

### 3.1 自动触发

不需要操作：生活系统抽到「看视频」且当日额度未用完时，会自动开始一轮。默认每日 6 次。

### 3.2 用对话触发

对月华说：

- 「去看看视频」
- 「去 B 站看看有趣的猫咪视频」

它会回一句「月华等下就去 B 站逛逛」，并在下一节拍进入观影流程。`instruction` 可以引导选片方向，但轮次仍受每日额度控制。

### 3.3 首次使用先登录

1. 观影开始时会自动打开一个 B 站浏览器窗口。
2. 如未登录，窗口会跳到登录页，程序最多等待 **60 秒**。
3. 请在这 60 秒内用手机扫码完成登录。登录状态由浏览器会话保持，之后一般无需重复登录。
4. 超时未登录则该轮放弃，不会反复弹窗。

### 3.4 一轮观影都做什么

| 阶段 | 内容 |
|------|------|
| 选片 | 根据偏好关键词从首页与搜索页预选 **4~8** 个候选 |
| 形成印象 | 采集标题、标签、简介、时长、发布时间、UP 主、评论与弹幕，用轻量模型生成视频印象 |
| 排序 | 按与你偏好关键词的匹配度综合排序 |
| 审核评价 | 用主模型逐条审核内容是否适合观看，给出评价与切片数（2~8，默认 5） |
| 观看 | 每秒推进一个切片，逐段理解画面 |
| 合并入库 | 全部切片看完后合成一份完整的观看记录 |
| 发动态 | 发布一条自己的观影动态，并打开自己的评论区 |
| 互动 | 回应本轮收到的 @ 与追评，总数受 `replies_per_round` 限制 |
| 写记忆 | 生成第一人称的日记式记忆 |

### 3.5 它会在哪里发言

只有两处：

1. **自己动态的评论区**；
2. **被动收到的 @ 与追评**。

它不会主动去别人的视频评论区留言。命中风险内容的视频会被跳过，不评论、不分享、也不写进日记。

### 3.6 观测与导出

- 控制台「系统日志」可看观影过程日志。
- 控制台「数据导出」屏可导出哔哩观影的上下文，便于排查。

## 四、功能特性

| 特性 | 说明 |
|------|------|
| 真实浏览器 | 打开真实 B 站页面，登录态与页面行为一致 |
| 候选定量 | 每轮固定预选 4~8 个候选，避免无限刷 |
| 两段式模型 | 印象与排序用轻量模型，审核与评价用主模型，兼顾速度与质量 |
| 切片观看 | 视频按段理解后合成，长视频不会一次性塞满上下文 |
| 动态与评论 | 只在自己动态下互动，被动回复 @ 与追评 |
| 风险规避 | 命中风险的视频不互动、不入日记 |
| 日记式记忆 | 每轮生成第一人称记忆，可被后续对话检索 |
| 断点续跑 | 一轮可跨多个节拍推进，被新消息打断后会自动续跑 |

## 五、运行参数

| 参数 | 文件 | 说明 | 默认值 | 建议 |
|------|------|------|--------|------|
| `preference_keywords` | `local_data/bilibili_life.json` | 选片偏好关键词，参与关键词生成与候选加分 | 出厂示例（AI / Qwen / 本地部署等） | 换成你希望它多看的主题 |
| `replies_per_round` | `local_data/bilibili_life.json` | 单轮可回应被动消息的次数（@ 与追评共享） | `15` | 想安静些就调小 |

固定机制（不可配置，供对照）：

| 项目 | 值 |
|------|----|
| 每轮候选数量 | 4~8 |
| 每个视频切片数 | 2~8，默认 5 |
| 单轮采集评论条数 | 30（单条最多 200 字） |
| 单轮采集弹幕条数 | 30 |
| 登录等待时长 | 60 秒 |
| 生活触发权重 / 每日额度 | 14 / 6 次 |

> `bilibili_life.json` 属于本地私有配置，不会随程序分发，也不会进入版本库；请在程序目录的 `local_data/` 下自行维护。

## 六、常见问题

| 现象 | 可能原因 | 处理办法 |
|------|----------|----------|
| 观影开始后又马上结束 | 未登录、登录超时，或没选到可用候选 | 在浏览器窗口内完成扫码登录；确认网络可访问 B 站 |
| 浏览器窗口没出现 | WebView2 缺失，或窗口被最小化 | 安装 WebView2 Runtime；检查任务栏是否有被遮住的窗口 |
| 只看了很少几个视频 | 候选命中风险被跳过，或切片数设置较小 | 属正常策略；可调整偏好关键词让候选更贴合 |
| 没有发动态 | 内容风险未通过，或登录态失效 | 重新登录后重试 |
| 评论区没有回应 | 本轮没有收到 @ 或追评，或次数已用完 | 检查 `replies_per_round` |
| 一天刷太多次 | 每日额度为 6 次，触发后可能连续安排 | 属生活系统调度；可通过减少对话触发来降低频率 |
| 记忆里只有标题没有内容 | 切片理解失败（画面无法解码） | 检查本机视频解码能力与网络状况 |
| 想减少打扰 | —— | 调小 `replies_per_round`，或减少「去看看视频」这类指令 |
