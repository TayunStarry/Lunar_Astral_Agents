# 04 观影机制

## 一、这是什么

观影机制是月华「刷 B 站」的完整流程：它用真实浏览器打开哔哩哔哩，按观影记忆与偏好补齐待看列表，然后一段一段地把视频看完、写下观感，并在需要时回应别人的 @ 与追评。

它不再是独立的一条链上流程，而是挂进生活链的固定回合：

1. 待看列表为空时补齐候选（`viewer.EnsureWatchlist`）；
2. 每轮生活回应 B 站消息（`viewer.AutoRespondOnBilibili`）；
3. 生活权重抽到「看视频」时看下一个片段（`viewer.WatchNextSegment`）。

---

## 二、核心用途

- **自主消遣**：在空闲时自己找内容看，形成连续的生活经历。
- **内容理解**：把视频画面按片段理解成文字印象，而不只是记录标题。
- **轻量互动**：在视频评论区留下观感，每看完 8 个视频发一条阶段动态。
- **被动回应**：收到 @ 或追评时在对应位置回复。
- **记忆沉淀**：观感进入观影记忆，供后续对话回忆。

---

## 三、使用方法

### 3.1 自动触发

不需要操作。生活回合推进到「待看列表补齐」阶段时，若满足以下四项条件就自动补齐：

1. 生活链被触发；
2. Bilibili 页面能成功开启；
3. B 站账号已登录；
4. 待看视频列表为空。

任一条件不满足即跳过本轮，不产生任何写入。

### 3.2 用对话触发

对月华说「去看看视频」或「去 B 站看看有趣的猫咪视频」。它会登记一次生活事件，在下一个生活回合进入「看视频」分支；`instruction` 会作为本轮选片的额外参考。

### 3.3 首次使用先登录

1. 观影开始时会自动打开一个 B 站浏览器窗口。
2. 如未登录，窗口会跳到登录页，程序最多等待 **60 秒**。
3. 请在这 60 秒内用手机扫码完成登录。登录状态由浏览器会话保持，之后一般无需重复登录。
4. 超时未登录则该轮跳过，不会反复弹窗。

### 3.4 待看列表怎么补齐

| 步骤 | 内容 |
|------|------|
| 筛候选 | 按观影记忆与偏好关键词，从首页与搜索页筛出 **24** 个候选（同 BV 去重） |
| 抽印象 | 采集标题、标签、简介、时长、发布时间、UP 主、评论与弹幕，用轻量模型生成视频印象 |
| 审核 | 用主模型逐条审核内容是否适合观看，同时给出评价与切片数（2~8，默认 5） |
| 入队 | 过审的候选写入待看列表；同 BV 已存在时不重复写入 |
| 切片下载 | 按切片数把视频下载成本地片段；任一段失败则该视频标记为可重试，下一轮继续 |

### 3.5 看视频时做什么

`WatchNextSegment` 每次只处理**一个已下载、未看过**的片段：

1. 本地解码该片段并抽帧，交给多模态模型理解画面（解码失败时降级为「视频印象」文本）；
2. 依据画面理解与视频印象写一条观感评论；
3. 把评论发布到原视频的评论区；**最后一段**的评论会 @ 原作者；
4. 更新「我刚刚在干的事情」；
5. 每看完 **8** 个完整视频，发一条阶段动态。

同一个视频的片段按顺序推进，全部片段看完才算一个完整视频。

### 3.6 在哪里发言

1. **视频评论区**：每看一个片段留一条观感，最后一段 @ 作者；
2. **自己的动态评论区**：每 8 个视频一条阶段动态；
3. **被动收到的 @ 与追评**：在对应位置回复。

命中风险的视频不会入队，也就不会被评论；已经入队的视频如果下载失败，会保留可重试标记。

### 3.7 观测与导出

- 控制台「系统日志」可看观影过程日志。
- 控制台「数据导出」屏可导出哔哩观影的上下文，便于排查。

## 四、功能特性

| 特性 | 说明 |
|------|------|
| 真实浏览器 | 打开真实 B 站页面，登录态与页面行为一致 |
| 候选定量 | 每次补齐固定 24 个候选，避免无限刷 |
| 两段式模型 | 印象用轻量模型，审核与评论用主模型，兼顾速度与质量 |
| 逐段观看 | 每次生活回合只推进一个片段，长视频不会一次塞满上下文 |
| 评论与动态 | 片段观感留在视频评论区，阶段动态留在自己动态区 |
| 风险规避 | 命中风险的视频不入队、不互动 |
| 失败可续跑 | 下载失败下一轮重试；回应失败进队列，最多尝试 3 次 |
| 记忆驱动选片 | 长期记忆里的主题词参与候选筛选，看过的不再重复入选 |

## 五、运行参数

| 参数 | 文件 | 说明 | 默认值 | 建议 |
|------|------|------|--------|------|
| `preference_keywords` | `local_data/config/bilibili.json` | 选片偏好关键词，参与候选加分与检索 | 出厂示例（AI / Qwen / 本地部署等） | 换成你希望它多看的主题 |

固定机制（不可配置，供对照）：

| 项目 | 值 |
|------|----|
| 每次补齐候选数 | 24 |
| 每个候选采集评论数 | 20 |
| 每个视频切片数 | 2~8，默认 5 |
| 阶段动态间隔 | 每 8 个完整视频 |
| 单条回应最多尝试次数 | 3 |
| 登录等待时长 | 60 秒 |
| 生活触发权重 / 每日额度 | 26 / 12 次 |

> `config/bilibili.json` 属于本地私有配置，不会随程序分发，也不会进入版本库；请在程序目录的 `local_data/` 下自行维护。

## 六、常见问题

| 现象 | 可能原因 | 处理办法 |
|------|----------|----------|
| 待看列表一直不补齐 | 未登录、登录超时、页面打不开，或列表非空 | 在浏览器窗口内完成扫码登录；确认网络可访问 B 站 |
| 浏览器窗口没出现 | WebView2 缺失，或窗口被最小化 | 安装 WebView2 Runtime；检查任务栏是否有被遮住的窗口 |
| 只看了很少几个视频 | 候选被风险筛掉，或当天额度用完 | 属正常策略；可调整偏好关键词让候选更贴合 |
| 没有发阶段动态 | 累计完整视频未满 8 个 | 属正常；继续观看即可 |
| 评论区没有回应 | 没有新的 @ / 追评，或回应连续失败 3 次已放弃 | 查看「系统日志 · 生活」中的失败原因 |
| 一天刷太多次 | 每日额度为 6 次 | 属生活系统调度；可通过减少对话触发来降低频率 |
| 记忆里只有标题没有内容 | 片段解码失败，画面理解降级为视频印象 | 检查本机视频解码能力与网络状况 |
| 想减少打扰 | —— | 减少「去看看视频」这类指令 |
