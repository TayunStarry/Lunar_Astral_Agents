> [🏠 手册门户](README.md) ｜ [◀ 上一模块](08-构建运行与配置.md) ｜ [下一模块 ▶](10-llama.cpp-参数参考.md)

## 一、功能介绍

LTPX（Lunar Tool Package，月华工具包）是一套约定「如何把工具注册给月华、并让 AI 智能体调用它」的扩展协议。它的核心机制是 AtoA（Agent-to-Agent）：用户以自然语言下达指令时，月华不直接实现该工具，而是把指令转交给目标工具包内嵌的专用智能体（或宿主内置的桌面 / 网络智能体），由后者自行理解意图、完成多步操作，再把结果回传。它解决的问题是：让「新增一项能力」不再等同于「改动核心程序」——任何团队或个人都可以用独立包的形式扩展系统能力，而页面、桌面自动化、网页操作与沙箱插件都能沿同一协议接入。支持的扩展形态覆盖本地页面包、自带智能体的应用包、通用 / 自主页面操作智能体、桌面自治智能体、网络搜索智能体，以及 LTP3 / LTP9 沙箱插件包。

## 二、使用方法

### 如何安装 / 启用一个工具包

1. 从 LTPX 应用市场或本地归档安装包，安装后包落入本地包目录。
2. 在前端包面板中即可看到该包的卡片；声明了对外工具的包，其能力会被自动登记进月华的工具链。
3. 打开包页面即可直接使用；被月华调用时，页面会自动打开并接收执行指令。

### 如何在月华中调用外部工具

1. 直接用自然语言向月华描述要完成的事情（例如「用某工具帮我做某事」），无需记忆具体工具名。
2. 月华会把指令转交目标包的智能体执行，执行过程与结果会在包页面中实时呈现。
3. 需要观察中间过程时保持页面打开；任务完成后，回执会把结论回传给月华。

### 如何编写与注册一个包（面向创作者）

1. 新建一个以包标识命名的目录，放入入口页面与页面逻辑。
2. 编写元数据，声明标识、面板显示标题、图标、所属分支标签；若希望被月华调用，再声明对外工具的名称与说明。
3. 将包放入本地包目录并刷新前端，工具链会在下次请求时自动扫描到它，无需改动核心程序。

### mini-LTP 的使用说明

1. 适用于「只需操作现有页面、不想额外开发」的场景：包页面无需实现任何智能体。
2. 由宿主在页面加载后自动注入通用操作智能体，接收月华指令后以键鼠、滚动、组合键等方式完成任务。
3. 页面只需能被正常打开，无需为被调用做额外改造。

## 三、功能特性

### 工具包协议

| 特性 | 说明 |
|------|------|
| 声明式注册 | 包以元数据自声明身份与对外工具，前端每次请求时动态扫描，包的增删不必改动核心程序 |
| 工具归一 | 对外工具聚合成单一 `use_the_program`：可用应用名在启动时写入 `tool` 参数枚举，需要了解某个应用时按名传 `details=true` 查询说明 |
| 内置工具 | 桌面操作、网络搜索等由宿主直接内置，无需任何前端包承载 |

### 分支体系（各形态无明显升级取代关系）

| 路线 | 分支名 | 载体形态 | 定位 | 状态 |
|------|--------|----------|------|------|
| LTP1 | — | 单文档工具定义 | 工具定义 + 实现 + 文档的单文件载入 | 已废弃 |
| LTP2 | Zero-LTP | 包页面 | 协议基座：包 = 页面 + 元数据 + 工具定义 | 现行 |
| LTP3 | Yara-LTP | 沙箱插件 | 本地插件引擎（事件容器） | 现行 |
| LTP4 | Node-LTP | WebApp 页面 | 为特定应用定制的专用页面智能体 | 现行 |
| LTP5 | Mini-LTP | 页面智能体 | 通用页面操作智能体 | 现行 |
| LTP6 | Self-LTP | 页面智能体 | 页面内自主循环的智能体 | 现行 |
| LTP7 | Face-LTP | 桌面窗口智能体 | 面向桌面的通用智能体 | 已废弃 |
| LTP8 | 桌面操纵 | 桌面窗口智能体 | 桌面闭环自治智能体（仅控制台「月华链路」屏人工启用，不对月华暴露） | 现行 |
| LTP9 | Embed-LTP | 沙箱插件 | 插件主线：三端组织、全同步事件、权限强绑定 | 现行（主线） |
| LTP10 | Web-LTP | 顶层浏览器会话 | 后端网络搜索智能体（已并入月华原生 `network_explore`） | 已迁移 |

### 页面 / 桌面 / 插件智能体形态

| 形态 | 说明 |
|------|------|
| 自带智能体页面（Node-LTP） | 包页面内置针对该应用的智能体，自行理解指令并执行操作序列 |
| 通用页面操作（Mini-LTP） | 宿主注入智能体，借助页面元素与截图定位，以键鼠 / 滚动 / 组合键完成操作 |
| 自主页面操作（Self-LTP） | 由页面上的开始 / 停止按钮触发，在页面内多轮自循环直至完成 |
| 桌面自治（桌面操纵） | 面向桌面窗口，多角色协作，可启动程序、识别界面并闭环执行；仅控制台人工启动，对话者开始应答时自动终止 |
| 网络搜索（Web-LTP） | 已在 `agents/WebSearch` 中实现，由月华原生 `network_explore` 工具调用，不再走 LTPX 路由 |

### LTP3 与 LTP9 插件引擎能力

| 引擎 | 能力 |
|------|------|
| LTP3（Yara-LTP） | 事件容器：订阅 / 发布事件、监听命令、精确匹配与正则匹配触发，支持中止链路 |
| LTP9（Embed-LTP） | 插件层 / 引擎层 / 客户端三端组织，全同步事件模型，内置跨包调用与前端智能体调度，能力面覆盖事件、数据库、记忆、文件、调用、智能体、编解码、加解密、网络与语音等 |

### 权限密钥机制

| 特性 | 说明 |
|------|------|
| 密钥文件 | 插件随包分发一份加密的权限清单文件，声明该插件可用的权限 |
| 强绑定 | 密钥与插件内容（打包后的脚本）绑定，内容变动即校验失败 |
| 拒绝策略 | 校验失败或出现非法权限名时，拒绝该插件的全部权限 |
| 开发态 | 开发模式下跳过校验，便于调试 |
| 生成工具 | 由官方权限密钥生成器按脚本生成，并自带自检 |

## 四、运行参数

### 包注册元数据字段（用户需填写）

| 字段 | 说明 | 是否必填 |
|------|------|----------|
| `id` | 包的唯一标识，广播与插件装载均以它路由 | 是 |
| `title` | 面板中显示的标题 | 是 |
| `icon` | 卡片图标（相对路径） | 是 |
| `tags` | 分支 / 类别标签，决定载体形态与调用方式 | 是 |
| `tools` | 对外工具清单（工具名 + 说明），供月华调用 | 选填（需要被月华调用时必填） |
| `background_retention` | 后台保活：关闭覆盖层后保留页面现场（输入、编辑状态） | 否 |

### 权限密钥与市场发布相关设置

| 设置项 | 说明 | 建议 |
|--------|------|------|
| 权限密钥文件 | 声明插件可用权限的加密清单，随插件一起分发 | 用官方密钥生成器按当前插件内容生成 |
| 权限名 | 按需勾选（文件、数据库、记忆、网络、调用、智能体、信号、证书、发送、套接字等） | 遵循最小授权原则 |
| 市场发布 | 与程序更新共用同一发布通道，靠描述标记与附件名前缀区分市场包与更新包 | 发布前核对标记与前缀是否正确 |

安装方式的端口 / 发布通道等运行级设置见 [08 安装、运行与配置](08-构建运行与配置.md)；发布通道的具体约定见 [13 控制台 TUI 系统](13-控制台TUI系统.md)。

## 五、常见排故

| 现象 | 可能原因 | 处理办法 |
|------|----------|----------|
| 工具包不生效（月华不知道这个工具） | 包未安装到本地包目录，或元数据未声明对外工具 | 确认包已安装且工具清单非空；刷新前端让工具链重新扫描 |
| 调用超时（一直等待） | 包页面未打开 / 未响应，或任务长时间无回执 | 确认包页面能正常打开并响应指令；失败时会按超时兜底回执 |
| 权限校验失败（插件权限被全部拒绝） | 权限密钥与插件内容不再匹配（打包后内容有变动） | 用密钥生成器对当前插件重新生成权限密钥 |
| 插件沙箱报错 | 插件使用了未授权的权限，或写法超出引擎支持范围 | 按报错补齐授权，或简化配置写法 |
| 市场包与更新包混淆 | 发布时描述标记 / 附件名前缀写错 | 按约定标记区分市场包与更新包，发布前核对 |
