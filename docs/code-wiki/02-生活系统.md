# 02 生活系统

## 一、这是什么

生活系统让月华拥有一份**自己的日常**：在你没有找它说话的时候，它会自己发呆、看视频、逛论坛、做点创作，也会定期整理记忆。这些行为不是随机弹窗，而是按一套节拍推进的「生活链」——每隔一秒推进一次，攒够空闲时间后才开始一段生活，结束后再进入下一段冷却。

生活系统同时负责维护月华自身的心情与对人的情感认知：你的发言会影响它的心情，长期的互动会沉淀成对某个人的好感取向。

---

## 二、核心用途

- **主动生活**：让 AI 在空闲时自发产生经历，而不是只被动等指令。
- **节律控制**：通过权重与每日额度，控制各类生活在一天中出现的频率。
- **记忆沉淀**：把生活经历与对话内容定期整理进长期记忆。
- **状态延续**：心情、情感、生活记录跨重启保留，形成连续的人格表现。

---

## 三、使用方法

### 3.1 自动生活怎么开始

1. 启动程序后，生活链随主循环自动运行，无需手动开启。
2. 月华空闲满 **10 分钟**（默认 600 个节拍）后，会从当日还有额度的生活类型中抽取一项开始。
3. 一段生活结束后统一冷却 **15 分钟**；对话结束后冷却 **10 分钟**。看视频不再是独立体系，而是生活回合里的一个分支。
4. 有新消息时优先处理对话，生活会被让位，不会打断正在进行的应答。

### 3.2 手动触发生活

- **通过对话触发**：对月华说「去看看视频」「去论坛逛逛」，它会用联网探索工具登记一次强制生活，并在下一节拍直接进入对应流程（回你一句「等下就去」）。
- **控制台观测**：控制台「系统日志」屏左右切换可查看「生活」分类日志；「运行状态」屏可看到当前体系与空闲进度。

### 3.3 生活类型与频率

权重总和固定为 **100**，按「发生频率 × 重要性」配比：

| 生活类型 | 内容 | 权重 | 每日额度（次/自然日） | 依据 |
|----------|------|------|----------------------|------|
| 发呆 | 不做事，单纯休息（兜底事件） | 40 | 99999（几乎不限） | 无模型开销的兜底，保持最高基础占比 |
| 看视频 | 到 B 站刷视频、留片段观感评论、每满 8 个视频发阶段动态 | 26 | 12 次 | 正式分支，占用资源最高 |
| 逛论坛 | 到互助论坛看看、发言 | 20 | 6 次 | 中频休闲，一天几次 |
| 创作 | 按最近交流与当前心情做一件作品（写作/脚本等） | 14 | 32 次 | 低频高价值，受创作参考字符串是否更新约束 |

- 权重越高越容易被抽中；每日额度按进程本地时区的自然日零点清零。
- 额度用完的类型当天不再出现，但强制触发不受影响。
- **记忆整理不是生活类型**：它和更新心情、更新对他人态度一起，属于每回合固定步骤，不占权重、没有额度，也不会被随机抽取命中。

### 3.4 记忆整理怎么进行

记忆整理是每回合的固定步骤三（更新心情 → 更新对他人态度 → 记忆待合并），只做一件事：**处理待合并组**，不再按历史时间或条目总量触发，也不再作为权重事件参与随机挑选。

1. 写入记忆时命中高度相似条目，新措辞照常写入并标记 `Pending` + `PendingPartner`，二者构成一个待合并组。
2. 每轮整理取当前全部待合并组（含伙伴），按「组内最旧条目」升序逐组处理。
3. 每组调用主推理模型，输出**一条或多条**整合后的条目；保留事实粒度，禁止把不同事实压成一句概括。合并的输入本身就是高度重复的记忆，因此只在结果为空、没有实质正文（去空白与标点后为空）、或正文低于 `max(输入的 5%, 12 字)` 时判为不可用，保留原条目。
4. 落库顺序固定为**先写新、再删旧**：逐条写入（完全同文直接复用），校验通过后才删除组内旧条目；任一步失败该组保持原状，下轮重试。
5. 模型**原样返回**（没有可合并内容）是合法终止态：保留原条目并立即解除 `Pending`，让它们重新对检索可见，不再等待下一轮。
6. 失败兜底：同一批条目连续失败达到 3 次，或待处理状态持续超过 72 小时，解除 `Pending` 放行可见。放行的始终是完整旧记忆，不会把半成品整理结果写入检索。
7. 没有待合并组时该固定步骤为空操作，不读记忆正文、不产生模型调用。
8. 单批最多 6000 字符（单簇上限），整理后单条记忆不超过 512 字符；截断优先在句读处收尾，句读位置过早时硬切到上限并补省略号。
9. 待合并队列容量上限（200 条）保留，超限时新写入照常落库（不丢数据），不做基于条数的淘汰。

### 3.5 心情与情感

- **心情**：开心、愤怒、伤心、好奇、无聊、平静、厌倦、担忧、恐慌、满足、元气。每次对话后会根据你的发言更新，并带有稳定性权重（不会被一句话带偏）。
- **情感认知**：对每个对话者（按发言者身份区分，群聊里的每位成员各算一位）的好感取向，分正向（喜欢 / 信任 / 关心）与负向（讨厌 / 反感 / 冷淡），跨度从「很讨厌」到「很喜欢」，无足够信号时为「平淡」。
- **评估窗口**：生活阶段逐人计算，每位对话者取自己最近 **5 轮**「发言 + 月华回应」的成对语义求均值，再按 0.7 的历史权重融入长期好感度；窗口没有前移的人不会重复计分。
- 两者都会影响月华在后续对话中的语气与生活选择。

## 四、功能特性

| 特性 | 说明 |
|------|------|
| 单节拍调度 | 每秒推进一次，按优先级依次判断：对话 > 后勤 > 生活 |
| 空闲触发 | 空闲计数达到阈值才开始生活，避免频繁打断 |
| 加权抽取 | 按事件权重随机抽取，并在额度范围内过滤 |
| 强制事件 | 工具触发的生活会插队到下一节拍，且不受额度限制 |
| 分阶段回合 | 一段生活按固定五步推进：维护三步 → 补齐待看列表 → B 站自动响应 → 论坛自动响应 → 权重分支 |
| 跨日清零 | 事件额度按自然日重置，生活记录与计划保留 |
| 状态持久化 | 生活状态、心情、情感分别落盘，重启后延续 |
| 失败有记录 | 生活未完成时会记录「未完成」状态，不会静默消失 |

状态文件位于 `local_data/database/life/`：

| 文件 | 内容 |
|------|------|
| `life_state.json` | 当日额度、上次生活记录、生活版本 |
| `mood_state.json` | 当前心情向量与标签 |
| `affection_state.json` | 对各个对话者的情感取向 |
| `tick_state.json` | 空闲节拍进度与调度状态 |

## 五、运行参数

生活系统的大部分节奏是内建机制，用户可调的参数只有「看视频」的偏好关键词。

| 参数 | 文件 | 说明 | 默认值 | 建议 |
|------|------|------|--------|------|
| `preference_keywords` | `local_data/config/bilibili.json` | 选片偏好关键词，参与候选筛选与加分 | 出厂示例含 AI / 本地部署等 | 换成你希望它多看的主题 |

内建节奏（不可配置，供对照）：

| 项目 | 值 |
|------|----|
| 节拍间隔 | 1 秒 |
| 进入生活的空闲阈值 | 600 节拍（10 分钟） |
| 对话结束后的冷却 | 10 分钟 |
| 生活（看视频 / 逛论坛 / 创作 / 发呆等）结束后的冷却 | 15 分钟 |

> 生活系统的状态文件由程序自动维护，不建议手动编辑；删除后会在下次启动时按默认值重建。

## 六、常见问题

| 现象 | 可能原因 | 处理办法 |
|------|----------|----------|
| 长时间看不到生活行为 | 刚聊过天，空闲未满 10 分钟；或当日相关额度已用完 | 等待冷却结束；查看「系统日志 · 生活」确认额度 |
| 说了「去看视频」但没动静 | 生活正在忙，或当前对话尚未结束 | 等当前应答结束后，下一节拍会进入 |
| 生活只做一半就停了 | 该轮被新消息让位，或中途失败 | 下一节拍会自动续跑；连续失败会记录为「未完成」 |
| 心情长期不变 | 近期发言情绪信号不足 | 属正常；心情需要一定强度的语义信号才会迁移 |
| 情感标签始终「平淡」 | 互动次数或情感极性未达阈值 | 需要多轮带明显态度的交流 |
| 每天生活次数不符预期 | 额度按自然日清零，午夜重置 | 属预期行为 |
