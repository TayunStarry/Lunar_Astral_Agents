# 12 图像生成参数调优手册

> [🏠 手册门户](README.md) ｜ [◀ 上一模块](11-stable-diffusion.cpp-参数参考.md) ｜ [下一模块 ▶](13-控制台TUI系统.md)

本手册帮助你在「出图效果 / 出图速度 / 显存占用」三者之间做出取舍。当前基线模型为 `Qwen-Image 2.1`（原生 2K 画质）。参数完整速查见 [11-stable-diffusion.cpp-参数参考](11-stable-diffusion.cpp-参数参考.md)，配置字段含义见 [08-构建运行与配置](08-构建运行与配置.md)。

---

## 一、功能介绍

图像生成的效果、速度与显存占用互相牵制，任一维度的提升往往以另一维度为代价。本手册把这些取舍讲清楚，让你按目标选择参数：

- **更清晰**：靠尺寸与步数。尺寸决定细节上限，步数决定细节是否充分展开。
- **更快**：靠降低步数、控制尺寸、显存充裕时关闭权重内存卸载。
- **省显存**：靠显存预算、权重内存卸载、提示词编码器上 CPU；VAE 解码放不下时改 CPU 全帧解码（默认自动）。
- **改画风**：主要靠提示词与图生图强度，采样器 / 调度器影响较小。
- **可复现**：靠固定随机种子，并坚持一次只改一个变量。

## 二、使用方法

### 2.1 按目标选参数

| 你的目标 | 优先调整 | 调整方向 |
|----------|----------|----------|
| 出图更清晰 | 尺寸、步数 | 尺寸提到 1024 以上（画质优先 2048，为原生 2K）；步数用 40 |
| 出图更快 | 步数、尺寸、权重内存卸载 | 步数降到 30 左右；尺寸回到 1024；显存充裕时关闭权重内存卸载 |
| 更省显存 | 显存预算、权重内存卸载、提示词编码器、VAE 解码后端 | 设定显存预算、权重常驻内存、编码器跑 CPU；VAE 保持 `sd_vae_backend=auto`（整帧 GPU → direct conv → CPU 三档退让，绝不落到分片） |
| 改画风 / 改外观 | 提示词、图生图强度 | 微调画风用 0.2~0.4，换场景服饰保留主体用 0.4~0.55，大改构图用 0.6~0.8 |
| 复现同一张图 | 随机种子 | 填入固定种子，其余参数保持不变 |

### 2.2 调参步骤（推荐顺序）

1. **固定提示词与随机种子**，作为对照基准。
2. **先定尺寸**：从 1024 起步，按需升到 1536 / 2048，观察细节、耗时与显存是否吃紧。
3. **再定步数**：常规 40，快速草图 30，精细 50~60；50 步以上收益递减。
4. **采样器 / 调度器 / flow-shift 保持自动**，仅在对比实验时才显式指定。
5. **最后处理显存**：出现显存不足时依次尝试显存预算、权重内存卸载、把 VAE 解码改到 CPU。
6. 每次只改一个变量，改动后与上一步的最佳结果对比。

## 三、功能特性

本手册覆盖以下参数维度：

| 特性 | 说明 |
|------|------|
| 尺寸 | 宽高需为 32 的倍数；原生 2K 支持 1:1 / 4:3 / 3:4 / 3:2 / 2:3 / 16:9 / 9:16 等比例；低于 1024 会明显变糊 |
| 步数 | 决定细节展开的充分度，默认 40，上限 150 |
| 采样器 | 引擎按模型自动选择，默认不传参 |
| 调度器 | 引擎按分辨率动态选择，默认不传参 |
| flow-shift | 与分辨率相关的动态偏移，默认自动 |
| VAE 解码后端 | 默认 auto：整帧 GPU → direct conv（省一半显存）→ CPU 三档退让，任何一档都不用分片 |
| VAE 分片 | 默认关闭；开启时按分片几何解码，**分片接缝会出现硬边方块** |
| 显存预算 | 传给引擎的图切割显存上限，默认自动决策 |
| 权重内存卸载 | 权重驻留内存、按需载入显存，用速度换显存 |
| 提示词编码器位置 | 编码器跑 CPU 可省显存，不影响画质 |
| 扩散 flash attention | 用速度换数值精度，默认开启 |
| 随机种子 | 留空或 0 表示随机，填固定值用于复现同一构图 |
| 角色立绘 | 统一入口 `portrait`：`character` 可填内置角色（`月华`/`琉璃`）、自定义角色名或 `通用-女`/`通用-男`，`chibi` 切 Q 版。月华与琉璃有**内置人设**（外观底板 + 默认服装），自定义角色由 `create_character` 写入 SQLite 角色库（`character.db` 的 `painter_characters` 表），通用角色走**男女底板 + 自述外观**。画风统一为赛璐珞二次元。纯文生图，不依赖参考图，因此细节与清晰度最好；图生图只用于「照着这张图改」 |
| 合照 | 统一入口 `group_photo`：`roles[]` 自由拼接任意数量角色（内置/自定义直接写名字，临时角色写外观描述），`chibi` 控制整张合照是否 Q 版；角色身份复用「基础外观 + 默认服装（全尺寸/Q版）」，不再维护单独的合照外观 |

## 四、运行参数

| 参数 | 说明 | 默认值 | 建议 |
|------|------|--------|------|
| `sd_image_size` | 生成尺寸（宽高须为 32 的倍数） | 1024×1024 | 常规 1024，画质优先 2048 |
| `sd_steps` | 迭代步数（调用方未指定且方案无推荐步数时的兜底） | 40 | 30 草图 / 40 常规 / 50~60 精细；`models.schemes.<name>.steps` 优先于它 |
| `sd_sampler` | 采样器 | auto（不传参） | 保持 auto，对比实验再显式指定 |
| `sd_scheduler` | 调度器 | auto（不传参） | 保持 auto |
| `sd_flow_shift` | 动态偏移 | 0（auto） | 保持 auto，对比实验试 1.5 / 3.0 |
| `sd_vae_tiling` | VAE 分片策略 | off | 非必要不启用；分片必留接缝方块，只在「显式要求 GPU 且放不下」时才用 |
| `sd_vae_tile_size` | 分片尺寸 | 引擎默认 32x32 | 启用分片时用 64x64 |
| `sd_vae_tile_overlap` | 分片重叠 | 引擎默认 0.5 | 启用分片时用 0.25 |
| `sd_vae_backend` | VAE 解码后端 | auto | 保持 auto：整帧放不下先试 direct conv，仍放不下才整段 CPU；`gpu` 强制 GPU、`cpu` 强制 CPU |
| `sd_vae_conv_direct` | 整帧放不下时改用直接卷积 | 开启 | 保持开启：实测与 CPU 全帧等价（最大差 1/255、98.9% 像素相同）且解码快约 50 倍（3.81s vs 197.93s）；关闭则直接退到 CPU |
| `pixel_budget_mp`（TS 侧） | 图生图/合照按参考图比例推导尺寸时的像素预算（百万像素） | 1.6 | 常规比例不受影响；超宽/超长画幅才需要调大 |
| `img2img_cfg`（TS 侧） | 图生图的 CFG（覆盖绘制者给出的值） | 不设（按 1.0） | 引导蒸馏模型必须 1.0；换非蒸馏模型（SDXL 等）才设 2~3 |
| `sd_max_vram` | 显存预算（GiB） | 空（自动） | 显存不足时给 9~10；希望程序常驻显存时给 8 |
| `sd_offload_to_cpu` | 权重内存卸载 | always | 12GB 卡保持 always；≥16GB 可关闭提速 |
| `sd_te_on_cpu` | 提示词编码器上 CPU | 开启 | 保持开启，可省显存 |
| `sd_diffusion_fa` | 扩散 flash attention | 开启 | 保持开启；排查伪影时可关闭对比 |
| 随机种子 | 复现指定构图 | 空 / 0 = 随机 | 复现实验时填固定值 |

完整 CLI 参数见 [11-stable-diffusion.cpp-参数参考](11-stable-diffusion.cpp-参数参考.md)；配置字段键名与含义（位于 `lunar_config.json` 的 `diffusion` 分组）见 [08-构建运行与配置](08-构建运行与配置.md)。

## 五、常见排故

| 现象 | 可能原因 | 处理办法 |
|------|----------|----------|
| 爆显存 / 显存不足 | 尺寸过大、缺少显存预算 | 设定显存预算、保持权重内存卸载开启；VAE 解码按 `sd_vae_backend=auto` 自动退让（direct conv / CPU） |
| 出图慢 | 步数偏高、尺寸偏大，或显存充裕却仍卸载权重 | 步数降到 30 左右；尺寸回到 1024；显存充裕时关闭权重内存卸载 |
| 图糊、五官或肢体崩坏 | 尺寸过小 | 尺寸提到 1024 以上（512 仅为原生的约 1/16 像素） |
| 画面出现**纯色硬边方块**（如脸部一块白方斑） | VAE 解码被改用空间分片：显存不够整帧解码时，**引擎会自行降级为分片**（即使没开 `sd_vae_tiling`） | 保持 `sd_vae_backend=auto` + `sd_vae_conv_direct=true`（本程序按「整帧 GPU → direct conv → CPU」退让，杜绝分片）；日志里搜 `retrying with spatial tiling` 确认是否降级 |
| 发灰、塑料感 | 引导强度（CFG）偏高 | 按本模型的引导蒸馏路线把 CFG 压到 1.0（此时负面提示词不生效）。**图生图同样按 1.0**：2026-10-17 起缺省即为 1.0，可用 `diffusion.img2img_cfg` 覆盖 |
| 图生图发糊、明显不如文生图 | 参考图本身是厚涂 / 模糊 / 带水印，img2img 会继承它的画风与清晰度；或 strength 偏低（≈0.5 时参考图占主导） | 要「画一张新的」就用立绘 / 文生图工具；必须保留参考图构图时把 `strength` 抬到 0.6~0.85，并接受画风继承参考图 |
| 细节平淡、纹理平 | 步数不足、量化过激 | 步数提到 40；把扩散权重的量化档位调高 |
| 风格不符 / 改得太多或太少 | 图生图强度不合适 | 微调画风 0.2~0.4，换场景服饰保留主体 0.4~0.55，大改构图 0.6~0.8 |
| 每次构图一模一样 | 随机种子被固定 | 清空随机种子（默认随机），并确认结果回传的种子在变化 |
| 想确认某开关是否生效 | 参数未生效 | 直接读取生成图片内嵌的参数元数据（步数、CFG、尺寸、采样器、模型）比看日志可靠 |
