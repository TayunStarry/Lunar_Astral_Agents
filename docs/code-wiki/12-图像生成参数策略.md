# 12 图像生成参数策略

> [🏠 文档地图](README.md) | [◀ 上一章](11-stable-diffusion.cpp-参数参考.md)

本文给出月华图像生成管线（`subsystem/multimodal_analysis` + sd.cpp）中**尺寸 / 步数 / 采样器 / VAE 分片 / 显存预算 / 随机种子**这些参数的使用约定、默认值与调优方向。CLI 参数本身的完整速查见 [11-stable-diffusion.cpp 参数参考](11-stable-diffusion.cpp-参数参考.md)；管线其它细节见 [04-公共子系统](04-公共子系统.md)。

当前基线模型：**Qwen-Image 2.1**（7B 单流 DiT、32 层、Flow Matching + Euler discrete、64 通道 RGBA VAE、16× 空间压缩）。

---

## 12.1 速查表

| 参数 | 默认值 | 推荐 | 依据 | 设置位置 |
|------|--------|------|------|----------|
| 尺寸 | 1024×1024 | 1024 起，画质优先 2048（原生 2K） | 官方 Default Parameters：2048×2048；宽高需被 **32** 整除 | `sd_image_size` / 插件表单 / HTTP `width`·`height` |
| 步数 | 40 | 40（最低 30） | 官方 `num_inference_steps` 默认 40 | `sd_steps` / 插件表单 / HTTP `steps` |
| 采样器 | auto（不传参） | 保持 auto（引擎选 `euler`） | 官方为 Flow Matching + Euler discrete | `sd_sampler` |
| 调度器 | auto（不传参） | 保持 auto（引擎选 `flux`） | 分辨率相关的动态 shift 由引擎处理 | `sd_scheduler` |
| flow-shift | 0（auto） | 保持 auto；要试就 1.5 / 3.0 | 官方"dynamic shifting"按分辨率自动取 | `sd_flow_shift` |
| VAE 分片 | **off** | 非必要不启用 | 默认分片几何（tile 32 latent = 512px、overlap 0.5 = 256px 步长）会在分片角注入硬边纯白方块 | `sd_vae_tiling` |
| 分片尺寸/重叠 | 引擎默认 32x32 / 0.5 | 必须开时用 `64x64` + `0.25` | 放大分片、减小重叠可让接缝网格挪出画面显著区 | `sd_vae_tile_size` / `sd_vae_tile_overlap` |
| 显存预算 | 空（自动） | OOM 时给 `"9"`（GiB） | 交给 sd.cpp 图切割执行；空则由 `--auto-fit` 自动决策 | `sd_max_vram` |
| 权重内存卸载 | `always` | 12GB 卡保持 always | 显存换速度，只影响耗时不影响画质 | `sd_offload_to_cpu` |
| 提示词编码器 | CPU（`te=cpu`） | 保持 | 省约 1.5GB 显存 | `sd_te_on_cpu` |
| 扩散 flash attention | 开 | 保持开；排查伪影时可关对比 | 速度换数值精度 | `sd_diffusion_fa` |
| 随机种子 | 请求 0/空 = 随机 | 复现实验时填固定值 | 引擎默认种子固定为 42，必须显式传参 | HTTP `seed` / 插件表单 |

## 12.2 尺寸

**规则：宽高必须是 32 的倍数。** 官方原文 "Use image dimensions divisible by 32"。注意官方 2K 比例里 `3:2 = 2528×1696`、`2:3 = 1696×2528` 是 32 的倍数但**不是 64 的倍数**，所以对齐基准取 32 而非 64（早期插件按 64 对齐会直接吃掉这两个比例）。

官方推荐尺寸（原生 2K）：

| 比例 | 尺寸 | 比例 | 尺寸 |
|------|------|------|------|
| 1:1 | 2048×2048 | 2:3 | 1696×2528 |
| 4:3 | 2400×1792 | 16:9 | 2752×1536 |
| 3:4 | 1792×2400 | 9:16 | 1536×2752 |
| 3:2 | 2528×1696 | | |

**为什么低于 1024 会明显变糊**：512×512 只有原生 2048² 的 1/16 像素面积，DiT 没有足够 token 承载五官/发丝/材质细节，实测表现为"整体糊 + 肢体与五官崩坏"。1024² 起品质才有可用性。

归一化实现：`module/generate.go` 的 `normalizeImageSide()` —— 缺省取 `sd_image_size`，夹到 256~2816，四舍五入到 32 的倍数；插件侧对应 `script.js` 的 `snap32()`。两边规则一致，所以 HTTP / Agent / 插件三条入口的尺寸口径相同。

显存与耗时（RTX 4070 12GB + `offload-to-cpu`，仅供参考量级）：1024² 几十秒级，2048² 是 4 倍像素、耗时与显存压力显著上升，也是最容易触发 OOM / 图切割的档位。

---

## 12.3 步数

- 官方默认 **40** 步；实测 20 步细节不足（省一半时间换明显的质量下降，不划算）。
- 50 步以上收益递减，代码侧上限硬夹在 150（`generate.go`）。
- 缺省来源：请求未指定时用 `sd_steps`（默认 40）；插件表单默认也是 40。

---

## 12.4 采样器 / 调度器 / flow-shift

Qwen-Image 2.1 是 Flow Matching 模型，官方用 **Euler discrete 调度 + 动态 shift**。sd.cpp 会按模型自动选，实测生成图内嵌元数据为：

```
Sampler: euler flux
```

因此这三个参数的默认值都是"**不传参**"（`auto`），把选择权交给引擎：

- `sd_sampler: "auto"` → 不传 `--sampling-method`
- `sd_scheduler: "auto"` → 不传 `--scheduler`
- `sd_flow_shift: 0` → 不传 `--flow-shift`（引擎按分辨率动态取）

只有在做参数对比实验时才显式指定，例如 `sd_sampler: "euler"`、`sd_scheduler: "simple"`、`sd_flow_shift: 3.0`。可选值集合见 [11 章](11-stable-diffusion.cpp-参数参考.md) 的 `--sampling-method` / `--scheduler`。

## 12.5 VAE 分片（`--vae-tiling`）

**默认关闭，非必要不启用。** 理由来自实测（源 PNG 逐像素测量，非主观观感）：

- 瑕疵形态是**硬边、纯 255、完全平坦的轴对齐矩形**（一个像素内由 236 跳到 255 再跳回），尺寸约等于 1 个 latent 单元（16×16 px 量级）。扩散采样输出必带纹理、VAE 卷积解码必带渐变过渡，二者都产生不了这种直边平台 —— 它是像素域被"贴"上去的。
- 出现的 3 个样本中，矩形的**右边缘与上边缘 100% 落在 256px 网格线上**（1024² 样本落在 (512,256)，2048² 样本落在 (1024,1280)）。
- sd.cpp 分片解码的默认几何恰好就是 256px 步长：tile 32 latent × 16× 压缩 = 512px，overlap 0.5 → 步长 256px，**与分辨率无关**，与 1024/2048 都吻合。
- 同 seed 下不同步数/不同 CFG（20步+CFG1、40步+CFG4）的图，方块出现在同一格 → 与采样轨迹无关，属于解码端。
- 6 张样本里 3 张复现 → 对应"时有时无"。

策略（`sd_vae_tiling`）：

| 取值 | 行为 |
|------|------|
| `off`（默认） | 永不传 `--vae-tiling` |
| `always` | 始终传（可配合 `sd_vae_tile_size` / `sd_vae_tile_overlap` 调整几何） |
| `auto` | 仅在 `宽×高 > 2 MP`（约 1536² 以上）或守卫后可用显存低于 `image_vram_guard_mib` 时启用 |

确实需要分片时（例如 2048² 爆显存）的推荐组合：

```json
"sd_vae_tiling": "always",
"sd_vae_tile_size": "64x64",
"sd_vae_tile_overlap": 0.25
```

或改用 CPU 解码路径规避：CLI 加 `--backend vae=cpu`（慢一些，但不需要分片）。另可交叉验证的开关：`--vae-conv-direct`、`--disable-segmented-compute`。

**判别口诀**：纯白硬边矩形 + 边缘落在 256px 网格 → 先怀疑分片；柔和光斑/渐变污块 → 先怀疑 `--diffusion-fa` 的数值精度或量化。

## 12.6 显存相关参数

| 参数 | 作用 | 使用建议 |
|------|------|----------|
| `sd_max_vram` | 传给 `--max-vram`，sd.cpp 图切割执行的显存预算（GiB，支持 `cuda0=9` 形式）。空 = 不传，由 `--auto-fit`（默认开）自动决策 | 2048² OOM 时给 `"9"`~`"10"`；想让月华常驻显存时给更小值（如 `"8"`）主动让位 |
| `sd_offload_to_cpu` | `always` 权重驻留内存按需载入显存 | 12GB 卡建议 always；显存充裕（≥16GB）再改 auto/off 提速 |
| `sd_te_on_cpu` | 提示词编码器（`--llm`）跑 CPU | 保持开启，省约 1.5GB 显存，对画质无影响 |
| `sd_diffusion_fa` | 扩散模型 flash attention | 保持开启；排查方块/过曝类伪影时置 `false` 做 A/B |
| `image_vram_guard` / `image_vram_guard_mib` | 画图前先卸载月华模型释放显存；守卫后可用显存同时是 `vae_tiling: auto` 的判据 | 保持默认（开，8192 MiB） |

`--max-vram` 语义细节：`0` = 用实时空闲显存、不设显式预算；负值 = 预留那么多空闲显存；`--auto-fit` 会在此基础上决定权重放 GPU / 内存 / 另一块 GPU / 磁盘。

## 12.7 随机种子

- 请求 `seed` 为 `0` 或留空 = **随机**。实现上由 `generate.go` 生成一个正种子并回写任务（不是依赖引擎的随机行为）。
- 历史行为：请求 0 时旧代码不传 `--seed`，而 sd.cpp 的默认种子固定为 **42**，导致每次生成构图完全一致（实测 6 张样本的元数据 Seed 全是 42）。现已修复。
- 返回值里的 `seed` 是**实际使用的种子**，会一并回传，便于复现同一张图。
- 复现实验：固定 `seed`，一次只改一个变量。

---

## 12.8 参数在哪里设（三层）

1. **全局默认** —— `local_data/lunar_config.json` 的 `diffusion` 段（或 `-sd-*` 命令行标志），改动需重启生效。键名见 [08-构建运行与配置](08-构建运行与配置.md)，中文标签见 `local_data/config_labels.json`。
2. **单次请求** —— 插件表单（`local_data/package/lunar.image-studio`）或 HTTP `POST /generate` 的 JSON 字段（`width`/`height`/`steps`/`seed`/`cfg_scale`/`allow_super_resolution` …）。
3. **Agent 工具** —— 月华 TypeScript 绘制者角色（`lunar_astral/TypeScript/agent/roles/painter.ts`）只暴露 `prompt` / `negative_prompt` / `cfg_scale`；未暴露的尺寸与步数走第 1 层默认值。

优先级：请求值 > 全局默认 > 代码内兜底。尺寸/步数只要传了 ≤0 或非法值，就会回落到全局默认。

## 12.9 排障矩阵

| 症状 | 首要怀疑 | 处置 |
|------|----------|------|
| 画面糊、五官/肢体崩 | 尺寸过小 | 提到 1024 以上（512 只有原生 1/16 像素） |
| 偶尔出现白色/纯色硬边方块 | VAE 分片解码 | `sd_vae_tiling: "off"`；必须开时改 `64x64` + 0.25 重叠，或 `--backend vae=cpu` |
| 过曝、发灰、塑料感 | CFG 偏高 | 按实测把 CFG 压到 1.0（本模型为 guidance 蒸馏路线；CFG=1 时负面提示词不生效） |
| 细节不足、纹理平 | 步数不足 / 量化过激 | 步数提到 40；扩散权重从 Q4_K_M 换 Q6_K / Q8_0 |
| 每次构图一模一样 | 种子被固定 | 清空插件"随机种子"（现已默认随机）并确认结果里的 seed 在变 |
| OOM / 显存不足 | 尺寸过大或缺预算 | 设 `sd_max_vram`、保持 `sd_offload_to_cpu: always`、必要时再开分片 |
| 想确认某个开关有没有生效 | —— | 生成的 PNG 内嵌 `parameters` 与 `SDCPP` 元数据里有实际参数（`Steps/CFG scale/Size/Sampler/models`），直接读它比看日志可靠 |

## 12.10 参数扫描建议

固定 prompt 与 seed，按下面顺序一次只动一个变量（后一项都在前一项的最佳值上进行）：

1. **尺寸**：1024 → 1536 → 2048（观察细节/耗时/是否触发分片与图切割）
2. **步数**：20 → 30 → 40 → 50
3. **VAE 分片**：off → on（验证白块是否随分片开关出现/消失）
4. **flash attention**：on → off（验证是否引入数值类伪影）
5. **采样器/调度器**：auto → euler+simple → res_multistep 等
6. **量化档位**：Q4_K_M → Q6_K → Q8_0（同 seed 对比纹理与文字）

每轮把 PNG 内嵌元数据（`Steps`、`CFG scale`、`Size`、`Sampler`、`models`）抄下来存档，避免参数与结果对不上号。
