## 为什么需要生活系统

只有对话的系统，安静时就是空的；下一次开口，它仍然停在上一句话的情绪里。生活系统解决的是**连续性**：

- 让月华在没人找她时也有经历：看视频、逛论坛、做点创作、发会儿呆。
- 让意图有去处：她可以把「想做的事」记成愿望，到点被提醒，完成后留下情绪反馈。
- 让情绪有来源：心情由最近几轮对话推动，并保留上一份心情的权重；好感由一段时间的互动累积。
- 让记忆有素材：生活事件会产生新的经历条目，进入长期记忆。
- 让下一次对话有话题：她可以主动提起刚看的视频、刚写的东西，而不是永远等你起头。

生活系统是常驻的，但**不会和对话抢同一时刻**。所有链共用同一个调度器，同一时刻只推进一个原子步骤；对话优先级更高，生活只在空档里前进。

## 一轮生活怎么跑

生活链的触发条件很克制：

1. 空闲 Tick 累计到 **600**。调度器每秒推进一次 Tick，因此对话结束后大约 **10 分钟**才会进入生活。
2. 当前没有更高优先级的链在工作。对话优先级最高，一旦有未读消息，生活就停在原地。
3. 生活回合结束后，空闲进度被重置为 **-300**，等价于再空 **900 个 Tick（约 15 分钟）**才进入下一轮。
4. 两种例外不等空闲：对话者通过工具登记了强制事件时，下一个空闲 Tick 直接进入生活，跳过权重抽签并优先执行指定事件；上一轮事件没做完时，每个 Tick 都续跑一步。

满足条件后，一个回合固定走五个阶段，**每次 Tick 只推进一个原子阶段**：

| 阶段 | 做什么 | 是否占事件权重 |
|------|--------|----------------|
| 1 固定四步 | 结算愿望 → 更新心情 → 更新好感 → 处理记忆待合并组 | 否 |
| 2 待看列表维护 | 列表为空时补齐候选、审核、入库与切片下载 | 否 |
| 3 回应 B 站 | 回应 @、视频评论区与动态评论区的未读 | 否 |
| 4 回应论坛 | 回应互助论坛的未读消息 | 否 |
| 5 愿望与事件 | 判定到期愿望并生成提醒，按权重抽事件并执行 | 是 |

第 2~4 步是「机会性维护」：任一步失败、条件不满足或页面没开都只记录，不阻断后面的阶段。这三步还存在让出点——用户消息到达时，回合停在当前阶段，下一次 Tick 从同一步继续。

固定四步每轮都会跑，但只在有变化时真正工作，并且不参与事件抽签，所以不会挤掉「看视频」这类真正的活动。事件本身可能跨多个 Tick：每推进一步都会存下断点，进程重启后能从断点续跑。

## 固定四步：愿望、心情、好感、记忆

### 愿望结算

愿望结算只做一件事：把上一段时间里愿望发生的状态变化，兑换成一次心情偏移。它不负责创建或删除愿望，也不会替你判断愿望该不该完成。

结算覆盖四种情况；临近、完成、延期各记一次，逾期每轮都结算：

- 进入截止前 **1 小时**：轻微推动「开心」。
- 被标记完成：推动「满足」。
- 超过截止时间 **30 分钟**仍未完成：**每一轮结算**都推动「失望」，直到愿望完成或删除。
- 截止时间被往后改：记为一次延期，推动「遗憾」。

已完成的愿望不会立刻消失，而是先保留到心情结算完成，避免重复计算；结算后才从清单移除。因此心愿清单只保存**尚未了结**的愿望，不保留长期完成历史。逾期愿望同样不销毁，会一直留在清单里持续参与每轮结算；多条逾期愿望会整合成一条「执念」写入运行时消息。

### 心情

心情不是一个标签直接赋值，而是「11 种基础情绪上的权重分布」：开心、愤怒、伤心、好奇、无聊、失望、厌倦、担忧、恐慌、满足、遗憾。更新分三步：

1. 取最近 **5 轮**对话（用户发言 + 月华回应）作为样本，而不是只看最后一句话。
2. 把样本与 11 个情绪锚点分别算相似度，用 softmax 压成目标分布；温度取得很低，因此目标会集中在最贴近的那一两个标签上。
3. 当前心情向量与目标向量按 **0.35 : 0.65** 混合，再取权重最高的标签作为当前心情。

这个比例决定了两件事：几轮情绪明显的对话就能把心情推向对应标签；但当前心情始终保留约三分之一的权重，不会被一句话彻底重置。初始心情偏向「开心」。窗口里最新一轮没有前移时整步跳过，避免重复调用嵌入服务。

除了对话，心愿与外部经历也会施加小幅偏移：临近截止、完成、延期、逾期会分别推动对应情绪；观影与创作的结果会通过联动记录轻推心情。创作 / 观影失败只产生一次类似逾期的「失望」，不会把愿望改判为逾期。这些偏移都小于一轮对话带来的变化，作用是让情绪有来处，而不是让某条愿望直接决定心情。

心情会影响：

- 回复的语气与用词。
- 创作事件的方向：心情偏正向时延续上一轮思路，偏负向时允许自己重新规划。
- 论坛发言时以什么状态逛论坛。

心情是**当前状态**，不写入长期记忆；它的变化过程会作为生活记录保留。

### 好感（态度积分）

好感按对话者分别维护，是一套 **[-50, 50] 的整数积分制**，新对话者默认 **20 分**。它不再对历史值做加权平均，因此不会长期被拉回中间值。更新方式是把「用户发言 + 月华当时回应」当成一对语义，看它更靠近哪一极：

- 正向锚点是喜欢、信任、关心，负向锚点是讨厌、反感、冷淡；两者相减得到 `[-1, 1]` 的感情极性。
- 每次只处理该对话者最近 **5 轮**里「尚未评估过」的新增轮次，避免同一句话被反复计分；窗口最新一轮未变化时整步跳过。
- 新增轮次的平均极性乘以 **10** 后四舍五入，就是本次的加/减分数：感受越正面加分越多，越负面扣分越多，单次最多 ±10。
- 积分在 **[-50, 50]** 之间累加并截断；标签按积分切分：`≥ 45` 很喜欢、`≥ 30` 喜欢、`≤ -30` 讨厌、`≤ 0` 疏离，其余为平淡。
- 旧版 `[-1, 1]` 好感度会在载入时换算为积分（默认 20 加上 `极性 × 30`），不会丢失历史数据。

只有已经形成标签的对话者，才会在运行时状态里看到情感标识。好感影响称呼、亲疏程度和主动关心的频率，但不改变安全边界。

### 记忆整理

固定步骤四只处理记忆库里的「待合并组」：写入时如果命中高度相似的旧条目，这些条目会进入待合并队列，由这一步逐组融合成更短、更完整的一条，并重算向量。没有待合并条目时这一步立即返回，不读正文、不产生模型调用。它不按条数或入库时间挑选，也不占用生活事件权重。

合并与淘汰的细节见 [记忆机制](./04-记忆机制.md#合并与淘汰)。

## 心愿清单

愿望是月华自己记下的「想做的事」，不是待办事项：它可以没有期限，也可以带一个到期时间。清单的控制权在月华手里，你通过对话让她增删改查。

**能力边界**

| 能力 | 行为 |
|------|------|
| 新增 | 记录内容；可附带截止时间与优先级；未指定优先级时取当前未占用的最小优先级编号 |
| 修改 | 改内容、改截止时间（记为延期）、改优先级 |
| 完成 | 标记完成，等待心情结算后移出清单 |
| 删除 | 明确放弃，不产生心情偏移 |
| 查询 | 读取当前清单与截止时间；对话中通常不需要，因为清单已经在她每轮的当前状态里 |

- **容量**：同时最多保留 **16 条**待处理愿望，优先级范围 `0`（最高）到 `15`（最低）。
- **到期**：截止时间支持常见的日期与时刻写法；没有截止时间的愿望不会触发提醒。
- **提醒**：到期时生成一条「某某愿望到期」的消息，进入未读上下文；它会在下一次对话时出现，而不是打断当前回合。
- **匹配完成**：创作产物或观影结束等结果会与待处理愿望做语义匹配，命中后自动完成；匹配不上的仍可由对话明确标记。

**谁在维护**

- `chain/wishchain` 是唯一的读写入口，负责愿望、心情、好感与联动记录的加载、修改和原子保存。
- 对话里的新增、修改、完成、删除由「愿望管理」智能体执行；月华只负责理解你的意思并转交。
- 生活回合负责定期结算；创作链与观影链在产物落地时报告结果，命中愿望则自动完成，失败只产生类似逾期的失望联动。

**存在哪里**

所有状态写在 `local_data/database/life/wish_chain.json` 一个文件里，包括愿望清单、心情权重、按对话者分别保存的好感，以及最近的联动记录。写入采用整文件原子替换，避免中途退出留下半份数据。

**在哪里被看到**

心愿系统没有独立的页面。它出现在三个位置：

- **对话**：你通过自然语言增删改查；月华每轮的「当前状态」里带着愿望清单，所以可以直接回答「我有什么愿望」。
- **推理实况**：调用愿望管理时，控制台会显示对应的工具调用与智能体执行过程。
- **智能体上下文导出**：排查问题时可以查看愿望管理智能体拿到的快照，包括当前清单、心情与最近的联动记录。

## 四类生活事件

事件按权重抽取，权重总和固定为 100，兼顾「发生频率 × 重要性」：

| 事件 | 权重 | 每日额度 | 它在做什么 |
|------|------|----------|------------|
| 发呆 | 40 | 几乎不限（99999） | 不产出内容，只让时间流逝、留下「今天想过什么」的痕迹 |
| 观影 | 26 | 12 次 | 取一个已下载片段，理解画面、写观感、偶尔发动态 |
| 论坛 | 20 | 6 次 | 逛互助论坛，看别人的问题，决定是否接话 |
| 创作 | 14 | 32 次 | 发起一次自由创作，产出作品 |

两个约束共同决定抽签：

- **每日额度**按自然日计数，跨日清零。额度用尽的事件不再参与抽签；如果四类都用尽，回落到发呆。
- **权重 ≤ 0 视为关闭自动触发**：该事件不再被随机抽到，但仍可由对话者的工具强制触发。

除额度外没有「按事件冷却」这层限制。唯一的时间节流在论坛：自主**发新话题**至少间隔 6 小时，回复不受限制；工具强制触发的论坛事件不受该冷却约束。系统也没有夜间安静策略，生活节奏完全由空闲 Tick、优先级与额度共同决定。

### 观影

观影是生活回合里的一个事件，不是独立 Tick。一次观看的流程固定：

1. 取一个已下载、未看完的片段。
2. 本地解码抽帧，交给视觉理解；拿不到画面时降级为只凭视频印象写观感，并在结果里说明。
3. 普通片段按约 1/4 的概率写观感评论；一个视频的最后一个片段必定写收束评论，并 @ 1~3 位特别关注。
4. 立刻更新「我刚刚在干的事情」。
5. 每累计看完 8 个完整视频，发一条阶段动态。

看完一个完整视频后，观影链会把结果与待处理愿望做匹配：内容确实对上的会自动完成；没看成的只产生一次类似逾期的失望联动，不会把愿望改判为逾期。这一步不额外改写观影流程。完整流程见 [外部工具与扩展包](./07-外部工具与扩展包.md#b-站观影)。

### 论坛

论坛事件让月华去互助论坛看看有没有需要帮助的问题。进入时会先判断这次是否允许发新话题：允许时可以先读再决定「回复或发帖」，不允许时只读和回复。是否参与由论坛链自己判断，不强制每次都发言。见 [外部工具与扩展包](./07-外部工具与扩展包.md#互助论坛)。

### 创作

创作事件发起一次自由创作，由文件操作智能体直接执行。生活链只下发一个主题，并附上愿望清单正文：心情偏正向且已有作品时延续同一项目目录与句柄，否则随机取一个新主题。新作品不预设路径，标题与 `documents/<标题>/` 目录由文件操作智能体按内容决定。产物落地后会与待处理愿望做匹配，命中则自动完成对应愿望；整体失败只产生类似逾期的失望联动。产物会进入资源库，也会成为下一次对话的素材。见 [创作与演绎](./06-创作与演绎.md#自由创作文件操作智能体)。

### 发呆

发呆不调用模型、不联网、不产出内容，只推进内部时间并留下轻量记录。它的作用是让「什么都没发生」也成为生活的一部分，而不是每次空闲都必须产出点什么。它同时是额度用尽后的兜底事件。

## 活动流与创作参考

除了愿望清单和随机事件，生活还维护两条更轻的线：

- **活动流**：系统记录她最近做过的事，包括生活事件、创作、观影和对话中的明确意图。它是一段持久化文本，重启后仍在；对话时以「我刚刚在干的事情」注入，让她接得上自己的话。
- **创作方向**：不再单独维护创作参考字符串。生活链只下发一个主题，标题与项目目录由文件操作智能体按内容决定；心情正向且已有作品时延续上次目录与句柄，否则换一个新主题。

观影、创作等外部结果还会写入一小段**联动记录**，用于给心情施加轻微偏移，并让下一次愿望结算知道哪些经历已经计入。联动记录有数量上限，只保留最近的部分，不参与记忆检索。

## 生活如何反过来影响对话

生活不是后台自嗨，它通过三条路径回到对话：

1. **运行时状态**：当前心情、刚做过的事、愿望清单与唯一执念，每轮进入上下文。
2. **长期记忆**：生活事件与观后感写入记忆，需要时被检索回对话。
3. **创作素材**：生活里产生的作品与观后感，会成为之后创作或闲聊的引用对象。

所以「她昨天看了一部电影」不需要你提醒，只要那段经历进入了记忆或活动流，下一次相关话题就可能被自然带出来。愿望也一样：到期提醒会以未读消息进入下一轮对话，她可以主动提起，也可以继续等你说。

反过来，你也能在对话里直接改变生活状态：让她记一个愿望、改截止时间、标记完成或放弃，下一次生活结算就会按新状态执行。愿望管理走的是对话工具与「愿望管理」智能体，不要求你打开额外页面。

## 失败与降级

| 失败 | 影响 | 处理 |
|------|------|------|
| 单次生活事件失败 | 这一轮没有产出 | 清空该事件的断点，记录失败原因，下一轮重新抽签；不会卡死生活链 |
| 观影/论坛/创作子链失败 | 事件没有结果 | 同上，生活链收尾并等待下一轮 |
| 心情更新失败 | 心情保持原值 | 不阻塞后续步骤，下一轮再尝试 |
| 好感更新失败 | 好感保持原值 | 同上 |
| 愿望结算失败 | 该轮不施加心情偏移 | 下一轮重新尝试，不重复结算已完成项 |
| 情绪/态度锚点初始化失败 | 暂时无法做语义更新，心情保留上次标签（首次为「开心」） | 愿望读写不受影响，下一次更新时重新初始化 |
| 愿望文件读取失败 | 按空清单继续 | 记录日志，不阻塞生活回合 |
| 记忆整理失败 | 待合并组继续排队 | 连续失败 3 次或隐身 72 小时后自动放行，避免永久卡住 |
| 进程在事件中途重启 | 该事件未完成 | 按持久化断点恢复，从上次完成的阶段继续 |
| 待恢复的事件已不存在 | 无处可续 | 清空断点并写入状态说明，不影响下一轮 |

生活系统遵循一个原则：**任何单个事件失败都不能让整条生活链停摆**。它可以这一轮什么都不做，但下一轮必须还能正常开始。
