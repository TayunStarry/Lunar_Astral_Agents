# 14 统一资源句柄、文本文件与多模态引用使用手册

> [🏠 手册门户](README.md) ｜ [◀ 上一模块](13-控制台TUI系统.md) ｜ 设计依据：[ADR-0001 统一资源寻址与三层存储](../adr/0001-统一资源寻址与三层存储.md)

月华在对话中需要稳定地引用**任何**资料：文本文件、图片、视频、音频。所有这些资源共用**同一套句柄文法**，只以类型码区分场景；多模态窗口负责管理图片的可见范围。本手册说明句柄文法、资源入库与引用方式。

---

## 一、功能介绍

统一资源句柄让月华在对话中稳定地引用每一份已收录的资料。无论是源码文件、Markdown 文档、图片、视频还是语音，都得到一个形如 `@D.003` / `@I.007` 的句柄，之后用该句柄指代这份资料。

- **统一文法**：`@<类型码>.<序号>`，类型码区分场景，可选锚点精确定位段落。
- **一次收录，长期可用**：句柄持久化且序号永不复用 —— 进程重启后同一句柄仍指向同一份资料。
- **本体与句柄解耦**：正文由内容仓库保存；本体被回收后句柄依然有效，降级为描述（图片）或大纲（文档）。
- **统一入库**：前端已落盘的本地文件只登记不复制；渠道（QQ 等）仅给 URL 的资源由系统下载后按内容哈希落盘。同一内容无论来自哪个渠道只存一份。
- **结构定位而非碎片拼接**：文档按标题层级建立段落表，引用时定位到具体章节再**整段展开**，不会出现半句截断或碎片拼接。

### 句柄文法

```text
@<类型码>.<序号>[|<锚点>]
```

| 类型码 | 含义 | 示例 |
|--------|------|------|
| `@D` | 文档（源码 / Markdown / 纯文本 / 配置） | `@D.003` |
| `@I` | 图片 | `@I.007` |
| `@V` | 视频 | `@V.001` |
| `@A` | 音频 | `@A.002` |
| `@T` | 表格 | `@T.005` |

锚点（可选，用于段落级引用）：

| 锚点 | 含义 | 示例 |
|------|------|------|
| `\|§n` | 第 n 节（按文档大纲的章节序号） | `@D.003\|§4` |
| `\|L<起>-<止>` | 第 起~止 行（1 基，含端点） | `@D.003\|L120-168` |

序号不足三位补零；超过 999 后自然变为四位。

## 二、使用方法

### 2.1 向对话注入资源

| 资源类型 | 注入方式 | 系统行为 |
|----------|----------|----------|
| 文本文件 | 在对话中发送或拖入文本类文件 | 解析为整篇资源、建立段落表，回执 `[已收录] @D.003 文件名.md` |
| 工作区文件 | 在消息里写 `@相对路径/文件名.ext`（无需先上传） | 按需收录为文档资源，原文件只读保留 |
| 图片 | 直接发送图片消息 | 登记为 `@I.00x`，在图片后附句柄旁注 |
| 视频 | 发送视频，或由 QQ 等渠道转入 | 本地化后登记为 `@V.00x`，正文中置换为「句柄 + 内容理解」 |
| 音频 | 发送语音/音频，或由渠道转入 | 转写后登记为 `@A.00x`，正文中置换为「句柄 + 语音转写」 |
| 工具产出 | 截图、绘图、超分结果 | 登记为对应类型句柄（默认 B 级保留），窗口内可按句柄引用 |

### 2.2 引用资源

1. **载入引用**：点击消息里出现的资源图标（回执 `[已收录]` 旁），即可把该句柄载入输入框上方。
2. **组合提问**：在引用之后写上你的问题（例如「这份配置该怎么改？」）。发送时句柄会随消息下发，系统在对应资源里按问题定位段落后再回答。
3. **直接书写**：也可以直接在消息里写句柄，例如 `@D.003|§4 这段说的是什么？`。
4. **按文件名引用（无需先上传）**：写 `@文件名.ext` 或 `@相对路径/文件名.ext` 即可让系统**按需收录**该文件。例如 `@AGENTS.md`、`@subsystem/build_common.ps1`。
   - 解析顺序：来源路径索引（同一引用只收录一次）→ 资源目录中已有的同名资源 → 工作区（项目目录）中的文件 → 系统数据目录（`local_data/`）中的文件 → 历史索引迁移
   - 工作区文件**只读收录**：系统把它复制（同卷则硬链接）进内容仓库建立存档副本，**绝不移动或删除你的项目文件**
   - 仅支持文本类扩展名（Markdown / 源码 / 配置 / 日志 / CSV 等），且限制在 100MB 以内
   - **同名不同路径的文件互不干扰**：资源名使用你书写的相对路径（`sub/build.ps1`），项目里多个 `build.ps1` 各自独立成条；同一路径重复引用复用同一句柄，不重复占用空间
   - 文件改动后再次引用会生成新的句柄（内容哈希变化 = 新版本）
5. **去重与移除**：同一引用重复载入会自动去重；不需要时可在输入框上方的图标条里单独移除。

### 2.3 引用按钮的两种形态

| 形态 | 出现位置 | 说明 |
|------|----------|------|
| 汇总引用图标 | 助手消息（`[已收录] @D.003 文件名` 回执） | 较大的圆角按钮，点击把该引用载入输入框 |
| 行内引用按钮 | 你自己发送的消息气泡内 | `@D.003` / `@文件名.ext` 渲染为可点击小按钮，点击同样可载入输入框 |

> 只发文件不提问时，该气泡正文留空、只显示「文件」徽标，内容由服务端的收录回执承载 —— 不会再出现空气泡。

> 仅受支持的文本类扩展名会被收录为文档资源；图片/视频/音频走媒体通道，其它类型按普通文本呈现。

### 2.4 让月华查阅资源

- **查看有哪些资料**：`list_resources` 列出全部资源；`list_images` 只看图片。
- **按关键词找资料**：`search_resources` 跨资源定位到「哪份资源的哪一节」，再 `read_resource` 取正文。
- **看文档结构**：`outline_resource` 返回大纲，每节附带规范锚点句柄与行区间、字数。
- **取正文**：`read_resource` 按句柄取回完整段落；图片/视频/音频返回内容描述（不注入本体，上下文成本极低）。

#### 引用时正文是自动注入还是模型主动读？

两者都有，按体积分流（这是**成本与体验的折中**，不是随机行为）：

| 资源情况 | 行为 | 原因 |
|----------|------|------|
| 小文件（≤6000 字符且无标题结构） | **阅读者在上下文构建阶段自动注入全文**，模型不需调用工具 | 这类资料整篇读完最自然，省一轮工具往返 |
| 有标题结构的文档 | 阅读者按你的问题**筛出最相关的若干节**注入（预算 12000 字符），每节带锚点 | 只给相关段落，避免整篇灌入 |
| 大文件（超预算 / 无结构且 >6000 字符） | **只注入资源卡片**（标题、体积、节数、摘要）+ 取用提示 | 上下文成本可控；模型会看到「体积较大，未自动注入正文」并主动调 `read_resource` |

所以：**你不需要手动让月华去读文件**；月华也不需要每次主动调工具。看到回复里直接引用了配置内容，说明该文件走了自动注入路径。若想强制它只按需读，可以把 `@文件` 换成明确指令（例如「先看 `outline_resource` 再只读第 3 节」）。

> 数量级的直觉：一份 200 行的配置（约 8KB）走「有结构 → 按问题选段」；一份 5000 行日志会只给卡片，正文要模型按需取。

### 2.5 在多模态窗口中查看与管理图片

- 查看可用图片：`list_images` 列出句柄与内容描述（按登记时间倒序，不含「窗内/窗外」标注）。
- 查看图片内容摘要：`read_resource` 取描述；占位文本里已有描述时通常无需调用，需要细节时可带针对性提问。
- 图片超分：按句柄（或最近作品）对已有图片做超分辨率放大。
- 窗口范围：模型只能看到最近 20 张图片本身，更早的只以文字占位出现。

### 2.6 用图片作为绘图参考

1. 在含图消息里说明绘图意图（例如「把 `@I.003` 改成雪景」），并指定要参考的图片句柄。
2. 系统把该句柄对应的源图准备为本次创作的参考图，并交给绘制者执行图生图。
3. 参考图是任务级状态：每次创作开工时重新绑定，不会跨任务沿用旧图。
4. 输出尺寸随参考图比例自动推导；改画风 / 换场景 / 大改构图的强度由绘制者按意图选择。

## 三、功能特性

| 特性 | 说明 |
|------|------|
| 句柄命名 | `@<类型码>.<序号>`，三位起补零；文法在 Go 侧定义唯一权威版本并向 TypeScript 与前端下发 |
| 序号分配 | 持久化主键，入库时分配、**永不复用**；进程启动时从资源目录重建计数 |
| 内容身份 | 内容 SHA-256 前 16 位（sha16），定义域为内容字节；用于去重与目录重建 |
| 统一入库 | 五类来源归一：本地文件只登记不复制；工作区文件只读收录（复制/硬链接，绝不移动原文件）；远程 URL 下载后按内容哈希落盘；data URI / 字节流落盘后登记 |
| 内容去重 | 同一内容多次入库只保留一份实体，目录可有多行句柄 |
| 文档段落表 | 按 Markdown 标题层级建立层级路径与行区间；无标题文本按 60 行分块退化 |
| 段落展开 | `\|§n` / `\|L..` 锚点整段取回，按段落边界保证不半句截断 |
| 资源目录 | SQLite（`local_data/database/archive.db`），存句柄、元数据、段落结构 |
| 内容仓库 | 分类沿用两棵树：文档/代码/脚本/配置 → `local_data/documents/`；图片/视频/音频 → `local_data/multimedia/`。归档副本与前端写入件同目录、同命名（sha16） |
| 媒体零重复 | 前端已按内容哈希落盘的图片/文档**直接引用、不再复制**，同一内容不付两倍磁盘 |
| 归属隔离 | 实体归属记录在资源目录的 `blob_owned` 列：`1` = 归档副本可回收，`0` = 前端/引擎所有，**回收器永不删除**；同实体被 `0` 行引用时也一律不删（按最保守一侧处理） |
| 本体回收 | 配额（默认 2GB / 单资源 20MB）与保留等级（A/B/C）驱动；**只删 `blob_owned=1` 且无人共享的实体、保留目录行** |
| 源文件保护 | 收录一律「复制或硬链接」，**绝不移动或删除来源文件**（前端已落盘件、工作区项目文件均原地保留） |
| 引用注入分级 | 小文件自动注入全文；有结构文档按问题选段注入；大文件只给资源卡片，正文由模型按需 `read_resource` |
| 回收后降级 | 句柄仍可解析：图片降级为描述、文档降级为大纲与摘要 |
| 记忆库分工 | 记忆库存"经历"（回合、对话、工具往返）；文档切片不再写入向量库 |
| 跨资源搜索 | 标题 / 摘要 / 标签 / 文件名 / 段落标题子串匹配（中文无空格分词，刻意不用 FTS5） |
| 图片句柄与可见性 | **无内存图片缓存**：句柄唯一权威在资源目录（入库即长期有效）。可见性由上下文自身表达——最近 20 张图片是真实多模态消息，更早的只剩 `[@I.00x]（描述）` 文本 |
| 渠道图片落盘 | 渠道仅给 URL 的资源由系统下载落盘，与前端上传图片行为一致；QQ 合并转发写真实 `@I.00x` 句柄（`ephemeral` 保留等级） |
| 图生图参考 | 按句柄把内容仓库源图准备为图生图基座，输出尺寸随参考图比例推导，参考图属任务级状态 |
| 图生图强度档位 | 改画风/光影 `0.2~0.4`；换服饰配色 `0.4~0.6`；**换背景/换地点 `0.8~0.9`（推荐 0.85）**；`0.95+` 会重排人物姿态。实测依据见 ADR 0001 的「图生图参数基线」 |
| 图片超分辨率 | 按句柄或最近作品对已有图片放大 |
| 历史迁移 | 旧 `#文件名.ext` 引用与切片集合在首次被引用时懒迁移重建为整篇资源 |

## 四、运行参数

句柄与资源目录本身无需配置参数；与资源归档、图片、多模态相关的配置项如下：

| 参数 | 说明 | 默认值 | 建议 |
|------|------|--------|------|
| `archive-db` | 统一资源目录数据库路径 | `local_data/database/archive.db` | 一般无需修改 |
| `archive-quota-mb` | 内容仓库容量上限（MB）：超限按「等级 → 最久未用」回收 blob | 2048 | 磁盘紧张时下调；回收不影响句柄 |
| `archive-max-blob-mb` | 单个资源入仓体积上限（MB） | 20 | 大文件较多时可上调 |
| `archive-gc-interval-min` | 资源仓库回收周期（分钟），0 表示关闭周期回收 | 30 | 关闭后仍可经 `resourceCollect` 手动触发 |
| `video_input` | 视频解读的输入方式：`file`（写入媒体目录后引用）或 `frames`（本地抽帧为图片序列） | file | 目标模型不支持本地文件引用时改用 frames |
| 多模态模型路由 | 多模态模型名称 / 服务地址 / 密钥 | 本地同源服务 | 需指向其它服务时修改 |

与资源归档相关的其余配置字段与含义见 [08-构建运行与配置](08-构建运行与配置.md)；句柄与窗口的运行机制细节见 [02-核心系统-钛宇-月华](02-核心系统-钛宇-月华.md)。

## 五、常见排故

| 现象 | 可能原因 | 处理办法 |
|------|----------|----------|
| 图片不显示 | 源图地址失效、图片格式不受支持，或图片已超出窗口范围 | 重新发送图片获取新句柄；确认格式受支持；确认该图仍在最近 20 张内 |
| 句柄引用取不到内容 | 句柄序号不存在（非本目录分配），或资源已被显式删除 | 用 `list_resources` / `list_images` 确认可用句柄；不要手写句柄 |
| 提示「本体已回收」 | 该资源的 blob 已被内容仓库按配额回收，仅剩目录行与描述 | 句柄仍然有效，可继续按描述使用；需要原图时请重新发送，或上调 `archive-quota-mb` |
| 文档引用只回了摘要与大纲 | 同上：正文已被回收 | 上调配额，或重新发送该文件 |
| 文档引用只回了开头几段 | 问题文本与任何段落都无词法重叠，触发「回退前若干段」 | 把问题写得更贴近文档用词，或先用 `outline_resource` 看结构再按 `\|§n` 定向引用 |
| 文件回执没有出现 | 文件扩展名不在文档白名单内，或类型为媒体（走媒体通道） | 确认扩展名受支持；媒体资源请在消息中查看对应句柄旁注 |
| 写 `@文件名` 后月华没读到文件 | 解析顺序里四处都没命中：路径索引无记录、目录无同名资源、工作区与数据目录都没有该文件，也不是历史索引 | 确认路径相对**服务端工作目录**（即项目根）书写；用 `list_resources` 看是否已收录；确认扩展名属文本类白名单 |
| 目录里出现多条同名资源 | 同名但**路径不同**的不同文件（这是预期行为，用相对路径引用即可区分） | 引用时带上目录前缀（如 `@sub/build.ps1`）；历史遗留的重复条目可直接删除 |
| 用户消息里的 `@文件名` 没变成按钮 | 浏览器缓存了旧的静态前端资源 | 强制刷新前端页面（Ctrl+F5）后重新发送 |
| 导入文件后原文件不见了 | **已修复的缺陷**（早期实现会把来源文件 move 进内容仓库） | 升级后不再发生；若确认丢失，检查 `local_data/multimedia/` 下的 sha16 命名文件，那即是原内容 |
| 月华似乎「通读」了很大的文件 | 该文件无标题结构且未超 6000 字符，走整篇注入；或问题与各节都有词法重叠，选中节数偏多 | 属预期行为；要更省上下文可明确要求「只看某一节」，或把大文件拆分为带标题的文档（有标题即走选段注入） |
| 图生图提示「参考图未在当前任务中正式选定」 | **已修复的缺陷**（对话者写入的句柄措辞与绘制者解析用的正则格式不一致，导致预置基座被静默忽略） | 升级后不再发生；契约由 `engine/reference_format_test.go` 对拍两端源码守住 |
| 导入文件内容不全 | 文本文件超过单次导入上限被截断 | 拆分文件后分别导入 |
| 动态图不能播放 | 动态图（GIF / APNG / 动态 WebP）在对话中按静态帧处理，窗口内不做动画播放 | 如需逐帧理解，改用序列帧输入方式；或转成静态图后发送 |
| 视频理解失败 | 输入方式与目标模型能力不匹配 | 把 `video_input` 在 file 与 frames 之间切换后重试 |
| 图片描述缺失 | 来源地址为空，或视觉模型调用失败 / 返回空 | 重新发送图片；或按句柄发起一次描述请求 |
| 磁盘占用增长较快 | 内容仓库按配额保留原始字节 | 下调 `archive-quota-mb`、缩短 `archive-gc-interval-min`，或把视频等大件设为 C 级参考 |
