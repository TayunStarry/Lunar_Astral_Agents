# 14 图片标签与多模态窗口

> [🏠 文档地图](README.md) | [◀ 上一章](13-控制台TUI系统.md)
> 相关源码：[image-cache.ts](../../subsystem/core_personality/personality/lunar/TypeScript/agent/capabilities/image-cache.ts) · [dialogue.ts](../../subsystem/core_personality/personality/lunar/TypeScript/agent/roles/dialogue.ts) · [image-recall.ts](../../subsystem/core_personality/personality/lunar/TypeScript/tool/image-recall.ts) · [media.ts](../../subsystem/core_personality/personality/lunar/TypeScript/agent/capabilities/media.ts) · [imagecache](../../subsystem/core_personality/personality/lunar/imagecache)

本篇说明月华如何用 `[图片.00x]` 标签在多模态窗口中管理图片、标签如何降级为文本、以及降级后占位文本里那句描述从哪里来。

---

## 1. 三层结构

| 层 | 位置 | 职责 |
|----|------|------|
| 共享图片缓存 | Go：[imagecache/cache.go](../../subsystem/core_personality/personality/lunar/imagecache/cache.go) | 权威索引：`标签 → {来源, 描述, 是否钉住, 序号, 时间戳}`，容量 80、钉住上限 30 |
| 标签能力封装 | TS：[image-cache.ts](../../subsystem/core_personality/personality/lunar/TypeScript/agent/capabilities/image-cache.ts) | 标签规整、描述规整、占位组装、入注标签暂存、降级转换（纯函数） |
| 消费方 | 对话者 [dialogue.ts](../../subsystem/core_personality/personality/lunar/TypeScript/agent/roles/dialogue.ts) / 绘制者 [painter.ts](../../subsystem/core_personality/personality/lunar/TypeScript/agent/roles/painter.ts) | 窗内看图、超窗降级、按标签取描述 / 取图生图基座 |

标签命名空间**全局唯一且单调递增**（`图片.001`、`图片.002`…，序号超过 999 自然变成四位），QQ 合并转发与对话者上下文共用同一空间；**缓存不落盘**，进程重启后编号重新从 1 开始。

## 2. 图片进入上下文（入注）

`LiteImageFile()` 在每轮对话开始前处理未读消息（[media.ts](../../subsystem/core_personality/personality/lunar/TypeScript/agent/capabilities/media.ts)）：

1. 静态图 → `resizeImage` 解码/转码/等比缩放到 1024 → base64；
2. `registerAndPushImage`：`putCacheEntry(原图地址, pinned=true)` 取标签 → 推 `image_url` 内容项 → **紧随其后追加一个裸标签文本项 `[图片.00x]`**；
3. 同一标签写入**本轮暂存区**（`stashPendingTag`），供「图片还没写进上下文就被降级」的场景取用。

因此消息在上下文里的形态是：

```
{ role: "user", content: [
    { type: "text",      text: "看看这个" },
    { type: "image_url", image_url: { url: "data:image/jpeg;base64,…" } },
    { type: "text",      text: "[图片.007]" }        ← 旁注：图片的可寻址句柄
] }
```

- 窗内时模型**同时看到真图字节与标签**——这是「看着真图学标签」的设计。
- 缓存登记的来源是**原图地址**（URL 形态可复用、避免 base64 常驻内存），不是缩放后的字节；远端地址失效时按标签取图会失败并提示换标签。
- 合并转发内的图片在 Go 侧直接注册（`pinned=false`）并把标签**内嵌进转发正文**（[message.go](../../subsystem/core_personality/personality/lunar/bridging/napcat/message.go)）；回复引用摘要里的图片只是 `[图片]` 字面量，不可寻址。
- 工具（如 `screenshot`）返回的图片：文本以 `tool` 角色回填、图片作为紧随其后的用户多模态消息注入，并同样注册标签 + 旁注（保证窗口期内可按标签引用）。

## 3. 超出窗口：降级（摘图留签）

对话者历史保留最近 **20 张**多模态图片（`IMAGE_WINDOW`）。每轮推理前 `formatHistoricalMessages()` 调用增量降级，从最老的消息开始把超标图片换成占位文本。

### 3.1 转换规则（[demoteContentImages](../../subsystem/core_personality/personality/lunar/TypeScript/agent/capabilities/image-cache.ts)）

- 图片项与其配套的标签旁注**合并为一个**文本项：`[图片.007]（描述）`；
- 配对方式兼容两种排布：旁注在图片**之后**（入注实际排布）或**之前**（历史形态）；每个旁注只被消费一次；
- **不与图片相邻的同形文本一律原样保留**（用户自己打的 `[图片.007]` 不会被吞掉）；
- 图片最终标签的取值优先级：①本轮暂存标签 → ②该图片配套的旁注 → ③现场补注册（无旁注场景）；
- 标签注册失败 → 丢弃该图片项，不留无法寻址的裸图；
- 描述为空 → 占位退化为纯标签 `[图片.007]`（不写「无描述」之类噪声）；
- 降级后立即 `unpinCacheTag`：图片已离开窗口，恢复其可淘汰资格；
- 转换是纯函数，并有单测覆盖 [`__tests__/image-cache.test.ts`](../../subsystem/core_personality/personality/lunar/TypeScript/agent/capabilities/__tests__/image-cache.test.ts)（含「无残留」断言）。

转换后的消息不再含任何 `image_url` 内容项，也不残留旧旁注：

```
{ role: "user", content: [ { type: "text", text: "看看这个" },
                           { type: "text", text: "[图片.007]（一只白猫坐在窗台上）" } ] }
```

### 3.2 占位文本里的描述从哪里来

`[图片.00x]（描述）` 括号内的文字**不是用户输入、也不是模型现场编的**，来源有三层，按序命中：

| 序 | 来源 | 条件 |
|----|------|------|
| ① | **缓存 `desc` 字段命中** | 该标签此前已生成过描述（例如更早的降级或 `describe_images` 调用），零成本直接复用 |
| ② | **描述者（视觉模型）现场生成一次** | 未命中：把 `{描述指令 + image_url}` 作为独立消息喂给描述者角色（`descriptionRole`，与 `describe_images` 同一角色），指令为「用一句不超过20字的中文描述这张图片的主体与场景，只输出描述本身」，返回文本写回缓存 `desc` |
| ③ | **空** | 来源地址为空（`if (!source) return ''`）或视觉调用抛错/返回空 → 占位退化为纯标签 |

无论来自哪一路，写进占位前都会经 `sanitizeImageDesc(raw, 20)` 规整：折叠空白、剥首尾引号、**剔除方括号与圆括号**（避免破坏 `[标签]（描述）` 结构）、去首尾标点、按 20 字硬截断并以省略号收尾。因此占位形态恒为 `[图片.00x]（…）` 或 `[图片.00x]`，不会出现半截括号或换行。

> 同一 `desc` 字段也被 `describe_images` 复用（命中即零视觉调用）；带 `question` 的定向提问**不回写**该字段，避免窄问题的答案覆盖通用描述。

### 3.3 缓存生命周期

- 容量 80：超限时按注册顺序 FIFO 淘汰**最老的未钉住条目**（窗内图片钉住，不会被淘汰；钉住条目超 30 时强制解钉最老者）。
- 缓存不落盘：重启后同一字面标签指向另一张图。因此写入长期记忆前会经 `evadeImageTags` 把标签消解为 `（历史图片）`，避免重启后按旧标签静默取到错图。

## 4. 模型侧的两条取用路径

| 工具 | 归属 | 作用 |
|------|------|------|
| `list_images` | 对话者 + 绘制者 | 列出当前可用标签（标签 / 描述 / 是否在窗内），用于确认标签是否仍有效、定位目标图片 |
| `describe_images` | 对话者 | 按标签取内容描述（不注入图片本体，成本极低）；占位里已有描述时通常无需调用，需要细节时带 `question` 定向提问 |
| `select_reference_image` | 绘制者 | 按标签把缓存源图落盘为图生图基座 |
| `upscale_image` | 绘制者 | 按标签（或最近作品）对已有图片做 RealESRGAN 超分 |

系统提示（[dialogueRole.md](../../subsystem/core_personality/personality/lunar/hierarchy/assets/prompts/dialogueRole.md)）中明确约定：

- `[图片.00x]（…）` 是占位文本，括号内是那张图的内容摘要，**不是用户说的话**；
- 只能看到最近 20 张图片本身，更早的只会以占位形式出现；
- 标签只在本次运行内有效，取不到即表示该图已过期，改用 `list_images` 里仍存在的标签或如实告知；
- 不要自己编造或照抄 `[图片.00x]` 这种写法，只用消息里真实出现过的标签。

## 5. 图生图（标签 → 基座图）

```
用户在含图消息里说「把这张图改成雪景」
  → 对话者 dispatch_painter{description, reference_tag:"图片.007"}
  → agent-control.ts 规整标签 → getCacheEntry → painterRole.prepareReference(源图)
  → resizeImage + hashBytes + saveFile → LocalDir/multimedia/reference/<hash>.png
  → 任务描述追加「（用户指定 [图片.007] 作为图生图基座，参考图已准备就绪：<path>…）」
  → 绘制者 createCreativeWork 识别该措辞并绑定本次任务参考图
  → image_to_image 以 initImg=<相对 LocalDir 路径> 走图生图
```

要点：

- **参考图是任务级状态**：每个创作任务开工时清空，任务描述里注明「已准备就绪」的基座由绘制者重新绑定，跨任务不再隐式沿用（避免旧图污染后续图生图与合照）；
- **输出尺寸随参考图比例**：绘制者读取参考图实际像素（保存时记录 / 读取时解码），在「总像素预算 + 长边上限」内搜索最贴近的一组 32 对齐边长——参考图 1664×2496（2:3）得到 1024×1536，超宽画幅（4:1）得到 ≈1.8MP 的 4:1 而不是被压成方图；
- **`strength` 由绘制者按创作意图显式指定**（0.2~0.4 只改画风、0.4~0.55 换场景服饰保留主体、0.6~0.8 大改构图），省略时按中性值 0.5，**不是随机值**；
- **`steps` 由绘制者按「细节 vs 耗时」取舍**（30~60，省略用 `sd_steps`），不影响构图；
- **文生图/自画像的比例由绘制者从预设中选**（`1:1` 默认，另有 `4:3`/`3:4`/`3:2`/`2:3`/`16:9`/`9:16`，短边恒 1024）；
- 标签过期/源图不可读时，工具结果会明确要求改用 `list_images` 清单中的其它标签；
- 标签取不到的描述性错误同时给出下一步动作，避免模型反复重试同一标签。

> 参数细节与排障见 [12 图像生成参数策略 §12.8.1](12-图像生成参数策略.md)。
