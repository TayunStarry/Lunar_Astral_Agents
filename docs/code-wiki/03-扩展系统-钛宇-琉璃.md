# 03 扩展系统——星图·琉璃（crystal_astral）

> [🏠 文档地图](README.md) | [◀ 上一章](02-核心系统-钛宇-月华.md) | [下一章 ▶](04-公共子系统.md)

工具集扩展系统，以下游工具界面（文件管理 / 知识库 / 记忆库 / 截图标注 / AI 代理转发）服务用户。AI 请求经**智能路由**代理到月华后端（`localhost:36789`）。LTPX 各包页面的加载、`/ltpx/` 代理路由与 Mini-LTP 智能体注入详见 [09·LTPX 协议](09-LTPX协议-月华工具包.md)。

## 0. 人格智能体与功能概述

**琉璃**寓意为「如水晶般澄澈」——她代表着透明、轻盈与纯粹的本真。琉璃的性格清透明澈、轻盈灵动，不做无谓修饰，以最简洁直接的方式完成每一项任务。如果说月华是平台温柔的「面容」，那么琉璃便是平台坚实的「双手」。

| 功能 | 说明 |
|------|------|
| 文件管理 | 本地文件浏览、上传、下载、删除、编辑、预览、归档 |
| 扩展包管理 | 扩展包的安装、导出、删除与包目录扫描 |
| 知识库 | SQLite 知识库管理（CRUD/建表/查询） |
| 记忆库 | 向量记忆库（实例初始化/集合管理/消息增删查/文档列表/重建） |
| 文件整理 | 批量文件整理操作 |
| 截图与图像处理 | 多显示器截图 + 区域截图 + 图片缩放 + 关键帧提取 + 图片格式转换 |
| AI 代理转发 | OpenAI 格式 API 代理，支持外部模型接入 |
| GGUF 元数据解析 | 解析 GGUF 模型文件头信息与元数据 |
| 引擎命令桥接 | StudioHub WebSocket 集线器，桥接智能体引擎命令与动画动作 |
| 月华服务管理 | 检测月华服务状态、一键启动 |
| 应用加载器 | 从界面启动外部 .exe / .ps1 / .bat 程序 |
| 随机背景图 | 本地图片库随机选取桌面背景 |

## 2. 启动与路由

### 2.1 启动流程（main.go / create.go）

```
main.go
  └── 解析参数 → 随机端口(10000~40000) → StartServer
        ├── 初始化记忆库
        ├── 初始化图像任务处理器
        ├── StudioHub 集线器
        ├── 注册 /ws 与 SystemEndpoints
        └── proxyAwareHandler 包裹静态文件服务（代理感知路由）
```

### 2.2 代理感知路由（create.go / variable.go）

`proxyAwareHandler.ServeHTTP` 依据 `shouldProxy(path)` 决定转发给反向代理（`getProxyHandler` → `http://localhost:36789`）还是本地静态文件服务。

**需代理的路径前缀**（`variable.go`）：`/v1/`、`/write/message`、`/tts`、`/generate` 等。

## 3. 关键模块与函数

### 3.1 handler.go —— 代理转发与工具

| 函数 | 职责 |
|------|------|
| `getProxyHandler` | 配置反向代理，目标 `http://localhost:36789`（月华 llama-proxy） |
| `yuehuaCheckHandler` | 检测 `127.0.0.1:36789` 是否可用（月华存活检测） |
| `yuehuaStartHandler` | 启动 `Lunar_Astral.exe`（拉起月华服务） |
| GGUF 元数据解析 | 解析 GGUF 模型文件头部信息 |
| 图片转换 | 委托 convert.go 的图片格式转换 |

### 3.2 gguf.go —— GGUF 模型解析

Parse GGUF 模型文件，读取文件头、张量信息与可用的元数据字段，供模型浏览/测试。

### 3.3 convert.go —— 图片格式转换

支持单张 / 批量 / 列表三种模式的图片格式转换。

### 3.4 ws.go —— WebSocket 集线器

- **StudioHub**：主循环处理客户端注册、注销与广播（引擎命令桥接核心）。
- **WebSocket 升级与读写协程**：`/ws` 客户端连接被注册并广播。
- **StudioEngineHandler**：`/write/engine` 将引擎命令广播给所有本地 WebSocket 客户端。

### 3.5 前端 assets/

基于原生 HTML/CSS/JavaScript 的毛玻璃风格 UI，提供各工具面板界面。AI 请求经前端 `ws_bridge.js` / Http proxy 转发至月华。

### 3.6 内置桌面智能体 —— window_agent（AutoLTP）

琉璃内置一个**通用电脑操作子智能体** `window_agent`，工具名固定为 `window_agent`，由子系统 `subsystem/auto_ltp`（AutoLTP）实现，作为琉璃固有工具选项随 `/ltpx/tools` 暴露给月华调用。

- **状态**：✅ **已实现 / 当前主用**。月华经 `/ltpx/call`（`tool=window_agent` + `instruction`）即可调用；路由于 [ltpx_remote.go](../../crystal_astral/ltpx_remote.go)。
- **架构**：多角色编排式——提示词编纂者→软件启动者→执行循环（视觉理解者 + UIA 理解者 + 任务规划者 + 单操作执行者 + 进度书记者），每个角色独立上下文、工具白名单物理隔离。
- **能力**：视觉 + UIA 双路理解界面、按名称/控件类型定位元素、Invoke/Value/SelectionItem 直接操作、坐标/键鼠兜底。
- **可观测性**：逐角色 trace 落盘 `local_data/logs/auto_ltp_trace.log`（读到/想了/决策/做了什么），截图归档 `local_data/images/moment`。

> ❌ **已弃用：`subsystem/face_ltp`（工具名 `face_ltp_desktop_agent`）已移除**。经对比测试，window_agent(AutoLTP) 采用率与多场景稳定度更优，face_ltp 的单模型循环实现已被替代并从代码库删除，`crystal_astral` 亦不再 import/require 之。

## 5. 运行与常见问题

### 5.1 编译与运行

```powershell
cd d:\Lunar_Astral_Agents\crystal_astral
.\build.ps1
```

编译产物：`d:\Lunar_Astral_Agents\Crystal_Astral.exe`。运行：`.\Crystal_Astral.exe`。

琉璃在 10000~40000 之间随机选择端口（支持多实例并行，避免端口冲突），窗口自动以 WebView 形式打开（1500×1050）。

### 5.2 常见问题

**琉璃和月华有什么区别？** 月华是 AI 智能体核心系统（角色对话、TTS），琉璃是工具集扩展系统（文件管理、知识库/记忆库、截图、图片处理、AI 代理）。琉璃启动时自动连接到月华后端进行 AI 请求代理。

**端口为什么是随机的？** 琉璃设计为可多实例并行运行，随机端口避免端口冲突。

**如何调用外部模型 API？** 使用 `/proxy/chat` 端点，传入 `base_url`、`api_key`、`model` 和 `messages` 即可代理转发到任意兼容 OpenAI 格式的 API 服务。
