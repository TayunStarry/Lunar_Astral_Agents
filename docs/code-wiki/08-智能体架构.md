# 08 智能体架构

> [🏠 手册门户](README.md) ｜ [◀ 上一模块](07-扩展包.md) ｜ [下一模块 ▶](09-安全机制.md)

---

## 一、这是什么

星月智能不是「一个万能模型」，而是**一组各司其职的智能体**。月华负责理解与表达，琉璃负责工具与承载，其余智能体各自处理检索、看图、读文档、修故障、刷视频等专项任务。

它们共享同一套本地模型服务，但各自有不同的提示词、工具和运行节奏。你只需要用自然语言提要求，由月华判断该交给谁做。

---

## 二、核心用途

- **分工**：把「说、画、唱、看、查、修」拆开，各自把一件事做好。
- **稳定**：专项智能体有固定的输入输出与超时，比让一个模型包办更可控。
- **可观测**：每个智能体都有独立的日志与上下文，可导出排查。
- **可扩展**：新增能力优先做成智能体或扩展包，不动核心思维链。

## 三、两位主智能体

### 3.1 月华（核心人格）

月华是与你直接对话的智能体，内部按角色拆分：

| 角色 | 负责 |
|------|------|
| 对话者 | 理解意图、调度工具、生成回复（实现于 `agents/Dialogue`；会话历史、未读队列与 Tick 调度留在思维链） |
| 绘制者 | 文生图、图生图、角色立绘、合照、超分 |
| 演奏者 | 歌曲生成、风格编排、音频产出 |
| 截图者 | 截取屏幕、识别区域并回传图片 |

记忆的入库与检索不是独立角色，而是后端流程，通过对话者的「回忆」类工具暴露。

### 3.2 琉璃（工具与承载）

琉璃是工具集扩展系统，负责：

- 桌面面板与扩展包加载；
- 文件管理、知识库、记忆库、截图标注等工具界面；
- 扩展包安装、导出、删除；
- 需要调用模型时，经统一端点转发给本地模型服务。

琉璃与月华共用同一个服务端口，琉璃桌面挂在 `/desktop/` 路径下。

## 四、专项智能体

| 智能体 | 职责 | 你怎么用到它 |
|--------|------|--------------|
| 响应者 | 承接外部推理请求，在主调度空档期依次处理 | 自动运行，无需操作 |
| 后勤修复 | 处理可自动修复的故障 | 自动运行，日志可见 |
| 搜索者-规划 | 判定搜索指令该走检索还是天气直连，产出检索词与参数 | 自动运行，随「帮我查一下……」触发 |

| 搜索抓取（执行体） | 引擎降级、详情页采集、正文提取与缓存，不发起模型调用 | 自动运行，归 `chain/search/crawler` 而非智能体 |
| 视觉理解 | 看图、动图、视频切片 | 发图 / 发视频 |
| 文献解析 | 大文件轻量扫描与分片摘要 | 发大文档并提问 |
| 归档解析 | 压缩包结构、条目、模型元数据 | 发 zip / 7z 并提问 |
| 归档操作 | 创建、删除、新增、移除压缩包条目 | 说「把这个文件打进压缩包」 |
| 创作规划者 | 生活事件中的写作与脚本创作的规划、执行调度与回滚编排 | 生活自动触发 |
| 生活记忆整理者 | 空闲节拍下把零散旧记忆合并、去重并保留事实 | 生活回合固定步骤三（与心情、态度同级） |
| 文件编辑 | 自然语言驱动的文件读写、检索、置换、运行 | 说「把 a.md 第 2 行改成……」 |
| 观影者-阅片 | 依据公开材料与抽帧画面理解视频内容、生成观后感受 | 生活回合的待看列表补齐与看视频分支自动运行 |
| 观影者-审查 | 合规与风险判定，附一句观影评价与切片数 | 候选入队前自动运行 |
| 观影者-评论 | 片段观感评论与被动互动回应 | 每看一个片段；收到 @ / 追评时 |
| 观影者-分享 | 阶段动态与 @ 作者评论等对外文案 | 每满 8 个完整视频、最后一段观看结束时 |
| 桌控角色（桌面操纵） | 理解界面并代为操作桌面程序 | 仅控制台人工启动 |
| 发送者（通讯桥接） | QQ 私聊与群聊接入 | 配置 NapCat 后自动连接 |
| 论坛角色（互助论坛） | 发帖/回复的模型生成实例，多轮上下文由论坛链推进 | 说「去论坛逛逛」 |
| 扩展包智能体 | 由扩展包自带的页面智能体 | 安装带智能体的包后直接调用 |

### 4.1 桌面操纵为什么不能直接叫

桌面操纵会真实移动鼠标、敲键盘，风险高于其它能力。因此它**不对月华工具链暴露**，只能在控制台「运行状态」屏人工启停；月华开始应答时会自动终止它，避免抢占桌面。

### 4.2 外部调用怎么接

外部程序或前端需要模型能力时，统一走两个端点：

| 端点 | 用途 |
|------|------|
| `/agent/chat/completions` | 多模态对话（非流式，模型名固定） |
| `/agent/embeddings` | 文本嵌入（模型名固定） |

调用方不能自选模型；请求由响应者智能体排队，在主调度空档期依次处理，避免与思维链抢显存。

### 4.3 四层定义与代码归属

四层术语的原文定义：

- **智能体** → 模型调用 + 推理实况上报 + 循环输出监管 + 工具声明与实现。
- **执行体** → 原本智能体队伍中不参与模型调度的那些实例。
- **逻辑链** → 模型调度 + 上下文管理 + Tick 循环；其中涉及模型调度实例的部分必须抽离为独立智能体。
- **引擎层** → 无模型调度，纯功能。

落到目录：

| 层 | 目录 | 收纳什么 |
|----|------|----------|
| 智能体层 | `agents/` | 有模型调用、有推理实况上报与工具声明实现的专精智能体 |
| 执行体层 | `executors/` | **只放不发起模型调用的实例**（确定性解析、纯工具执行）；当前为 `executors/ArchiveReader`，搜索抓取已随搜索链下沉到 `chain/search/crawler` |
| 链路层 | `chain/` | 跨多轮、跨多智能体的系统级流程编排：思维链、观影链、搜索链、创作链、生活链、论坛链、桌控链（共 7 条） |
| 引擎层 | `engine/` | 模型、浏览器、记忆、心情、好感、文件流等可复用能力，自身不发起模型调度 |

依赖方向固定为「链路层 → 智能体层 / 执行体层 / 引擎层」；智能体、执行体与引擎包不反向依赖链路层。`executors/` 的判据是「零模型调用」，一旦某个实例开始调用模型，就应升回 `agents/`。各链路的职责与迁移映射见 [12 链路编排](12-链路编排.md)。

**引擎内部依赖口径**：`engine/*` 各子包可以互相依赖，不设「同层禁止引用」的限制；`engine/console` 是本项目的总成页面，被 `engine/forum` 等子包依赖属于正常设计。唯一硬边界只有两条：`engine` 不得反向依赖 `agents/` 或 `chain/`；`protocol/` 不得依赖 `engine/`、`agents/`、`chain/`。同一份逻辑（如缩放、截断、BV 号解析、JSON 落盘）只允许存在一个实现，宁可新增引擎内部依赖也不复制代码；纯转发壳能直连就直连。

工具声明与实现的分层：**声明与执行都归智能体**。`protocol/toolreg` 提供按智能体命名空间的 schema 与执行器注册；各智能体在 `init()` 中注册自己的工具声明与执行器（如 `agents/Dialogue/tools.go` 与 `tool_crystal.go` / `tool_life.go` / `tool_network.go` / `tool_technique.go` 注册 `dispatch_technique` / `fetch_resources` / `life_planning` / `network_explore`、动态的 `qq_send` 与扩展应用 `use_the_program`；`agents/CreatorPlanner/tools.go` 注册创作链的 21 条工具声明；四个观影者与两个搜索者各自注册本阶段工具），运行时只通过注册表查表调用。`chain/creation`、`chain/viewer`、`chain/search` 的工具目录（`ToolCatalog`）不再汇总硬编码，统一由 `agentinfo.ToolsFromRegistry(各智能体 ID)` 从注册表派生。这样既满足「工具声明与实现属于智能体」，又不会产生智能体反向依赖链。LTPX 协调不再留在链侧：契约在 `protocol/ltpx`，进程内实现由 `agents/ltpxhost` 提供。

引擎层仍保留 4 类登记例外（记忆标签/融合、记忆嵌入、脚本沙箱 `llm.chat`、资源接入 ASR），理由与路径见 [迁移方案的例外登记](agent-taxonomy-migration-plan.md#引擎层模型调用例外登记为什么不能上移)。收尾阶段维持例外，不新建 `MemoryCurator`（事务边界风险）。除这些例外，引擎层不得发起模型调用。

## 五、私有脚本运行时

文件编辑与创作链需要执行脚本时，会在一个独立的 JavaScript 沙箱里运行：

- **入口约定**：脚本首行写 `//Engine: Lunar Harness`，并以 `exportFunction('main', main)` 注册入口；
- **可选能力**：`console`、定时器、`fetch` / `WebSocket`、`file`、`image`（读图 / 缩放 / 转码）、`video`（抽帧）、`memory`、`database`（单一共享库）、`encoding`、`hash`、`agent`（对话 / 搜索）、`http.download`（把远端文件落盘）；
- **运行时长**：默认 120 秒，可在调用时或首行用 `timeout=` 指定，范围 5~3600 秒；
- **隔离**：脚本只能读写自己的数据目录，越界路径会被拒绝；
- **用不到的能力不暴露**：该运行时没有权限清单、没有事件订阅、没有跨包调用，只保留单文件脚本实际用得上的能力。

类型声明按能力拆成多份，内嵌在 `engine/runtime/contracts`（`*.d.ts` 随程序分发）；AI 写脚本时会通过 `read_dts` 按能力查阅对应文件，而不是一次读完全部。

## 七、常见问题

| 现象 | 可能原因 | 处理办法 |
|------|----------|----------|
| 月华不回应但界面正常 | 模型服务未就绪、上下文异常，或外部请求占满队列 | 查看「系统日志 · 警告」与「对话」分类；确认模型服务在运行 |
| 某个专项能力没反应 | 对应智能体初始化失败，或前置条件不满足（未登录、未安装组件） | 查看对应分类日志，按提示补齐条件 |
| 想让月华操作桌面 | 桌面操纵不对外暴露 | 在控制台「运行状态」屏人工启停 |
| 外部程序调用报错 | 端点或模型名写错；或请求了流式 | 改用 `/agent/chat/completions`，不要指定模型名与 `stream` |
| 脚本运行超时 | 脚本执行超过运行时长 | 调大 `timeout`，或拆分任务 |
| 脚本读写文件被拒 | 路径越出沙箱数据目录 | 使用相对路径，只在自己目录内读写 |
