## 4.1 general_config —— 全局配置中枢

> 被所有 Go 模块引用。**零外部依赖、纯数据提供者、并发安全。**

### 工作原理：双层配置

1. **命令行参数（flag）** —— 最高优先级
2. **`lunar_config.json`** —— 第二层，按字段增量覆盖默认值

### 关键文件与函数

| 文件 | 职责 |
|------|------|
| `init.go` | 核心实现：过滤测试参数 → `flag.Parse()` → 读取 JSON → 覆盖全局配置变量（模型、agent/memory/search、server 开关等） |
| `allow.go` / `engine.go` / `image.go` | 各配置分组 |
| `model.go` / `path.go` / `port.go` | 模型 / 路径 / 端口配置 |
| `system.go` / `webview.go` | 系统与 WebView 配置 |

> `lunar_config.json` 示例结构：`models`（asr/diffusion/variational/prompt_analysis）、`server`（bridging_* 桥接）、`agent`/`memory`/`search`（各域 embedding/multimodal 模型分流）。

#### 端口体系（port.go）

端口以 `BasicPort`（默认 36789）为锚点，构建递增范围体系：

| 变量 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `BasicPort` | `*int` | `36789` | 基础 HTTP 服务端口（锚点） |
| `ModelPort` | `*int` | `36790` | llama.cpp 模型服务起始端口 |
| `ProxyPort` | `*int` | `36794` | 代理转发端口 |
| `MinPort` | `*int` | `36784` | 端口范围下界 |
| `MaxPort` | `*int` | `36804` | 端口范围上界 |

- `ModelPortMap`（`map[string]int`）运行时动态维护 `模型名 → 端口号` 映射，支持在该范围内同时运行多个模型服务实例，由 `ModelMapMutex`（`sync.RWMutex`）保护。

#### 模型配置矩阵（model.go）

模型配置分为**三类角色**（`agent` 核心智能体 / `memory` 记忆库 / `search` 智能搜索），每类各含嵌入与多模态两组服务，每组由 `Model`（模型名）+ `URL`（API 地址）+ `Key`（密钥）组成：

| 角色 | 嵌入服务 | 多模态服务 |
|------|---------|-----------|
| 核心智能体 | `AgentEmbeddingModel/URL/Key` | `AgentMultimodalModel/URL/Key` |
| 记忆库 | `MemoryEmbeddingModel/URL/Key` | `MemoryMultimodalModel/URL/Key` |
| 智能搜索 | `SearchEmbeddingModel/URL/Key` | `SearchMultimodalModel/URL/Key` |

默认模型名为 `system-embedding`（嵌入）与 `system-multimodal`（多模态），默认 API 地址为 `http://127.0.0.1:36789/v1`（同源 v1 端点），默认 `Key` 为空串 `""`。

#### 引擎级模型路径表（model.go/path.go）

#### lunar_config.json 示例结构

配置文件按 `models` / `server` / `agent` / `memory` / `search` 五组组织，放置于 `{LocalDir}/` 下（默认 `<exe目录>/local_data/`），仅非空字段覆盖对应默认值：

```json

    "variational_model": "./local_data/models/....safetensors",
    "prompt_analysis_model": "./local_data/models/....gguf",
    "real_esrgan_model": "./local_data/models/....pth",
    "asr_model": "./local_data/models/...."
  },
  "server": {
    "developer": false,
    "allow_diffusion": true,
    "bridging_type": "napcat",
    "bridging_path": "ws://localhost:4567",
    "bridging_keywords": ["月华", "3826713076"]
  },
  "agent": {
    "embedding_model": "system-embedding",
    "embedding_url": "http://127.0.0.1:36789/v1",
    "embedding_key": "",
    "multimodal_model": "system-multimodal",
    "multimodal_url": "http://127.0.0.1:36789/v1",
    "multimodal_key": ""
  },
  "memory": { "embedding_*": "...", "multimodal_*": "..." },
  "search": { "embedding_*": "...", "multimodal_*": "..." }

```

> `server` 分组的 `developer` / `allow_diffusion` 为布尔覆盖；`bridging_*` 等扩展字段由月华主程序读取，配置模块不处理。

#### 运行与使用方式

- 指定基础端口启动：`.\Lunar_Astral.exe -basic-port 36800`
- 开发模式（启用调试日志）：`.\Lunar_Astral.exe -developer`
- 禁用扩散图像生成：`.\Lunar_Astral.exe -allow-diffusion=false`
- 覆盖核心智能体多模态模型服务地址：`.\Lunar_Astral.exe -agent-multimodal-url http://127.0.0.1:36789/v1`
- 配置文件 `lunar_config.json` 放置在 `{LocalDir}/` 下（默认可执行文件同目录的 `local_data/`）

#### 常见问题

- **lunar_config.json 放在哪里？** 放在 `{LocalDir}/` 目录下，默认 `LocalDir` 为 `local_data`，即 `<exe所在目录>/local_data/lunar_config.json`。
- **哪些配置只能在命令行中设置？** 端口号、功能开关、图像参数、WebView 窗口等参数通过命令行设置；`lunar_config.json` 的 `models`/`server`/`agent`/`memory`/`search` 分组可覆盖对应的模型路径、功能开关及模型服务地址。
- **配置修改后需要重新编译吗？** 不需要。`lunar_config.json` 在每次启动时重新读取，命令行参数同样无需重新编译。

## 4.2 browser_client —— WebView 窗口 + IP 发现

### 职责

桌面 WebView 嵌入式窗口管理、系统浏览器回退、本地 IP 自动发现、单例管理。

### 关键文件与函数

| 文件 | 职责 |
|------|------|
| `webView.go` | `RunWebView` 主流程：锁定 OS 线程 → 等待清理 → 创建单例 WebView → 等待后端服务就绪 → 导航 URL → 运行事件循环 → 清理资源 |
| `execute.go` | JS 执行桥接 |
| `type.go` / `variable.go` | 类型与变量 |

#### 启动决策树

```
OpenBrowser(url)
    │
    ├── IsWebViewSupported() == true
    │   └── StartWebViewBrowser(url)  ← 嵌入式 WebView
    │       ├── runtime.LockOSThread()   ← GUI 线程绑定
    │       ├── waitForServer(url)       ← TCP 轮询等待后端就绪
    │       ├── createWebView()          ← 单例创建
    │       └── w.Run()                  ← 阻塞事件循环
    │
    └── IsWebViewSupported() == false
        └── OpenSystemBrowser(url)     ← 系统浏览器
```

WebView 采用**单例模式**：`webviewMutex`（`sync.Mutex`）保护共享状态（单例实例 `webviewInstance`、防重入标记 `webviewRunning`、外部关闭通道 `webviewClosedCh`、清理完成信号 `webviewCleanupDone`）；`CloseWebView()` 可从任意 goroutine 安全调用。

#### IP 发现优先级

`GetLocalIP(preferredNetworks []string)` 遍历所有网络接口并分级选择最佳局域网 IP：

| 优先级 | 匹配网段 | 说明 |
|--------|---------|------|
| 最高 | 用户指定网段 | `preferredNetworks` 参数指定 |
| 次优 | `192.168.x.x` | 常见家庭/企业网段 |
| 第三 | `10.x.x.x` | 私网 A 类 |
| 第四 | `172.16–31.x.x` | 私网 B 类 |
| 第五 | `169.254.x.x` | 链路本地 |
| 最低 | 其他公网地址 | — |

过滤规则：跳过虚拟接口（vEthernet、Hyper-V、Docker、VirtualBox、VPN）、未启用接口（`FlagUp == 0`）与环回接口（`FlagLoopback`）；找到最高优先级 IP 立即返回（短路优化）。

#### 导出函数表

| 函数 | 说明 |
|------|------|
| `OpenBrowser(url string)` | 入口函数：优先 WebView，回退系统浏览器 |
| `OpenSystemBrowser(url string)` | 跨平台系统浏览器启动 |
| `StartWebViewBrowser(url string)` | WebView 启动（需在专用 goroutine 中调用） |
| `CloseWebView()` | 安全关闭 WebView 窗口 |
| `WebViewClosed() chan struct{}` | 返回关闭通知通道（用于等待窗口关闭） |
| `IsWebViewSupported() bool` | 检查平台是否支持 WebView |
| `IsWebViewRunning() bool` | 检查 WebView 是否正在运行 |
| `GetLocalIP(preferredNetworks []string) (string, error)` | 获取最佳本地 IP |

#### 运行与使用方式

`browser_client` 作为库被宿主程序（钛宇-月华、钛宇-琉璃）调用，在需要展示前端页面时由其打开 WebView 窗口，不可用时自动回退系统浏览器。入口函数、IP 发现机制见上文。

依赖：**WebView2 Runtime**（WebView 嵌入式窗口，Win10/11 通常已预装）；**系统默认浏览器**（WebView 不可用时回退目标）。

#### Windows 平台窗口样式参数

除基础属性外，Windows 平台还支持设置窗口图标与标题栏样式：

| 参数 | 说明 | 适用系统 |
|------|------|----------|
| `-webview-icon` | 窗口图标 `.ico` 文件路径（空则不设置，使用默认图标） | Win10/11 |
| `-webview-caption-color` | 标题栏背景色，格式 `#RRGGBB` | Win11 |
| `-webview-border-color` | 窗口边框色，格式 `#RRGGBB` | Win11 |
| `-webview-dark-titlebar` | 标题栏深色模式开关 | Win10 1809+/Win11 |

相对图标路径按「可执行文件所在目录 → 当前工作目录」顺序解析（如 `crystal_astral/icon.ico` 相对仓库根目录下的 exe 可直接命中）。加载失败会在日志中输出实际尝试的路径。

示例：`.\Lunar_Astral.exe -webview-icon icon.ico -webview-caption-color "#202124" -webview-dark-titlebar`

#### 常见问题

- **WebView 窗口无法启动怎么办？** ① 确认已安装 WebView2 Runtime（Win10/11 通常已预装）；② 检查通过配置子系统设置的 WebView 窗口尺寸是否合法；③ 如 WebView 不可用，系统会自动回退到系统浏览器。
- **如何修改 WebView 窗口样式？** 通过 [general_config 子系统](04-公共子系统.md)（本页 §4.1）中的 WebView 参数调整窗口标题、大小、可调整性，Windows 平台还支持上表的图标与标题栏样式参数。
- **如何强制使用系统浏览器？** 入口函数会自动检测 WebView 支持情况并回退到系统浏览器，无需手动干预；也可通过 `general_config` 的命令行参数禁用浏览器。

#### SQLite 知识库（KnowledgeDB）

**初始化配置**：WAL 模式、`busy_timeout=10000ms`、连接池（10 最大 / 5 空闲 / 5 分钟生命周期）、`PRAGMA synchronous=NORMAL / cache_size=10000 / foreign_keys=ON`。

**操作类型表**（`ExecuteKnowledgeRequest`，请求体 `KnowledgeRequest{Operations, Transaction}`、返回 `BatchResult{Success, Results, TotalTime, Operations}`）：

| 分类 | 操作类型 | SQL 生成 |
|------|---------|---------|
| 数据操作 | `insert` | `INSERT INTO table (cols) VALUES (...)` |
| | `update` | `UPDATE table SET ... WHERE ...` |
| | `delete` | `DELETE FROM table WHERE ...` |
| | `select` | `SELECT * FROM table WHERE ... ORDER BY ... LIMIT ...` |
| 表操作 | `create` | `CREATE TABLE IF NOT EXISTS table (columns, constraints, indexes)` |
| | `drop` | `DROP TABLE IF EXISTS table` |
| | `truncate` | `DELETE FROM table` |
| 信息操作 | `tables` | 查询 `sqlite_master` |
| | `structure` | `PRAGMA table_info(table)` |
| | `count` | `SELECT COUNT(*) FROM table` |

事务内任一操作失败立即回滚。

**WHERE 操作符表**（MongoDB 风格，经 `sanitizeIdentifier` 防注入：移除 `; ' " \ -- /* * / ( ) [ ]`，SQL 关键字自动前缀 `_`）：

| 操作符 | SQL 转换 | 示例 |
|--------|---------|------|
| `$eq` | `= ?` | `{"age": {"$eq": 25}}` |
| `$ne` | `!= ?` | `{"status": {"$ne": "deleted"}}` |
| `$gt` | `> ?` | `{"age": {"$gt": 18}}` |
| `$gte` | `>= ?` | `{"age": {"$gte": 18}}` |
| `$lt` | `< ?` | `{"age": {"$lt": 60}}` |
| `$lte` | `<= ?` | `{"age": {"$lte": 60}}` |
| `$like` | `LIKE ?` | `{"name": {"$like": "%test%"}}` |
| `$in` | `IN (?, ?, ...)` | `{"role": {"$in": ["admin","user"]}}` |
| 默认 | `= ?` | `{"id": 123}` |

**知识库请求 JSON 示例**：

```json
{
  "operations": [
    {
      "type": "create",
      "table": "users",
      "columns": [
        {"name": "id", "type": "INTEGER", "primary_key": true},
        {"name": "name", "type": "TEXT", "not_null": true}
      ]
    },
    {
      "type": "insert",
      "table": "users",
      "data": {"name": "Alice"}
    },
    {
      "type": "select",
      "table": "users",
      "where": {"name": {"$like": "%li%"}},
      "order_by": "name ASC",
      "limit": 10,
      "offset": 0
    }
  ],
  "transaction": true
}
```

**文件安全机制**：所有路径经 `filepath.Clean(filepath.Join(config.LocalDir, 请求路径))` + `strings.HasPrefix(完整路径, config.LocalDir)` 校验防路径遍历；文件名经 HTTP 头 `X-File-Name` Base64 传递，`DecodeFileName()` 解码后检查 `./`/`../`，不覆盖模式自动追加时间戳；并发文件锁用 `sync.Map` 存储每路径一个 `*sync.Mutex`。

#### 运行与使用方式

`file_manager` 作为一个库集成到宿主程序（钛宇-月华、钛宇-琉璃）中，HTTP 路由由宿主程序注册。文件保存、读取、知识库/记忆库操作通过对应 HTTP 端点调用，完整端点表见上文。

依赖：SQLite（`go-sqlite3`）——知识库存储引擎；无额外外部命令行工具依赖。

## 4.6 lunar_decoder —— 月球编码（文件加密编解码器）

**中文译名：月球编码**。轻量级文件加密/编解码模块（包 `lunardecoder`，模块 `LunarSubsystem/LunarDecoder`，Go 1.24.4，仅用标准库）。对文件二进制数据执行**密钥驱动的确定性可逆变换**，用于数据的加密混淆与还原。编码产物恒为 Base64 可打印字符集（`A-Z a-z 0-9 + / =`）内的文本，可安全存入 JSON / 文本传输场景。

### 单轮加密管线

```
原始二进制
  → RLE 游程编码（控制字节 rleSeed 由 8 组操作派生）
  → 规范扩散（Feistel-CBC，16 字节块 × 8 子轮，IV/子密钥由轮密钥派生）
  → Base64(RFC 4648) 编码为文本
  → 8 组字符变换（ApplyTransform，0..7 正向）
  → 上下文窗口滑移（SlideRotate，环形滚动）
```

解码按严格逆序：反向滑移 → 逆字符变换（7..0）→ Base64 解码 → 逆向扩散 → RLE 解码。**多轮密钥**时后一轮以前一轮结果为输入，解码逆序逐轮还原。

### 密钥体系（key.go）

- **密钥字符集**为 65 字符 `asciiOrder`（`+/0123456789=ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz`），含符号、数字、大小写字母；空密钥或含字符集外字符（含多字节）返回 `ErrInvalidKey`。
- **按每 16 字符拆分为一轮**：超过 16 字符的密钥拆成多轮（每轮对前一轮结果重复加密）；**不足 16 字符的轮用圆周率小数补齐**——d 个字符从第 `(d-1)*20+1` 位起取（如 1 字符补前 15 位 `141592653589793`），保证短密钥也非全零组。
- **每轮 16 字符拆 8 组**（每组一个控制位 + 一个执行次数位）：控制位取值 `v`（数字取数字值、符号取字符集编码号）得 `Op = v % 10`，`v/10` 叠加到次数位；执行次数位直接取字符集编码号并与整十倍数相加。
- `int16` 整数密钥取 16 位**无符号幅度**参与分组，避免负号干扰。

### 规范扩散层（diffuse.go）

对字节流做**密钥约束的 Feistel-CBC 扩散**，使单比特改动扩散到整段密文（雪崩）：

- 16 字节块 CBC 链：加密为「明文与前一块密文异或 → Feistel 正向 8 子轮」，解密为「Feistel 逆向 → 与前一块密文异或还原」。
- 子密钥 `feistelSubkeys`（8 组 × 8 字节）与 IV `feistelIV` 均由轮密钥的字符值异或种子派生；轮函数 `feistelF` 用 `*2654435761` 黄金比例乘法累加做非线性混合，使输出强依赖右半全部字节。
- **尾部处理**：不足一块的剩余字节与前一块密文派生的字节流异或（加密/解密对称）。
- 空输入返回空，不改变长度；相同密钥与数据产出稳定密文（确定性）。

### 字符变换与滑移

**8 组字符变换**（`transform.go`，作用于 Base64 字符集；`decode=true` 逆序执行逆操作）：

| 类型 | 目标范围 | 操作 |
|------|---------|------|
| 0/1 | 数字 0-9 | 向后/向前循环位移 |
| 2/3 | 字母 a-zA-Z | 向后/向前循环位移 |
| 4/5 | 符号 +、/、= | 向后/向前循环位移 |
| 6/7 | 全 65 字符 | 反向排序表转换（`reverseMap`，自逆）+ 循环位移 |
| 8/9 | 全 64 字符（不含 `=`） | 与下一位字符的字符集索引异或 + 循环位移 |

> 操作 8/9 的相邻异或作用于 64 字符 Base64 索引上（两个 6 位索引异或结果仍是 6 位），保证产物不越出字符集；填充 `=` 作为边界原样保留，末位不参与异或以保证严格可逆。

**上下文窗口滑移**（`slide.go`）：编码链路末阶段将密文环形滚动。方向按 8 组 `groupValue=Op*10+Count` 的奇偶统计判定——**奇多于偶向前，否则向后**；滑移次数按 65 基数解析轮密钥对密文长度取模（`SlideAmount`）。向后滚 k 次的逆操作即向前滚 k 次。

### 公开 API

**类型与错误**

| 类型 | 说明 |
|------|------|
| `FileData` | `Name string` 文件名（原样保留）+ `Data []byte` 数据（编码后为变换文本，解码后还原为原始二进制） |
| `Group` | `Op int`（0-9 操作类型）+ `Count int`（执行次数） |
| `Round` | `Key string`（对齐 16 字符轮密钥）+ `Groups [8]Group`（该轮派生的 8 组操作） |
| `ErrNilData` | 文件数组或数据为 nil |
| `ErrInvalidKey` | 密钥为空或含字符集外字符 |
| `ErrInvalidBase64` | 还原出的内容不是合法 Base64 |
| `ErrInvalidRLE` | 游程编码数据格式非法（截断游程等） |

**函数清单**

| 函数 | 说明 |
|------|------|
| `EncodeFiles(files []FileData, key int16) ([]FileData, error)` | 整数密钥编码：每轮 RLE → 扩散 → Base64 → 字符变换 → 滑移；多轮依次套叠 |
| `DecodeFiles(files []FileData, key int16) ([]FileData, error)` | 整数密钥解码（轮次逆序还原） |
| `EncodeFilesWithKeyString / DecodeFilesWithKeyString(files, keyStr)` | 使用任意长度密钥字符串（≤16 位自动圆周率补齐、>16 位拆多轮）编解码 |
| `KeyGroups(key int16) ([8]Group, error)` / `KeyGroupsFromString(keyStr)` | 返回密钥**首轮**派生的 8 组操作 |
| `KeyRounds(key int16) ([]Round, error)` / `KeyRoundsFromString(keyStr)` | 返回全部加密轮（含对齐密钥与各组操作），供检查密钥派生结果 |
| `ApplyTransform(s []byte, groups [8]Group, decode bool) []byte` | 按 8 组操作变换字节串；`decode=false` 正向编码、`true` 逆序解码 |
| `SlideSpecFromGroups(groups [8]Group) SlideSpec` | 统计 8 组奇偶数量并确定滑移方向（奇多于偶向前，否则向后） |
| `SlideAmount(keyValue string, length int) int` | 以 65 基数解析密钥字符并取模，得到滑移次数 |
| `SlideRotate(s []byte, direction SlideDirection, amount int) []byte` | 环形滚转（双射）；`SlideNone`/`amount==0`/空串为恒等 |
| `ReverseDirection(direction SlideDirection) SlideDirection` | 返回相反滑移方向（解码用） |
| `SlideDirection` / `SlideSpec` | 滑移方向（`SlideNone`/`SlideBackward`/`SlideForward`）与参数类型 |

### 注意事项

- 模块定位为**加密混淆**：算法为自研可逆变换（密钥驱动 RLE + Feistel-CBC 扩散 + 字符变换 + 滑移），无密码学库依赖；用于本地数据保护与混淆场景，如需高强度加密请配合标准库 `crypto` 使用。
- 产物为 Base64 可打印文本（含 `=`），长度随数据与轮次略有膨胀；对已压缩媒体文件，RLE 层几乎不改变体积。
- 文件名（`FileData.Name`）编解码原样保留，不参与加密。
