## 一、这是什么

`subsystem/lunar_harness/chain/` 是**系统级链路编排层**。它只收纳「跨多轮对话、跨多智能体协作、带状态机与事件调度」的流程体系；单次调用即可完成的专项能力仍留在 `agents/`，可复用的底层能力仍留在 `engine/`。

按职责从下到上分为四层：

| 层 | 目录 | 职责 |
|----|------|------|
| 协议层 | `protocol/` | 智能体基座、工具分发、数据导出与修复登记 |
| 能力层 | `engine/` | 模型、浏览器、记忆、心情、好感、文件流、持久化等共享能力 |
| 智能体层 | `agents/` | 单一职责的专精智能体（绘画、搜索者-规划/摘要、视觉、归档操作、通讯桥接等） |
| 执行体层 | `executors/` | 不发起模型调用的实例（归档解析 `executors/ArchiveReader`；搜索抓取已下沉到 `chain/search/crawler`） |
| 链路层 | `chain/` | 把多个智能体与多轮状态组织成完整流程 |

依赖方向固定为 `chain → agents / executors / engine / protocol`。`agents/`、`executors/` 与 `engine/` **不得反向依赖** `chain/`；`app/`、`server/` 属于装配与对外入口，可以同时引用各层。

引擎内部不设同层禁令：`engine/*` 子包可以互相依赖（`engine/console` 是总成页面，被 `engine/forum` 等依赖属正常）。硬边界仅有两条：`engine` 不反向依赖 `agents/` / `chain/`，`protocol/` 不依赖 `engine/` / `agents/` / `chain/`。同一逻辑不得为规避依赖而复制，唯一实现优先下沉到 `internal/` 或直接复用引擎子包。

## 二、七条链路

| 链路 | 包 | 负责的流程 | 主要入口 |
|------|----|------------|----------|
| 思维链 | `chain/thinking` | 上下文管理（会话历史、未读队列、资源转换）、Tick 调度与对外入口；模型调用、提示词与循环监管委托给对话者 `agents/Dialogue` | 对话循环、`responder_loop.go`、`tick_runtime.go` |
| 生活链 | `chain/life` | 空闲节拍下的生活事件编排：观影、创作、逛论坛、发呆、整理记忆、计划判定 | `life.go` 的 `Step` / `RequestEvent` |
| 观影链 | `chain/viewer` | 选片 → 观看（每 Tick 一步）→ 评论互动 → 观后回顾与观影记忆 | `manager.go` 状态机、`run.go` |
| 搜索链 | `chain/search` | 规划 → 抓取 → 摘要：调度「搜索者-规划」与「搜索者-摘要」，抓取由链内 `chain/search/crawler` 承担，并管理搜索模型生命周期 | `search.go` 的 `Run`、`readurl.go` 的 `ReadURL` |
| 创作链 | `chain/creation` | 自由创作的任务路由、计划拆解、流程编排、过程记录与脚本执行 | `route.go`、`plan.go`、`flow*.go` |
| 论坛链 | `chain/forum` | 论坛多轮调度的上下文窗口、轮次推进、并发与超时；模型生成委托给论坛角色 `agents/MutualForum` | `forum.go` 的 `Run` / `Remember` / `HistorySnapshot` |
| 桌控链 | `chain/desktop` | `bootstrap → perceive → plan → operate` 的阶段编排、运行态启停与上下文推进；模型调用委托给桌控角色 `agents/desktop` | `run.go` 的阶段循环、`control.go` 的 `Start` / `Stop` / `Snapshot` |

七条链的中文名与目录名一一对应：**思维链** `chain/thinking`、**观影链** `chain/viewer`、**搜索链** `chain/search`、**创作链** `chain/creation`、**生活链** `chain/life`、**论坛链** `chain/forum`、**桌控链** `chain/desktop`。链包名统一为小写（`thinking`、`viewer`、`search`、`creation`、`life`、`forum`、`desktop`）。

搜索链本身不内嵌模型调用：规划与摘要各是一个独立智能体（`agents/SearchPlanner`、`agents/SearchSummarizer`），引擎降级、详情页采集、正文提取等确定性工作归链内 `chain/search/crawler`（零模型调用）。

观影链同理：选片→观看→互动→回顾的状态机留在链内，四类模型调用各归一个观影者智能体——阅片 `agents/ViewerScreening`（看画面与公开材料）、审查 `agents/ViewerCensor`（合规与风险判定）、评论 `agents/ViewerCritic`（互动回应与观后回顾）、分享 `agents/ViewerShare`（观影动态与 @分享文案）。

论坛链与桌控链是本轮收尾新增的两条链：链只保留上下文、轮次/阶段推进与对外入口，模型调用点分别抽为 `agents/MutualForum`（论坛角色）与 `agents/desktop`（桌控角色）；对外入口签名与返回结构保持不变（`forum.Run` 对应原 `MutualForum.Run`，`desktop.Start/Stop/Snapshot` 对应原 `desktop` 同名入口）。

### 2.1 七条链的分工边界

| 链路 | 链保留什么 | 抽出的智能体 | Tick / 节拍在哪 |
|------|------------|--------------|------------------|
| 思维链 | 会话历史、未读队列、上下文压缩、工具装配与对外 handler | 对话者 `agents/Dialogue` | `chain/thinking/tickloop`（通用调度器）+ `responder_loop.go`（回应者循环） |
| 观影链 | 选片→观看→互动→回顾状态机、持久化与事件 | 观影者-阅片 `ViewerScreening`、审查 `ViewerCensor`、评论 `ViewerCritic`、分享 `ViewerShare` | `chain/viewer/manager.go` 的 `RunOneStep`（每 Tick 一步） |
| 搜索链 | 模型生命周期租约、天气直连、结果收口与兜底 | 搜索者-规划 `SearchPlanner`、摘要 `SearchSummarizer` | 无 Tick；单次流水线，由思维链 `network_explore` 或生活链事件触发 |
| 创作链 | 任务路由、计划拆解、流程/回滚、过程记录、脚本执行 | 创作规划者 `agents/CreatorPlanner`（规划/执行工具循环） | 无 Tick；由生活链事件或对话者 `dispatch_technique` 触发 |
| 生活链 | 事件登记、空闲阈值、事件派发与记忆整理编排（分片/去重/批量/事务） | 生活记忆整理者 `agents/LifeMemorizer`（批量整合模型调用） | `chain/life` 的 `Step(ctx)`（一次生活 Tick） |
| 论坛链 | 40 轮上下文窗口（指令 3000 / 回复 4000 字符）、互斥锁、2 分钟超时、历史快照与重置 | 论坛角色 `agents/MutualForum`（发帖/回复生成） | 无独立 Tick；由生活链 `event_forum` 事件触发，每次 `Run` 推进一轮 |
| 桌控链 | `bootstrap/perceive/plan/operate` 阶段循环、尝试记录、运行态 `Start/Stop/Snapshot` | 桌控角色 `agents/desktop`（阶段模型调用） | 链内阶段循环；由控制台「运行状态」人工启停，非定时 Tick |

> 七条链均不再持有模型调用：模型请求、提示词、工具循环与失败上报全部归对应智能体，链只保留调度、上下文、计划与回滚编排。存储层 `engine/fileflow` 的未提交改动未做重构，链侧只做了接口适配（`CreatorPlanner.Request/Outcome` 的薄封装），差异单列在迁移方案中。LTPX 协调已不在链侧：契约在 `protocol/ltpx`，进程内实现由 `agents/ltpxhost` 提供，对话者的扩展应用工具 `use_the_program` 也归 `agents/Dialogue`。

### 2.2 两组 Tick 循环

思维链内确实存在两套节拍，二者职责不同、互不替代：

| 循环 | 位置 | 作用 |
|------|------|------|
| 通用 Tick 调度器 | `chain/thinking/tickloop` | 忙让出、强制事件抢占、优先级排序、空闲冷却与状态持久化 |
| 回应者循环 | `chain/thinking/responder_loop.go` | 在对话主路径的空档期，依次处理外部推理请求 |

通用调度器由对话者声明快照来源并注入宿主钩子；生活链路只提供「是否有待办事件」与空闲阈值，不重复实现调度。

## 三、能力与编排的边界

迁移时只移动编排部分，纯能力保持原位：

| 能力 | 所在层 | 说明 |
|------|--------|------|
| 心情、好感 | `engine/mood`、`engine/affection` | 数值与衰减规则，不感知生活事件 |
| 记忆读写 | `engine/memory`、`engine/knowledge` | 存储与检索原语 |
| 计划存储 | `engine/plans` | 计划文件读写 |
| 文件流 | `engine/fileflow` | 创作链使用的文件读写原语，留在能力层 |
| 浏览器、模型、多模态 | `engine/browser` 等 | 观看与创作链共享的底层能力 |

因此 `chain/life` 只负责「什么时候触发哪个事件」以及事件内部的多步编排；`chain/creation` 只负责「任务怎么拆、步骤怎么走、过程怎么记」。

## 五、常见问题

| 现象 | 可能原因 | 处理办法 |
|------|----------|----------|
| 新增能力不知道放哪 | 分不清是能力、智能体还是链路 | 单次调用放 `engine/`，单一职责放 `agents/`，跨轮流程放 `chain/` |
| 链路包编译报循环依赖 | 能力层反向引用了链路层 | 把被引用的状态或回调改为注入，保持依赖单向 |
| 生活事件不触发 | 思维链 Tick 未运行或事件注册缺失 | 查看思维链日志与生活事件登记 |
