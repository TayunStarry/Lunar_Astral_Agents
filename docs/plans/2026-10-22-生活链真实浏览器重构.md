## 2. 新机制

生活链使用真实浏览器与本地 Go 模型，不复用旧的 cookie/API 登录体系；执行器已接入 goja 对话链的消息闸门、进度通道和自动调度。TUI「月华引擎 管理」按 `b` 为强制触发：

```
打开真实 B 站首页（WebView2）
  → 未登录：点击登录 / 进入 passport 登录页
  → 每 10 秒检查一次登录，60 秒未登录则关闭浏览器、放弃
  → 首页选一个视频，保持详情页
  → 下载视频 → 60 秒切片 → 每片抽帧理解
  → 合并成“一个视频”的整体感受（不是多段视频）
  → 滚动到评论区，读 ≤15 条评论
  → 生成并发布 1–3 条普通评论（默认 2，占普通评论额度）
  → 单独发一条分享评论，@钛宇-星光阁（独立 @分享额度，不占普通评论）
  → 动态正文写这一轮生活的日记（纯文本，不发视频卡、不在动态里 @）
  → 读取日记动态的评论并回复 ≤5 条
  → 关闭浏览器
```

代码位置：`subsystem/core_personality/agents/BilibiliLife/`。

- `browser.go`：WebViewSession、登录、选片、滚动、页面内 fetch；
- `video.go`：view/playurl、ffmpeg 截取、60 秒切片、逐片抽帧理解；
- `model.go`：OpenAI 兼容模型调用（文本与序列帧）；
- `run.go`：评论/日记/分享评论文案与发布辅助；
- `manager.go`：可中断状态机、断点保存、消息闸门、自动调度、进度标题；
- `reply.go`：动态评论读取与逐条回复；
- `config.go`：选片偏好、安全过滤与每轮配额，读取 `local_data/bilibili_life.json`（gitignore）。

选片规则：

- 首页卡片先按 `preference_keywords` 打分（标题命中一次 +3）；
- 本轮最高分仍是 0 时，用前两个参考词去 B 站搜索页补候选，明显提高 AI 相关命中；
- `blocked_keywords` 与内置安全词合并，涉政、男女/性别对立、引战、网暴、录播/付费等直接过滤；
- 过滤后在最高分组里随机选一条，避免每天都是同一条；
- 用户参考词示例：AI、人工智能、Qwen、DeepSeek、小肥鱼、大肥鱼、AI娘。

TUI 入口：`engine/console/view_engine.go` 的 `b` 键；宿主钩子在 `app/tui_hooks.go`。

## 3. 与 goja 对话链的联动

- 宿主 `EnqueueMessage` 先调用 `BilibiliLife.NotifyUnread()`，再入队；生活运行中会请求中断。
- 中断请求生效前，`pullContext()` 返回空数组且**不消费**消息；生活停到断点、状态落盘后，才允许对话链拉取。
- 生活在每个可中断步骤边界检查中断；当前模型调用会先完成，然后保存断点并暂停。
- 对话链 `runDialogueTurn` 结束后调用 `bilibiliLifeDialogueIdle()`；如果生活暂停且 10 秒内没有新未读，自动从断点续跑。
- `bilibiliLifeProgress()` 提供运行时进度标题（如「月华正在看第 1/2 组《…》，看到了 2/3」）；整轮结束返回空串。
- 自动生活：`bilibili_life.json` 的 `auto_enabled`（默认 true）、`interval_hours`、`daily_limit`；首次启动先等一个完整间隔，TUI 的 `b` 强制触发不占每日次数。
- 每轮配额：`videos_per_round`、`comments_read`、`comments_per_video`、`replies_per_round`、`slices_per_video`。
- @分享评论的目标从 `mention_targets`（name/uid 数组）随机选，不再硬编码为某个人；评论接口只支持正文 @，所以 UID 目前仅作配置记录。
- 全程只有一个 `webSession`；一轮多个视频也是在同一窗口里顺序 `Navigate`，不会为每个视频新开窗口。
- 生活链模型调用改为流式（SSE），通过 `SetModelObserver` 接入 TUI「核心智能 实况」，角色显示为「月华·生活」；非流式响应有 JSON 兜底。

## 4. 当前边界

- 每个进程同时只允许一次生活；TUI 强制触发也会避开正在推理的对话和未读消息。
- 默认 1 个视频、最多 3 个 60 秒切片、读 15 条评论、写 2 条评论、回复 5 条动态。
- 动态与回复通过页面内 `fetch` 携带真实登录 cookie，不依赖旧 `bilibili_config.json`。
- 旧 B 站配置已移到 `.scratch/lifechain_old_bilibili_config.json`，不再被代码读取。
- 中断只能发生在步骤边界：下载、登录等待、模型调用进行中不会被强行取消；模型调用最长 5 分钟，所以极端情况下对话要等这次调用结束。
- 断点保存在 `local_data/database/bilibili_life/state.json`，但当前只在同一 Go 进程内自动续跑；进程重启不会自动恢复浏览器现场。
