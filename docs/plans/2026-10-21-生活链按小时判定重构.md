# 生活链重构：按小时判定、一轮多片段

> 日期：2026-10-21
> 状态：已实现
> 取代：[2026-10-20-月华循环系统方案.md](2026-10-20-月华循环系统方案.md) 的「多时段窗口 + 每窗口额度」调度部分

## 1. 目标

原「思维链」在本文中称 **对话链**；它与生活链并列，共享同一个每秒 goja 定时器。

生活链的新行为：

1. 对话链没有未读消息、也没有在回话时，才允许开始生活。
2. 生活链每 **60 分钟** 最多判定一次（`life_chain.cooldown_minutes`）。
3. 判定时用随机值决定这次做不做（`life_chain.chance`，单项可覆盖）。
4. 单项生活每天最多完成 `daily_limit` 轮（单项可覆盖；当前默认 1 轮）。
5. **一轮生活由多个片段组成**，一个片段最多调用一次模型/写一次操作：
   看视频（最多 5 个，每个最多 10 片，一片一次调用）→ 评论（最多 2 条）
   → 动态（最多 2 条）→ 回应动态互动（最多 3 条）→ 日记（1 条）。
6. **全部片段走完才算一轮完成**；片段之间如果对话链空闲，下一 tick（约 1 秒）立刻继续，
   不等冷却、不重新判定。只有整轮完成（或失败/跳过）才记录完成时间与报告。
7. 对话到来时先处理对话；生活停在当前片段边界（`status=partial` 或 `ready`），
   对话处理完、无未读消息后立刻续跑。
8. 程序启动后的 **10 分钟** 内不判定新一轮（`startup_grace_minutes`）；
   如果上次有未完成的 `partial/ready` 轮次，启动后直接续跑，不受静默期影响。
9. TUI 的 `B` 键可强制开始一轮：跳过冷却、概率、每日上限，但仍等对话链空闲。
10. B 站每轮动作额度以 `bilibili.quota` 提供：看视频数、每视频切片数、评论数、动态数、
    社交回复数、日记数；每轮重置，不是每日计数。`daily_limit` 只限制每天完成几轮。

## 2. 一轮的生命周期

```
对话链空闲
  ├─ 有未完成的一轮（status=partial/ready）→ 立刻继续下一个片段
  ├─ 有 TUI 强制信号 → 跳过冷却/概率/上限，开始新一轮
  └─ 到冷却点 → 随机判定
        ├─ 不做 → 记录完成时间，等下一个冷却周期
        └─ 做 → prepare（为当前片段准备：选片/下载/切段/取回复，不调用模型）
                 ├─ 有消息/正在回话 → status=ready，先把对话处理完
                 └─ 仍空闲 → perform（当前片段的一次模型调用 / 写操作）
                              ├─ 整轮未完成 → status=partial，下一空闲 tick 继续
                              └─ 整轮完成 → 记录完成时间 + 报告
```

`prepare` 与 `perform` 分开，是为了让“对话优先”真正可执行：
下载/切段期间进消息时，可以停在 `ready`，不必重新下载。

### 2.1 统一链路调度器（`agent/chains.ts`）

以前是 `setInterval` 里先 `thoughtLoopTickEvent()`、再 `lifeChainTick()`，两条链各自猜
`reasoningInProgress`，会出现同一 tick 对话刚启动、生活又插进去的竞争。现在只有一个
`chainTick()`：

- 每个 tick 先做计划表到期 flush（它属于对话链输入）；
- 有宿主未读 / JS 未读 / 到期计划 → 本 tick **只跑对话链**，`await runDialogueTurn()`；
- 否则 → 本 tick **只跑生活链一个片段**，`await lifeChainTick()`；
- 两条链共用 `GlobalConfig.reasoningInProgress`；进入任一条前置 true，结束（含异常）复位；
- `activeChain` 只用于让生活链区分“忙碌的是对话链还是自己”，不是第二个并发闸门；
- `tickInProgress` 防止异步链被下一个 1 秒回调重入。

因此：对话跑过的 tick 不会再跑生活；生活只能等下个 tick。任一链在跑时，后续 tick 直接跳过。

### 5.1 每轮动作额度与片段续跑

- `quota` 是**每一轮生活**的额度，每轮重新计，不是每日计数：
  - `watch`：本轮最多看几个视频（默认 5）；
  - `slices`：每个视频最多几个切片，一片一次模型调用（默认 10）；
  - `comment` / `dynamic` / `social` / `memory`：本轮最多评论 / 动态 / 社交回复 / 日记几条。
- 一轮的固定顺序：看视频（全部视频的全部切片）→ 评论 → 动态 → 社交回复 → 日记。
  只要还有下一片段，整轮就没完成；调度器把 `current.status` 置为 `partial`，
  下一空闲 tick 立刻继续——不等待 60 分钟冷却，也不重新掷概率。
- 对话插入时：当前片段边界暂停（`partial`/`ready`），对话处理完且 `unreadCount()==0`
  后继续；不会在对话进行中调用模型。
- `daily_limit` 只限制每天**完成**几轮（当前默认 1 轮）；轮内的片段不计入这个次数。
- 一个视频的切片全部理解完后，合并摘要写入待办队列；评论/动态/日记都从本轮
  看过的视频里取。旧版 `bilibili.json` 里没做完的视频会在新一轮开始时并入队列（补旧账）。
- 额度按“尝试”计数：模型判断不值得发、未登录跳过等也会消耗一次，避免同一步反复占轮次。
- 社交阶段：只读取**本轮自己发的动态**下的评论（`type=17`），只回非本人、友好/提问的评论；
  没有回复或接口失败就结束社交阶段，不阻塞日记与整轮完成。
- 每轮报告在整轮完成时写一次（不是每个片段一份）；`bilibili.json` 的 `session` 保存
  未完成轮次的视频队列、当前切片、阶段与新视频计数，重启后继续。

旧的 `windows`、`entry_wait_minutes`、`grace_minutes`、`max_run_minutes`、
`exit_on_unread`、`watch_segments` 已移除；旧 `quota.json` 也不再读取，新会话状态
随 `bilibili.json` 持久化。

### 5.3 感知者“死循环”修复

感知者代码本身没有 `while` 调用循环：`watchVideo` 最多 8 段，`evaluateSegment` 最多
2 次尝试。实际问题是模型在 `reasoning_content` 里反复描述同一帧（思考自身循环），
不是 SSE 读不动。

最终采用的处理：

- **只保留关闭思考**：`PerceiverRole.disableThinking = true`，请求发送
  `chat_template_kwargs.enable_thinking = false`；
- 不限制感知者输出 token，不加 reasoning 熔断，不额外加提示词约束；
- 视频切片标准从 80 秒/80 帧改为 **60 秒/60 帧**（1fps 下正好 1 分钟），降低单次感知上下文；
- `doStreamingChat` 保留 300 秒整体截止，仅作为网络/服务端异常兜底，不是感知者专属限制。

## 6. 验收要点

- 启动 10 分钟内不出现生活模型调用。
- 对话链有未读/回复中时，生活不开始；已准备好的轮次停在 `ready`，不重复下载。
- 一轮内每个片段最多一次模型调用（看切片走 `watchOneClip`，其余走单个角色 `run`）。
- 判定为不做时 `state.lastRoundEndAt` 立即更新，下一次判定在 60 分钟后。
- 单项生活完成轮数到 `daily_limit` 后不再自动触发；TUI 强制仍可触发。
- 一轮未走完（`partial/ready`）时，下一个空闲 tick 立刻继续；对话有未读时暂停，不丢进度；重启后仍能续跑。
- 只有整轮走完（或失败/跳过）才写一次报告、才记 `lastRoundEndAt`。
- 一个视频的切片按 `quota.slices` 上限逐片理解，每片一次模型调用；总切片数不超过 `watch × slices`。
- 50 个切片必须仍然只是 5 个视频：`bilibili.json` 只新增 5 条待办，日记只写一条“这一轮看了 5 个视频”，评论/动态按视频而不是按切片执行。
- TUI 强制请求在已有未完成生活时并入当前轮，不排队开第二轮；强制轮同样走完整流程。
- 有未读消息时，正在执行的模型调用先结束；下一 tick 先跑对话链，`unreadCount()==0` 且对话链无任务后才继续生活片段。
- `git status` 不出现 `bilibili_config.json` / `napcat_config.json`；`lunar_config.json` 不含 B 站账号、cookie、目标 UID 与 QQ 群号。
- TUI「月华引擎 管理」按 `l` 后二维码直接显示在屏内，Esc 只关闭二维码、不离开引擎屏。
- 对话者运行时消息出现 `[月华的生活] …`，但历史上下文里不出现。
