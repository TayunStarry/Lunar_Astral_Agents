# 知识库删除接口

**功能**：根据UUID和知识库文件路径，将删除请求缓存到内存中，若删除请求已存在，则不重复添加。只有收到/knowledge/flush请求时，才会执行实际的删除操作

**请求方式**: POST
**路径**: `/knowledge/delete`

## 请求参数

| 参数名     | 类型   | 必填 | 说明                                                |
| ---------- | ------ | ---- | --------------------------------------------------- |
| `filePath` | string | 是   | 知识库文件路径，相对于 local_data 目录              |
| `uuid`     | string | 是   | 要删除的对象UUID                                    |

## 请求体示例

```json
{
  "filePath": "knowledge/example.json",
  "uuid": "要删除的对象UUID"
}
```

## 响应示例 (200 OK)

```json
{
  "message": "删除请求已缓存，等待执行"
}
```

或者（当删除请求已存在于缓存中时）：

```json
{
  "message": "删除请求已存在于缓存中，不重复添加"
}
```

## 错误响应

| 状态码 | 说明                   |
| ------ | ---------------------- |
| `400`  | 请求参数错误           |
| `403`  | 访问被拒绝             |
| `500`  | 服务器内部错误         |

```json
{
  "error": {
    "code": 400,
    "message": "KnowledgeDelete请求[ERROR] -> 缺少UUID"
  }
}
```

## 处理流程

1. 验证请求参数，确保filePath和uuid有效
2. 检查文件路径安全性，防止路径遍历攻击
3. 将删除请求缓存到内存中，不立即执行删除操作
4. 检查缓存中是否已存在相同的删除请求
5. 若请求已存在，则不重复添加，返回相应提示
6. 若请求不存在，则添加到缓存中，返回成功响应

## 注意事项

- 删除请求会被缓存到内存中，只有收到/knowledge/flush请求时才会执行实际删除操作
- 删除操作是幂等的，多次提交同一UUID的删除请求不会报错
- 缓存中的删除请求会自动去重，不会重复执行
- 建议在批量删除后调用/knowledge/flush接口，将删除操作应用到文件中
